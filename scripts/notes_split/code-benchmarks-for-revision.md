# 程式碼評測基準：HumanEval、MBPP 與 CRB 的定位

屬於 [CDLM 研究脈絡總覽](corrective-dlm-overview.html)。

## CRB 建立在哪些資料集上（論文第 3 節）
- **HumanEval**：Chen et al.（2021；arXiv 2107.03374），*Evaluating Large Language Models Trained on Code*，58 位作者。
- **MBPP**：Austin et al.（2021；arXiv 2108.07732），*Program Synthesis with Large Language Models*，11 位作者。
- **HumanEval+ / MBPP+**：Liu et al.（2023；arXiv 2305.01210），*Is Your Code Generated by ChatGPT Really Correct?*，4 位作者。

## 缺口
論文指出這些基準與目前 DLM 常用評測偏向前綴補全，不探測錯誤定位或就地修正。

## CRB 的設計
- 對正確程式 ^\star$ 選索引集合 $，以保持詞類與 tokenizer 長度的替換 $\phi$ 產生損壞程式。
- 三種損壞：運算子、識別字、字面值；$|E|\in\{1,\dots,5\}$ 控制難度。
- 損壞後執行測試，只保留會失敗的實例，確保確有錯誤。
- 指標：信心差距 Gap、Hit@K（最低信心的 K 個位置是否含真實錯誤）、迭代修正後的 Pass@1。

## 現成模型的基線（論文 Table 1，nreplace = 1）
Dream-7B-Base 的 Gap 為 0.578，但 top-1 hit 只有 0.094；LLaDA-8B-Base 的 Gap 為 0.235；Open-dCoder-0.5B 的 Gap 為 0.106。T=1 時 Pass@1 分別為 0.776、0.552、0.143。結論是信心與正確性只有粗略對應。
