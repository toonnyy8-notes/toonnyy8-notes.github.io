No. 118 Generative Verifiers（GenRM）
    No. 118 · 互動教學 · arXiv 2408.15240 · ICLR 2025

    生成式驗證器：把驗證寫成下一個 token 的預測

    這篇論文用「Yes」這個 token 的機率當作解答正確性的分數，讓驗證器能先寫出檢查步驟再下判斷。

    Lunjun Zhang、Arian Hosseini、Hritik Bansal、Mehran Kazemi、Aviral Kumar、Rishabh Agarwal（2024）〈Generative Verifiers: Reward Modeling as Next-Token Prediction〉

    01 · Best-of-N

    讓語言模型對同一題寫 N 份解答，由驗證器（替解答打分的模型）選分數最高的一份。驗證器越準，選到正確解答的機會越大。詳見 01。

    02 · 問「答案正確嗎？」

    GenRM 問模型「答案正確嗎（Yes/No）？」，把下一個 token 是 Yes 的機率當分數；還能先寫出逐步檢查（思維鏈，chain-of-thought，CoT）再回答。詳見 03、05。

    03 · GSM8K 的結果

    在 GSM8K（小學數學應用題資料集）上，用 GenRM-CoT 從 16 份解答中選一份，解題率由 73.0% 提高到 93.4%（Fig. 1；起點推定為單次取樣的解題率 推定）。詳見 08。

    同一份錯誤解答在兩種驗證器下的分數（Fig. 2）：0 表示判為錯誤，1 表示判為正確。

    01 · Best-of-N

    Best-of-N 的效果取決於驗證器

    大型語言模型（LLM）解推理題時，常寫出看似合理但錯誤的解答；推理題中只要一步錯，整份解答就錯（Sec. 1）。常用的補救是 Best-of-N（Sec. 2）：給定一道題目 $\mathbf x$，從一個固定的生成器（generator，負責寫解答的 LLM）抽出 $N$ 份候選解答 $\mathbf y$，再由一個學過的驗證器（verifier，也稱獎勵模型 reward model，RM）替每份解答打分數，選分數最高的一份當作最終答案。

    兩個基準量。Pass@1 是單次取樣就答對的題目比率。Pass@N 是 $N$ 份中至少有一份正確的題目比率，也就是「完美驗證器」下的 Best-of-N。兩者都是對題目取平均的量。

    論文用兩種指標評估驗證器（Sec. 4）。Best-of-N 解題率：固定生成器，用驗證器挑選後，測試集上答對的題目比率。RM accuracy：驗證器把單份解答分類為正確或錯誤的準確率。論文寫兩者相關，但 RM accuracy 只評估逐點分類，Best-of-N 評估的是排序後能否選出正確解。

    下面的玩具模型需要一個量 μ。驗證器替正確解打的分數，平均比錯誤解高出 μ 個標準差；μ = 0 表示分數與對錯無關，μ 越大，正確解與錯誤解的分數越容易分開。μ 越大，單份解答的分類準確率（RM accuracy）越高；但 Best-of-N 還取決於單份正確率 $p$ 與候選數 $N$。

    C1

    Best-of-N 模擬器

    示範值

    假設：每道題目都有相同的單份正確率 p，每份解答獨立地以機率 p 正確（真實資料各題 p 不同，Pass@N 是各題的平均）；驗證器給正確解的分數服從 N(μ, 1)、給錯誤解的分數服從 N(0, 1)，彼此獨立；RM accuracy 以正確、錯誤各半的測試集與閾值 μ/2 計算。這是本頁自訂的玩具模型，μ 與 p 都是示範值，不對應論文中任何驗證器。

    Best-of-N（本驗證器）完美驗證器 Pass@N隨機挑選 Pass@1
    正確解的分數 N(μ, 1)錯誤解的分數 N(0, 1)
    候選數 N

    RM accuracy：一份解答的分數高於閾值就判為正確，判對的比率（逐點）。
    Best-of-N：N 份中分數最高的一份是否正確（排序）。

    計算方式

    給定 $c$ 份正確解與 $m$ 份錯誤解，「最高分落在正確解」的機率是 $W(c,m,\mu)=\int c\,\varphi(s-\mu)\,\Phi(s-\mu)^{c-1}\Phi(s)^m\,ds$，其中 $\varphi,\Phi$ 是標準常態的密度與累積分布；$c=0$ 時為 0，$m=0$ 時為 1。正確解份數 $c$ 服從二項分布，所以 $\text{BoN}=\sum_{c=0}^{N}\binom Nc p^c(1-p)^{N-c}W(c,N-c,\mu)$。積分以梯形法計算，範圍 $[\min(0,\mu)-8,\max(0,\mu)+8]$，步長 0.01，指數部分在對數空間相加以免下溢。RM accuracy $=\Phi(\mu/2)$ 本頁推導。

    讀數由本頁依上式即時計算（本頁自訂模型，非論文公式）。Pass@N 與 Pass@1 的邊界 本頁推導：分數與對錯無關時，選最高分等於隨機挑一份。

    Best-of-N 抽 $N$ 份解答，由驗證器打分，選最高分的一份。驗證器分數與正確性無關時，選最高分等於隨機挑一份，結果等於 Pass@1；驗證器完美時，只要 $N$ 份中有一份正確就會被選到，結果等於 Pass@N。對單一題目，若每份解答獨立地以機率 $p$ 正確，Pass@N $=1-(1-p)^N$；資料集的 Pass@N 是各題這個值的平均，各題 $p$ 不同時，不能把平均正確率直接代入公式（例如一半題目 $p=0$、一半 $p=1$，Pass@N 恆為 0.5）。C1 讓每題的 $p$ 相同，所以 $1-(1-p)^N$ 就是圖中的完美驗證器曲線 本頁推導。

    RM accuracy 與 Best-of-N 解題率是不同的量。RM accuracy 只看單份解答是否被正確分類（逐點）；Best-of-N 看驗證器能否在多份解答中排出並選到正確解（排序）。兩者相關但不相同（Sec. 4）。在 C1 的預設值（p = 0.30、μ = 1.5）下，RM accuracy 是 77.3%，與 $N$ 無關；Best-of-N 在 $N=1$ 時是 30.0%，在 $N=16$ 時是 84.7%。兩個數字的定義不同，不能直接比大小。

    檢查理解

    Best-of-N 怎麼運作？驗證器完全無用與完美時，結果各是多少？

    抽 N 份解答、驗證器打分、選最高分者。分數與正確性無關時等於 Pass@1；完美時等於 Pass@N。單題、每份獨立以機率 $p$ 正確時 Pass@N $=1-(1-p)^N$；資料集的 Pass@N 是各題此值的平均（本頁推導）。

    Best-of-N 解題率與 RM accuracy 差在哪裡？

    RM accuracy 是逐點分類的準確率；Best-of-N 是排序後選到正確解的比率。兩者相關但不相同（Sec. 4）。

    02 · 判別式驗證器

    判別式驗證器只輸出一個分數

    先整理後面會用到的四個詞。logit 是模型對每個 token 輸出的未正規化分數 $z_j$。softmax 把 logit 轉成機率：$p_j=e^{z_j/\gamma}/\sum_i e^{z_i/\gamma}$，$\gamma$ 是溫度，溫度越低，機率越集中在 logit 最大的 token，溫度 0 即貪婪解碼（每步取機率最大的 token）。sigmoid $\sigma(z)=1/(1+e^{-z})$ 把一個實數轉成 0 到 1 之間的機率，等於只有兩類時的 softmax。BCE（binary cross-entropy，二元交叉熵）是二元分類的損失：標記 $y\in\{0,1\}$、預測機率 $r$ 時為 $-[y\log r+(1-y)\log(1-r)]$。

    LLM 是自迴歸模型：在參數 $\theta$ 下，給定題目 $\mathbf x$ 生成序列 $\mathbf y=(y_1,\dots,y_T)$ 的機率逐個 token 相乘（Eq. 1），每個 token 的機率由 softmax 在 logit 上算出。監督式微調（SFT）最小化目標序列的負對數機率（Eq. 2）：

    $$p_\theta(\mathbf y\mid\mathbf x)=\prod_{t=1}^{T}p_\theta(y_t\mid\mathbf x,y_{\lt t}),\qquad \mathcal L_{\text{SFT}}(\theta,\mathcal D)=-\mathbb E_{(\mathbf x,\mathbf y)\sim\mathcal D}\Big[\sum_{t}\log p_\theta(y_t\mid\mathbf x,y_{\lt t})\Big]$$
    Eq. 1、2

    推理任務上主流的驗證器是判別式 RM（Discriminative RM，論文也稱 ORM，outcome reward model；Cobbe et al., 2021）。它在一個特殊詞彙 token $cls$ 的 logit $z_{cls}$ 上接 sigmoid，輸出解答正確的機率 $r_\theta(\mathbf x,\mathbf y)\in[0,1]$，在正確解集合 $\mathcal D_{\text{correct}}$ 與錯誤解集合 $\mathcal D_{\text{incorrect}}$ 上以 BCE 訓練（Eq. 3）。論文的資料一律正確、錯誤各半。

    $$\mathcal L(\theta,\mathcal D_{RM})=-\mathbb E_{\mathcal D_{\text{correct}}}\log r_\theta(\mathbf x,\mathbf y^+)-\mathbb E_{\mathcal D_{\text{incorrect}}}\log\big(1-r_\theta(\mathbf x,\mathbf y^-)\big),\quad r_\theta=\mathrm{sigmoid}(z_{cls})$$
    Eq. 3

    論文比較的其他三種做法（Sec. 2、Sec. 4）：LLM-as-a-Judge 不微調，直接提示現成 LLM 檢查解答（Table A.3），實驗中產生 32 條驗證理由取多數決；DPO 驗證器依 Hosseini et al. (2024)，以 DPO（direct preference optimization，一種直接在「較好／較差」配對上訓練政策的方法）在「正確解 vs 錯誤解」配對上訓練；self-consistency 不用驗證器，抽多份解答、取最常見的最終答案。

    判別式 RM 的分數是 $r_\theta=\mathrm{sigmoid}(z_{cls})$，以 BCE 訓練（Eq. 3），正確與錯誤資料各半。它只在一個專用輸出（$cls$ 的 logit）上給一個數字、不產生文字，所以不能先寫 CoT，也無法和解題的 SFT 在同一個輸出頭上統一。論文 Sec. 5 提到 Yang et al. (2024) 雖然加了輔助的生成式 SFT 損失，但放在另一個頭上作正則化、訓練後丟棄，查詢 RM 時不產生文字。這就是作者說判別式 RM 沒有用到 LLM 生成能力的意思。

    檢查理解

    判別式 RM 的分數與損失是什麼？為什麼說它沒用到生成能力？

    $r_\theta=\mathrm{sigmoid}(z_{cls})$，以 BCE 訓練（Eq. 3），正負資料各半；只在專用輸出上給一個數字、不產生文字，不能先寫 CoT，也無法和解題 SFT 在同一個輸出頭上統一。

    03 · GenRM

    GenRM 以 Yes token 的機率作為分數

    GenRM 的最簡形式是直接驗證器（Sec. 3.1）。在題目與解答後面接上固定提示 $I$＝「Is the answer correct (Yes/No)?」，讓模型預測下一個 token。訓練資料是 $\mathcal D_{\text{Direct}}=\{((\mathbf x,\mathbf y^+,I),\text{'Yes'})\}\cup\{((\mathbf x,\mathbf y^-,I),\text{'No'})\}$，在上面最小化 Eq. 2 的 SFT 損失，等於最大化正確解的 $\log p_\theta(\text{Yes}\mid\cdot)$ 與錯誤解的 $\log p_\theta(\text{No}\mid\cdot)$。推論時以 Yes 的機率為分數：

    $$r_{\text{Direct}}(\mathbf x,\mathbf y)=p_\theta(\text{Yes}\mid\mathbf x,\mathbf y,I)$$
    Eq. 4

    作者認為使用機率（而不是只看最後輸出 Yes 或 No）納入了驗證器的信心，降低測試時判錯的機會。$p_\theta(\text{Yes})$ 是對整個詞彙表做 softmax 的結果，Fig. 3 也畫出「其他 token」的機率。論文的溫度 $\gamma$ 是為生成定義的，Eq. 4 沒有說評分時使用 $\gamma\ne1$；本頁推定評分時 $\gamma=1$ 推定。

    C2

    Yes token 的分數與損失

    示範值

    這是單一位置的 softmax 計算，logit 為示範值；實際 LLM 的詞彙表有數十萬個 token，這裡把 Yes、No 以外的 token 合併成一個「其他」，它的 logit 代表這些 token 的 log-sum-exp。

    這份解答其實是

    讀數由本頁依 Eq. 4 與 softmax 即時計算。「只看 Yes 與 No 的 sigmoid」與梯度式 本頁推導。

    GenRM 直接驗證器的分數是 $r_{\text{Direct}}=p_\theta(\text{Yes}\mid\mathbf x,\mathbf y,I)$，$I$＝「Is the answer correct (Yes/No)?」，以 SFT 損失訓練正確解→Yes、錯誤解→No（Eq. 2、4）。它與判別式 RM 的關係 本頁推導：若其他 token 的機率可忽略，$p(\text{Yes})\approx\mathrm{sigmoid}(z_Y-z_N)$，正確解上的損失 $-\log p(\text{Yes})$ 就與 Eq. 3 的 BCE 形式相同；是否真的近似取決於其他 token 分到的機率，論文沒有量測。兩者的參數也不同：判別式 RM 用特殊 token $cls$ 的 logit，GenRM 用語言模型頭上既有的 Yes／No token，並接在提示 $I$ 之後。論文的量測是直接 GenRM（不用 CoT）只與判別式 RM 相當或略好（Fig. D.1），主要增益來自後面的 CoT 與多數決（Sec. 4.1）。

    C2 的梯度欄是損失 $-\log p(\text{target})$ 對各 logit 的偏微分 $(p_j-\mathbb 1[j=\text{target}])/\gamma$ 本頁推導。目標是 Yes 時，梯度下降會提高 $z_Y$、降低 $z_N$ 與其他 token 的 logit。

    檢查理解

    GenRM 的分數怎麼定義、怎麼訓練？它與判別式 RM 在數學上的關係？

    $r_{\text{Direct}}=p_\theta(\text{Yes}\mid\mathbf x,\mathbf y,I)$，以 SFT 損失訓練正確解→Yes、錯誤解→No（Eq. 2、4）。其他 token 機率可忽略時 $p(\text{Yes})\approx\mathrm{sigmoid}(z_Y-z_N)$，損失與 BCE 形式相同，是否近似論文未量測（本頁推導）；直接 GenRM 只與判別式 RM 相當或略好（Fig. D.1）。

    04 · 統一訓練

    同一個模型同時學解題與驗證

    因為驗證只是再生成一個 token，GenRM 可以把驗證資料與解題資料混在同一個 SFT 損失裡（Sec. 3.2）。$\mathcal D_{\text{verify}}$ 是驗證資料，目前只介紹過 $\mathcal D_{\text{Direct}}$；05 章會介紹另一種驗證資料 $\mathcal D_{\text{CoT}}$（每份解答附一段逐步驗證理由），它同樣可以放進下式。$\mathcal D_{\text{correct}}$ 在這裡當作「題目 → 正確解」的生成資料，$\lambda>0$ 控制兩者的混合比例：

    $$\mathcal L_{\text{GenRM}}(\theta,\mathcal D_{\text{verify}})=\mathcal L_{\text{SFT}}(\theta,\mathcal D_{\text{verify}})+\lambda\,\mathcal L_{\text{SFT}}(\theta,\mathcal D_{\text{correct}})$$
    Eq. 5
    統一訓練的實驗結論
    圖設定結論

    統一訓練的損失是 $\mathcal L_{\text{GenRM}}=\mathcal L_{\text{SFT}}(\mathcal D_{\text{verify}})+\lambda\mathcal L_{\text{SFT}}(\mathcal D_{\text{correct}})$（Eq. 5），論文預設所有 GenRM 都用它；$\lambda$ 的預設值是演算法任務 1/3、GSM8K 1/4（App. D）。加入解題資料在所有任務上都提升驗證（Fig. 9），但解題資料過多會降低驗證表現（Fig. D.3）；反方向，把驗證資料加進生成器的訓練，生成器本身的 Pass@N 也提高（Fig. 10）。演算法任務用真值驗證資料，增益大於使用合成理由的 GSM8K。作者推測教模型驗證能加深它對生成過程的理解。

    檢查理解

    Eq. 5 是什麼？λ 的預設值與過大的後果？

    $\mathcal L_{\text{GenRM}}=\mathcal L_{\text{SFT}}(\mathcal D_{\text{verify}})+\lambda\mathcal L_{\text{SFT}}(\mathcal D_{\text{correct}})$；演算法 1/3、GSM8K 1/4；加入解題資料提升驗證（Fig. 9），過多則降低（Fig. D.3）；驗證資料也提升生成的 Pass@N（Fig. 10）。
