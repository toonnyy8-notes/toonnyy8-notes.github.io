## 1. 介紹（步驟 6-1）

### 1.1 一段話總結

MoE（Mixture-of-Experts）以「條件計算」擴大模型：每個 token 只啟用少數專家，總參數變多而每個 token 的計算量不變。作者指出語言建模混合兩種子任務：需要深層動態計算的組合推理，以及大量局部、固定、刻板的片段（專有名詞、慣用語）。後者原本可以查表解決，但 Transformer 沒有查表的基本運算，只能用前幾層的注意力與 FFN 逐步「算出」這些片段。作者引用的例子是 Table 3，它轉載自 Ghandeharioun et al. (2024) 以 PatchScope 對另一個模型的分析，不是本文的量測：該模型到第 6 層才把 “Wales” 解析成 “Diana, Princess of Wales”。作者稱這個過程「理論上可以用一次知識查找完成」。本文提出另一條稀疏軸「條件記憶（conditional memory）」，以 **Engram** 模組實作：把目前位置結尾的 2-gram、3-gram 經 tokenizer 壓縮與多頭雜湊，在大型嵌入表中以 O(1) 查出向量（Sec. 2.2），再用目前隱藏狀態算出的純量閘門 $\alpha_t$ 調節、經短卷積後加回殘差流（Sec. 2.3）。作者定義「稀疏度分配」問題：固定總參數與每 token 計算量，把未啟用參數的比例 $\rho$ 分給 MoE 專家、$1-\rho$ 分給 Engram；驗證損失對 $\rho$ 呈 U 形，最佳約在 $\rho\approx75\%$–$80\%$（Sec. 3.1，Fig. 3 左）。作者據此擴大到 Engram-27B。它的 $\rho=74.3\%$，略低於 75%–80% 的區間。與參數量、FLOPs 都相同的 MoE-27B 相比，各類任務都進步（Table 1）：知識類 MMLU +3.0、CMMLU +4.0；一般推理增益更大，BBH +5.0、ARC-C +3.7、DROP +3.3；程式與數學 HumanEval +3.0、MATH +2.4，與知識類相當。長文脈 RULER Multi-Query NIAH 由 84.2 升到 97.0（Table 2）。LogitLens 與 CKA 顯示 Engram 讓淺層提早完成特徵組合，相當於增加有效深度（Sec. 6.1）。因為查表位址只由輸入 token 決定，推論時可以提前從主機記憶體預取，把 100B 參數的表放在 CPU 端，吞吐量最多只降 2.8%（Table 4）。

### 1.2 研究動機（Sec. 1）

1. MoE 已是前沿模型的標準稀疏做法，但它只擴大「計算」這一軸。
2. 文本中相當比例是局部、靜態、刻板的模式（具名實體、固定片語）；經典 N-gram 模型能以低成本查表捕捉這類局部依賴。
3. 標準 Transformer 沒有原生的知識查找運算，只能用多層注意力與 FFN 重建一張靜態查找表，浪費序列深度。作者以 Table 3 說明，該表轉載自 Ghandeharioun et al. 2024 的 PatchScope 分析，屬於外部例子，不是本文對自家模型的量測。
4. 先前的 N-gram 嵌入工作（OverEncoding、SCONE 等）沒有在嚴格等參數、等 FLOPs 下驗證，也把嵌入放在輸入層（Layer 0），讓記憶存取與計算序列化（Sec. 7）。

### 1.3 貢獻

1. 提出「條件記憶」作為與條件計算互補的稀疏軸，並以 Engram 實作：tokenizer 壓縮、多頭雜湊、情境感知閘門、多分支整合（Sec. 2）。
2. 稀疏度分配問題與 U 形規律：$\rho\approx75\%$–$80\%$ 在兩個計算預算下都最佳；記憶無限擴大時損失對槽數呈對數線性（Sec. 3，Fig. 3）。
3. 等參數、等 FLOPs 的 27B 規模驗證，以及 40B 的擴展（Table 1）；長文脈延伸訓練的 iso-loss 比較（Table 2）。
4. 機制分析：LogitLens、CKA、插入層掃描、元件消融、推論時關閉 Engram 的敏感度（Sec. 6.1–6.3、6.5）。
5. 基礎設施導向設計：確定性位址 → 訓練時跨 GPU 分片、推論時預取並與計算重疊、依 Zipf 分布做多層快取（Sec. 2.5、6.4）。

#### 步驟 1：兩種子任務與 MoE 的參數預算（Sec. 1、3.1）

- MoE：每層有多個專家 FFN，路由器依隱藏狀態為每個 token 選 top-$k_{\text{act}}$ 個專家；未選中的專家參數屬於 $P_{\text{sparse}}$，不增加該 token 的計算量。DeepSeekMoE 另有共享專家（每個 token 都會用到）。
- 作者主張：組合推理需要深層動態計算；具名實體、慣用語是局部靜態的，適合查表。Transformer 沒有查表運算，只能用前幾層重建。作者用 Table 3 說明：Diana 例子中第 1–2 層只解讀為「英國的一個國家」，第 6 層才得到完整實體。這張表轉載自 Ghandeharioun et al. (2024)，是以 PatchScope 對另一個模型做的分析，頁面標為「外部例子」，不寫成本文對 Engram 或 MoE-27B 的量測。作者的措辭是這個過程「理論上可以用一次知識查找完成」（Sec. 6.1）。
- 下一步：需要一個「依輸入內容查表」的稀疏模組，與「依隱藏狀態選專家」的 MoE 並列。

#### 步驟 2：tokenizer 壓縮（Sec. 2.2，App. C，Table 6）

- 子詞 tokenizer 為了可逆重建，常給語意相同的字串不同 ID（例：`Apple` 與 `␣apple`）。作者預先計算滿射 $\mathcal P:V\to V'$，依正規化後的文字（NFKC、轉小寫等）把原始 ID 合併成標準 ID。128k tokenizer 的有效詞表縮小 23%（Sec. 2.2；Table 6 寫 23.43%）。
- Table 6 前五名：所有空白類 token（`\t`、`\n`、`␣␣` 等 163 個）合併為 `␣`；`A`、`a`、`␣a`、`á`、`ä` 等 54 個合併為 `a`；`o` 40 個；`e` 35 個；`i` 30 個。
- 示範程式的正規化順序：NFKC → NFD → 去除重音 → 小寫 → 連續空白改為單一空格 → 去頭尾空白（純空白 token 保留為一個空格）。去頭尾空白使 `␣apple` 與 `apple` 合併，與 Table 6 一致。
- 位置 $t$ 的後綴 $n$-gram：$g_{t,n}=(x'_{t-n+1},\dots,x'_t)$。序列開頭不足 $n$ 個 token 時，示範程式以 pad ID 補齊。
- 下一步：$|V'|^n$ 種組合無法逐一給參數，需要雜湊。

#### 步驟 3：多頭雜湊（Sec. 2.2，Eq. 1–2）

$$z_{t,n,k}\triangleq\varphi_{n,k}(g_{t,n}),\qquad \mathbf e_{t,n,k}=\mathbf E_{n,k}[z_{t,n,k}]\tag{Eq. 1}$$
$$\mathbf e_t\triangleq\big\Vert_{n=2}^{N}\big\Vert_{k=1}^{K}\mathbf e_{t,n,k}\tag{Eq. 2}$$

- 沿用 Tito Svenstrup et al. (2017) 的雜湊嵌入；每個階數用 $K$ 個不同的頭降低碰撞；表大小 $M_{n,k}$ 取質數；$\varphi_{n,k}$ 是輕量的乘法–XOR 雜湊（論文只寫到這裡）。
- 示範程式的具體做法（頁面以「示範程式」標明）：每層抽 $N$ 個奇數乘數 $m_0,\dots,m_{N-1}$；$\text{mix}=(x'_t m_0)\oplus(x'_{t-1}m_1)\oplus\cdots$（$\oplus$ 為逐位元 XOR，共 $n$ 項）；第 $k$ 頭的索引為 $\text{mix}\bmod M_{n,k}$。$M_{n,k}$ 是從設定的表大小往上找、彼此不重複的質數。各頭向量維度為 `n_embed_per_ngram / n_head_per_ngram`。
- 〔本頁推導〕示範程式的 $K$ 個頭共用同一個 mix，只是模數不同。由中國餘數定理，兩個 $n$-gram 在 $K$ 頭全部同格，若且唯若兩者的 mix 對 $\prod_k M_{n,k}$ 同餘。$K=8$、$M\approx2.26\times10^6$ 時這個乘積約 $10^{51}$。以示範程式的規模估計，token ID $<2^{17}$、乘數 $<2^{31}$，mix 的範圍 $R$ 約 $2^{48}\approx2.8\times10^{14}$（推定），遠小於上述乘積。所以「全部同格」只在 mix 完全相同時發生。但 mix 本身只有約 $2^{48}$ 種值，不同 $n$-gram 仍可能得到相同的 mix。
- 〔本頁推導〕碰撞的近似分析：表中共有 $U$ 個不同 $n$-gram，單一頭大小 $M$。$U$ 是讀者假設的值，論文沒有給出不同 $n$-gram 的數量。
  - 某 $n$-gram 在一個頭與至少一個其他 $n$-gram 同格的機率 $p_1=1-(1-1/M)^{U-1}$。
  - $K$ 個頭都與別人同格，也就是沒有任何一個無碰撞的頭，機率為 $p_1^K$。這一項假設各頭近似獨立，`check.py` 的實測在 $U\le20{,}000$ 時與它相符。
  - 與它在 $K$ 頭全部同格的其他 $n$-gram 期望個數：
    - 獨立模型為 $(U-1)/M^K$，只在 $M^K$ 不超過 mix 範圍 $R$ 時成立。
    - $M^K>R$ 時，全部同格等於 mix 相同，期望值的下限是 $(U-1)/R$。
    - 頁面合併為 $E_{\text{full}}\approx(U-1)/\min(M^K,R)$（推定 $R=2^{48}$）。若要整張表完全沒有全部同格的組合，需要 $U^2\ll R$，也就是 $U\ll1.7\times10^7$。
  - 例：$U=10^6$、$M=2{,}262{,}400$ 時 $p_1=0.357$。$K=8$ 時 $p_1^8=2.65\times10^{-4}$；獨立模型給 $\log_{10}=-44.8$，mix 下限給 $\log_{10}E_{\text{full}}=-8.45$。$U=10^9$ 時每一頭幾乎每格都被共用（$p_1\approx1$），$E_{\text{full}}\approx3.6\times10^{-6}$（$\log_{10}=-5.45$）。這個值仍然很小，但比獨立模型的 $10^{-41.8}$ 高約 36 個數量級。頁面不寫「8 個頭的組合必然唯一」。
  - 正式模型的雜湊細節論文沒有寫，$R$ 只依示範程式推定（R2、R9）。
- 單位與表大小的換算（推定）。
  - 每層、每個階數 $n$ 有 $K=8$ 張表 $\mathbf E_{n,k}$，每張約 $V_{\text{E}}$ 列。各張表的列數是彼此不同的相鄰質數，差距可忽略。
  - 每列 $d_{\text{mem}}/((N-1)K)=1280/16=80$ 維，所以一個階數在一層的 8 個頭合計 $8\times80=640$ 維。
  - Table 5 的 Engram Vocab Size 解讀為每個頭的列數 $V_{\text{E}}$：2,262,400 = 129,280 × 17.5，7,239,680 = 129,280 × 56。示範程式的預設寫法為 `129280*5`，也是以詞表大小的倍數設定表大小。
  - Engram 參數 $=2\text{ 層}\times2\text{ 階}\times8\text{ 頭}\times V_{\text{E}}\times80$：27B 為 5.79B（論文 5.7B），40B 為 18.53B（論文 18.5B）。
  - Sec. 3.2 的「slot」單位不同，見步驟 7。頁面把這兩個詞分開使用：Table 5 寫「每頭列數」，Sec. 3.2 寫「槽」。
- 下一步：雜湊查出的向量不看上下文，會受碰撞與多義影響，需要依上下文調節。

#### 步驟 4：情境感知閘門（Sec. 2.3，Eq. 3–4）

$$\mathbf k_t=\mathbf W_K\mathbf e_t,\qquad \mathbf v_t=\mathbf W_V\mathbf e_t\tag{Eq. 3}$$
$$\alpha_t=\sigma\!\left(\frac{\mathrm{RMSNorm}(\mathbf h_t)^\top\mathrm{RMSNorm}(\mathbf k_t)}{\sqrt d}\right),\qquad \tilde{\mathbf v}_t=\alpha_t\cdot\mathbf v_t\tag{Eq. 4}$$

- 以注意力為藍本：$\mathbf h_t$（已經過前面注意力層彙整全域上下文）當 Query，記憶 $\mathbf e_t$ 同時產生 Key 與 Value。對 Query、Key 做 RMSNorm 是為了梯度穩定。作者的解釋：若查出的記憶與目前上下文矛盾，$\alpha_t$ 趨近 0，該位置的記憶向量幾乎不加入殘差流。
- 〔本頁推導〕假設 RMSNorm 增益為 1 並忽略 eps，$\mathrm{RMSNorm}(\mathbf y)=\mathbf y/\sqrt{\tfrac1d\sum y_i^2}$ 的長度恰為 $\sqrt d$，Eq. 4 的 sigmoid 引數等於 $\sqrt d\cos\theta$（$\theta$ 為 $\mathbf h_t$ 與 $\mathbf k_t$ 的夾角）。在這個假設下，$d=2560$ 時引數的範圍是 $\pm50.6$；只有 $|\cos\theta|<5/\sqrt{2560}=0.099$ 時 $|s|<5$。論文的 RMSNorm 有可學增益，實際範圍取決於增益，所以 $\pm50.6$ 只是增益為 1 時的值，不代表正式模型的實際範圍。頁面以 $s=\gamma\sqrt d\cos\theta$ 表示，$\gamma$ 代表學到的增益對引數的整體縮放（本頁簡化）。
- 頁面把 Eq. 4 拆成兩行顯示：先定義 $s_t=\mathrm{RMSNorm}(\mathbf h_t)^\top\mathrm{RMSNorm}(\mathbf k_t)/\sqrt d$，再寫 $\alpha_t=\sigma(s_t)$，避免窄螢幕溢出。
- 示範程式在 sigmoid 前多做一步帶號平方根 $s\mapsto\mathrm{sign}(s)\sqrt{|s|}$，論文 Eq. 4 沒有這一步。頁面 C2 提供切換並註明出處，不宣稱哪一個是正式模型的實作（R3）。
- 下一步：閘門只看單一位置，作者再加短卷積擴大感受野並增加非線性。

#### 步驟 5：短卷積、殘差融合與插入位置（Sec. 2.3，Eq. 5；Sec. 2.5、6.2）

$$\mathbf Y=\mathrm{SiLU}\big(\mathrm{Conv1D}(\mathrm{RMSNorm}(\tilde{\mathbf V}))\big)+\tilde{\mathbf V}\tag{Eq. 5}$$

- 深度（depthwise）因果卷積，核大小 $w=4$、擴張率 $\delta$ = 最大 N-gram 階數（3），SiLU 激活。融合：$\mathbf H^{(\ell)}\leftarrow\mathbf H^{(\ell)}+\mathbf Y$，之後接標準的 Attention 與 MoE。
- 卷積參數初始化為 0，訓練開始時 $\mathrm{Conv1D}(\cdot)=0$、$\mathrm{SiLU}(0)=0$，所以 $\mathbf Y=\tilde{\mathbf V}$（Sec. 4.1「strictly preserve the identity mapping」）。
- 〔本頁推導〕卷積在位置 $t$ 讀取 $t,\ t-\delta,\ t-2\delta,\ t-3\delta$ 四個位置的 $\tilde{\mathbf v}$。依 Eq. 2，每個位置的查表內容同時包含結尾於該處的 2-gram 與 3-gram，3-gram 的視窗較長，涵蓋了 2-gram 的視窗。$\delta=N=3$ 時，四個 3-gram 視窗剛好首尾相接、不重疊，查表內容的範圍是連續 $wN=12$ 個位置；$\delta=1$ 時只有 $N+w-1=6$ 個。位置靠近句首時，部分位置落在句首以前，由 pad 補齊。C3 的預設 $t=9$ 就是 10 個句內 token 加 2 個 pad。這裡只計算「查表內容」的來源：$\alpha_{t'}$ 依賴 $\mathbf h_{t'}$，而 $\mathbf h_{t'}$ 經注意力看過整個前綴。
- 只在部分層插入（Engram-27B：第 2、15 層）。插入位置的權衡（Sec. 6.2）：插得越早，查表結果越早進入殘差流，主幹花在重建局部模式上的層數越少；但越早的 $\mathbf h_t$ 上下文越少、各分支差異越小，閘門越不精確。12 層 3B MoE 上單一模組掃描第 1–12 層，第 2 層最佳（Val Loss 1.770），越深越差；同樣 1.6B 拆成兩個模組放在第 2、6 層更好（1.768）。系統面另一個考量：越深的插入點留給預取的計算時間越長（Sec. 2.5）。
- 下一步：主幹是多分支殘差流，Engram 要配合調整。

#### 步驟 6：與多分支架構整合（Sec. 2.4，Eq. 6）

$$\alpha_t^{(m)}=\sigma\!\left(\frac{\mathrm{RMSNorm}(\mathbf h_t^{(m)})^\top\mathrm{RMSNorm}(\mathbf W_K^{(m)}\mathbf e_t)}{\sqrt d}\right),\qquad \mathbf u_t^{(m)}=\alpha_t^{(m)}\cdot(\mathbf W_V\mathbf e_t)\tag{Eq. 6}$$

- 主幹採 Manifold-Constrained Hyper-Connections（mHC），殘差流擴成 $M=4$ 條平行分支，以可學的連接權重混合。
- 參數共享：一張嵌入表與一個 $\mathbf W_V$ 由 $M$ 條分支共用；每條分支有自己的 $\mathbf W_K^{(m)}$，讓閘門可依分支不同。一個 $\mathbf W_V$ 與 $M$ 個 $\mathbf W_K^{(m)}$ 可融合成一次稠密 FP8 矩陣乘法。
- Engram-27B 有 2 個 Engram 層 × 4 條分支，每個 token 共 8 個閘門純量（Sec. 6.5 註腳 2）；Fig. 7 只顯示與語意模式最相關的那一個。
- 消融中的「w/o multi branch」保留 mHC 主幹，但改為在 pre-mapping 後的 $\mathbf H_{pre}$ 上做單一融合（Sec. 6.2）。

#### 步驟 7：稀疏度分配與 U 形規律（Sec. 3.1，Eq. 7，Fig. 3 左）

$$P^{(\text{sparse})}_{\text{MoE}}=\rho\,P_{\text{sparse}},\qquad P_{\text{Engram}}=(1-\rho)\,P_{\text{sparse}}\tag{Eq. 7}$$

- 固定 $P_{\text{tot}}$ 與 $P_{\text{act}}$（等參數、等 FLOPs），只調整路由專家數與 Engram 槽數。$\rho=1$ 為純 MoE。Engram 每個 token 只取固定數量的槽，增加槽數只增加 $P_{\text{tot}}$。
- 兩個預算（稀疏比 $P_{\text{tot}}/P_{\text{act}}\approx10$）：$C=2\times10^{20}$ FLOPs，$P_{\text{tot}}\approx5.7$B、$P_{\text{act}}=568$M、基準 106 個專家；$C=6\times10^{20}$，$P_{\text{tot}}\approx9.9$B、$P_{\text{act}}=993$M、基準 99 個專家。
- 結果：兩個預算都呈 U 形。$\rho\approx40\%$（5.7B 模型 46 個專家、9.9B 模型 43 個）時已與純 MoE 相當；把約 20%–25% 的稀疏預算給 Engram 最好。10B 預算下驗證損失由 1.7248（$\rho=100\%$）降到 1.7109（$\rho\approx80\%$），$\Delta=0.0139$；最佳位置在兩個預算都落在 $\rho\approx75\%$–$80\%$。作者解釋：$\rho\to100\%$ 缺少靜態模式的專用記憶，只能用深度與計算重建；$\rho\to0\%$ 失去條件計算，記憶無法取代計算。
- 〔本頁推導〕專家數換算：若 $\rho=1$ 時所有未啟用參數都是未被選中的路由專家（每個專家大小相同、top-6），則 $E(\rho)=6+\rho(E_0-6)$。$E(0.4)=46.0$（$E_0=106$）與 $43.2$（$E_0=99$），與論文的 46、43 一致；Engram-27B 由 72 減到 55 個專家，$\rho=(55-6)/(72-6)=74.2\%$，論文寫 74.3%。
- Engram-27B 的 $\rho=74.3\%$ 略低於作者在小規模實驗中找到的 75%–80% 區間。論文沒有說明為什麼選這個值，頁面不寫成「27B 落在最佳點」，只寫「依小規模結果選擇的接近值」。
- 〔本頁推導〕Engram-27B 的參數核對。Table 1 的「26.7B」寫在「Total Params」列，下一列才是「Activated (w/o token embed)」，所以 26.7B 是否含詞嵌入無法確定。頁面並列兩種讀法，都標「推定」：
  - 讀法 A：26.7B 含詞嵌入與 LM head（$2\times129{,}280\times2560=0.662$B）。$P_{\text{tot}}=26.04$B，$P_{\text{sparse}}=26.04-3.8=22.24$B，$(1-49/66)\times22.24=5.73$B，與 5.7B 一致。
  - 讀法 B：26.7B 已不含這兩者。$P_{\text{sparse}}=26.7-3.8=22.9$B，$(1-49/66)\times22.9=5.90$B。
  - 讀法 A 較接近論文的 5.7B，C4 的 27B 預設組採用讀法 A。
- 無限記憶（Sec. 3.2，Fig. 3 右）：作者固定 3B MoE 主幹（$P_{\text{act}}=568$M、訓練 100B token），把槽數 $M_{\text{slot}}$ 由 $2.58\times10^5$ 掃到 $10^7$，最多增加約 13B 參數。驗證損失對槽數呈冪律，在對數座標下為直線。在同樣的記憶預算下，Engram 比 OverEncoding（把 N-gram 嵌入與詞嵌入平均）有更大的擴展潛力。

  - 論文沒有給出 Fig. 3 的曲線數值，頁面不重繪曲線，也不做互動元件，只在 S7 正文用一句話寫出掃描範圍與「對數線性」的結論。

#### 步驟 8：大規模預訓練（Sec. 4，Table 1、5）

- 共同設定：262B token、DeepSeek-V3 tokenizer（128k，Table 5 寫 129,280）、30 個 block、隱藏維度 2560、MLA 32 頭、mHC 擴展率 4、Muon 最佳化器；啟用參數皆 3.8B。

#### 步驟 9：長文脈延伸（Sec. 5，Table 2）

- 預訓練後以 YaRN 在 32768 token 上訓練 5,000 步（30B token），$s=10,\alpha=1,\beta=32$，$f=0.707$。
- 方法論：Engram 41k → 46k → 50k 的長文脈表現隨預訓練進度單調上升，表示長文脈能力與基礎模型的整體能力耦合；所以比較架構時要對齊預訓練損失，而不只對齊步數。
- 三種比較（對手皆為 MoE-27B 50k，預訓練損失 1.63）：

  - Iso-FLOPs（Engram 50k）：差距更大，例如 VT 89.0、LongPPL Book 4.14 vs 4.38。
  - 約 82% 計算量（Engram 41k）：LongPPL 與基準相當（Book 4.37 vs 4.38），多數 RULER 子項較高（MQ 89.5 vs 84.2、FWE 99.6 vs 73.0），S（99.6 vs 100.0）與 CWE（3.8 vs 4.5）略低。「82%」是預訓練步數比 41k/50k = 0.82，論文稱為「82% of the pre-training FLOPs」；頁面寫「依步數換算約 82%」，不當成獨立量測的 FLOPs。

#### 步驟 10：機制分析（Sec. 6.1–6.3、6.5）

- LogitLens：把各層隱藏狀態直接接最終 LM head，計算與最終輸出分布的 KL 散度。兩個 Engram 模型的 KL 都系統性地較小，差距在淺層最明顯（Fig. 4a），表示特徵組合較早完成。
- CKA（Eq. 8）：$\mathrm{CKA}(K,L)=\mathrm{HSIC}(K,L)/\sqrt{\mathrm{HSIC}(K,K)\mathrm{HSIC}(L,L)}$，$K=XX^\top$、$L=YY^\top$（線性核），minibatch 無偏 HSIC 估計，資料為 Few-NERD 具名實體的最後一個 token。軟對齊指標（Eq. 9）$a_j=\sum_{i\in I_j}S_{i,j}\,i/\sum_{i\in I_j}S_{i,j}$，$I_j$ 為與 Engram 第 $j$ 層最相似的 top-5 個 MoE 層。觀察到 $a_j>j$：Engram-27B 第 5 層約對應 MoE 第 12 層（Fig. 4b–c）。作者的結論：Engram 在功能上相當於增加有效深度。
- 元件消融（Sec. 6.2，Fig. 5；12 層 3B MoE、0.56B 啟用、100B token；基準 1.808；參考配置 1.6B Engram、{2,3}-gram、第 2 與 6 層，1.768，$\Delta=0.04$）：影響最大的三項是分支專屬融合、情境感知閘門、tokenizer 壓縮（Fig. 5 沒有數值，頁面不排三者的先後）；移除卷積只稍微變差；在固定 1.6B 下加入 4-gram 稍差（作者推測稀釋了較常見的 2/3-gram 容量，不排除更大記憶時有益）。論文沒有給出各消融點的數值，頁面不寫數字。
- 敏感度（Sec. 6.3，Fig. 6）：推論時把 Engram 輸出完全關掉、主幹不變。事實知識只保留 29%–44%（TriviaQA 29%），閱讀理解保留 81%–93%（C3 93%）。作者提醒這種事後消融造成訓練–推論不一致，所以只分析兩端。
- 閘門視覺化（Sec. 6.5，Fig. 7）：閘門在完成局部靜態模式的 token 上啟動，例如 “Alexander the Great”、“the Milky Way”、“By the way”、“Princess of Wales”，中文例如「四大发明」「张仲景」。因為查的是後綴 N-gram，高啟動落在片語的最後一個 token。

#### 步驟 11：系統效率（Sec. 2.5、6.4，Table 4）

- 確定性位址：MoE 的路由依賴執行時的隱藏狀態；Engram 的索引只由輸入 token ID 決定，在該層執行前就能算出。
- 訓練：嵌入表以模型平行切分到各 GPU，前向用 All-to-All 收集被用到的列、反向分派梯度，總記憶容量隨 GPU 數線性增加。
- 推論：嵌入表放在主機記憶體，經 PCIe 非同步預取，與前面層的計算重疊（Fig. 2b）。插得越深，可隱藏延遲的計算時間越長；但建模偏好早插入（步驟 5），兩者要同時滿足。
- 多層快取：N-gram 存取服從 Zipf 分布，少數模式佔大多數存取；常用列放 HBM 或 DRAM，長尾放 NVMe SSD。
- Table 4（nano-vLLM、H800、512 條序列、長度 Uniform(100, 1024)，100B 參數 Engram 放在第二個 block、整張表在主機 DRAM，與第一個 block 的計算重疊）：4B-Dense 9,031.62 → 8,858.28 tok/s（−1.92%〔本頁推導〕）；8B-Dense 6,315.52 → 6,140.02 tok/s（−2.78%，論文寫 2.8%）。每步的通訊量隨啟用的槽數增加，與表的總大小無關。這組實驗強制所有查表都走 PCIe，沒有使用快取，作者稱之為保守基準。

常見錯誤（頁面 S11 逐條列出）：
1. 把 Engram 當成取代輸入詞嵌入：Engram 插在中間層，輸入嵌入與輸出 un-embedding 保持不變（Fig. 1 說明）。
2. 用原始 token ID 直接雜湊：要先經 $\mathcal P$ 壓縮；消融顯示 tokenizer 壓縮是影響最大的三項之一。
3. 只用一個雜湊頭：每個階數用 $K$ 個頭與質數表大小；單頭時碰撞即無法區分（C1）。
4. 卷積沒有零初始化：零初始化保證訓練開始時 $\mathbf Y=\tilde{\mathbf V}$。
5. 嵌入表沿用主幹的最佳化設定：論文對嵌入用 Adam、學習率 ×5、weight decay 0，主幹用 Muon、weight decay 0.1。
6. 只看建模而把 Engram 插得很深（或只看系統而插得很淺）：插入層要同時滿足建模（早）與預取延遲（晚）。
7. 比較長文脈能力時只對齊步數：應對齊預訓練損失（Sec. 5.2）。
8. 層編號：論文寫第 2 與 15 層，示範程式的 `layer_ids` 為 [1, 15]（0 起算的 block 索引），兩者的起算方式論文沒有說明（R4）。

### C1 · 從 token 到嵌入表索引（S3）

- **教的概念**：tokenizer 壓縮 → 後綴 N-gram → $K$ 個頭各得一個索引（Eq. 1–2）；多頭使「全部同格」很罕見，但示範程式的各頭共用一個 mix，所以全部同格的機率有下限（〔本頁推導〕）。
- **面板 A：管線**
  - 輸入：預設句兩個 chip（「Fig. 1 例句」= `Only Alexander the Great could tame the horse Bucephalus.`；「壓縮示例」= `The cat saw the CAT. Thé café, the Café.`）；可編輯文字框（最多 200 字元、40 個 token，超出截斷並提示）；位置 $t$（點選 token 方塊或滑桿，範圍 $0$ 到 $T-1$，Fig. 1 例句為 0–9，預設 $t=3$）；$K\in\{1,2,4,8\}$ 分段按鈕（預設 8）；每頭表大小目標 $M_{n,k}$（固定 10,000，面板 A 不提供調整，避免與面板 B 混淆；頁面控制項一律標 $M_{n,k}$，不用單獨的 $M$，因為 $M$ 是分支數）。
  - 演算法（照錄於頁面「示範」標籤下）：
    1. 玩具分詞：`text.match(/\s*[\p{L}\p{N}]+|\s*[^\s\p{L}\p{N}]/gu)`，每個 token 保留前導空白（以 `␣` 顯示）。這是本頁的玩具分詞器，不是 DeepSeek-V3 tokenizer。
    2. 原始 ID：依首次出現順序編號（從 1 起）。
    3. 正規化：`s.normalize('NFKC').normalize('NFD').replace(/\p{M}/gu,'').toLowerCase().replace(/[ \t\r\n]+/g,' ')`；結果為單一空格則保留 `' '`，否則 `trim()`；若結果為空字串則用原 token。標準 ID 依正規化字串首次出現順序編號（從 1 起），0 保留給 pad。
    4. 乘數：`r = mulberry32(0)`，$m_i=2\lfloor r()\cdot2^{30}\rfloor+1$，$i=0,1,2$ → 572152369、708123、479473029。
    5. 表大小：2-gram 用 `nextPrimes(10000, K)`，3-gram 接著再取 $K$ 個（$K=8$：10007…10079 與 10091…10141）。
    6. 索引：$\text{mix}=x'_t m_0\oplus x'_{t-1}m_1[\oplus x'_{t-2}m_2]$，$t-i<0$ 時以 0（pad）代入；用 `BigInt` 計算（JS 的 `^` 只有 32 位元）；索引 $=\text{mix}\bmod M_{n,k}$。
  - 顯示：token 帶兩列（原始 token＋原始 ID；正規化字串＋標準 ID，合併的 token 以相同底色與 `=` 記號標出）；讀數「$|V|$ → $|V'|$，縮小 x%」。選定 $t$ 時，2-gram 與 3-gram 視窗以括號標在 token 帶下方（2-gram 實線、3-gram 虛線）；下方兩列小格各 $K$ 個，顯示 $z_{t,2,k}$、$z_{t,3,k}$（JetBrains Mono），格上標 $M_{n,k}$。末端一條長方塊標「串接 → $\mathbf e_t$（$2K$ 段）」。
- **面板 B：碰撞**
  - 輸入：$U$（不同 $n$-gram 數，對數滑桿 $10^3$–$10^{10}$，預設 $10^6$）；$M_{n,k}$（每頭大小，對數滑桿 $10^3$–$10^8$，預設 2,262,400，滑桿旁 chip「Engram-27B 的表大小（推定）」可一鍵設定）；$K$（1–16，預設 8）。
  - 計算：
    - $p_1=-\mathrm{expm1}((U-1)\,\mathrm{log1p}(-1/M))$；$p_1^K$。
    - 兩個 $E_{\text{full}}$ 讀數並列：
      - 「獨立模型」$\log_{10}(U-1)-K\log_{10}M$。
      - 「示範雜湊（mix < 2⁴⁸，推定）」$\log_{10}(U-1)-\min(K\log_{10}M,\ 48\log_{10}2)$。
    - 兩者不同時，第一個讀數變灰並加註「此時 $M^K$ 超過 mix 範圍，獨立模型不適用」。
    - 另顯示一行「整張表沒有任何全部同格組合的條件：$U^2\ll2^{48}$（$U\ll1.7\times10^7$）」，目前 $U$ 超過時以文字標「不滿足」。
    - $E_{\text{full}}$ 一律用 $10^{x}$ 形式顯示，避免下溢。$U=1$ 時各值皆為 0。
  - 圖：橫軸 $K=1\ldots16$，縱軸 $p_1^K$（線性 0–1），畫長條並標出目前的 $K$。不用第二條縱軸，$E_{\text{full}}$ 只放在讀數。
  - 實測按鈕「用示範雜湊實測」：僅在 $U\le20{,}000$ 且 $M\le10^5$ 時啟用（否則按鈕停用並顯示原因）。列舉 $U$ 個 2-gram：$i=0,\dots,U-1$，第 $i$ 個為 $(x'_{t-1},x'_t)=(\lfloor i/1000\rfloor+1,\ (i\bmod1000)+1)$；$\text{mix}_i=x'_t m_0\oplus x'_{t-1}m_1$（面板 A 的乘數，`BigInt`）；頭 $k=0,\dots,K-1$ 的表大小 $P_k$ 為 `nextPrimes(M,K)` 的第 $k$ 個（只取這一組，不取 3-gram 那組），索引 $z_{i,k}=\text{mix}_i\bmod P_k$。
  - 讀數定義（三者分母都是 $U$；每個 $n$-gram 只計一次，不是計成對數）：
    - 先數佔用：$c_k(z)=\#\{j: z_{j,k}=z\}$，包含 $i$ 自己。「同格」指 $c_k(z_{i,k})\ge2$，也就是頭 $k$ 上至少還有另一個列舉的 $n$-gram 落在同一格；不指定是哪一個。
    - 「第 1 頭同格比例」$=\#\{i: c_0(z_{i,0})\ge2\}/U$（第 1 頭 = $k=0$，表大小 $P_0$）。
    - 「$K$ 頭都同格比例」$=\#\{i: \forall k,\ c_k(z_{i,k})\ge2\}/U$。各頭的同格對象可以不同；這對應解析值 $p_1^K$ 的「沒有任何無碰撞的頭」。
    - 「索引組完全相同比例」$=\#\{i: \exists j\ne i,\ \forall k,\ z_{j,k}=z_{i,k}\}/U$，也就是同一個對象在 $K$ 頭都與 $i$ 同格（索引組字串出現 ≥ 2 次）。對應 $E_{\text{full}}$。$K=1$ 時三個讀數相同。
    - 顯示：先算三個整數計數，再以 `(count / U).toFixed(4)` 顯示，旁邊附計數（例：「0.3078（6155 / 20000）」）。不可用 `Math.round(count*1e4/U)/1e4`：第 5 節有三個剛好落在 .5 的值（17303、14905、6595），那種寫法會把末位進位成 0.8652、0.7453、0.3298（已用 Node 核對）；`toFixed` 依浮點數的實際值捨入，與 check.py 的 `:.4f` 一致。
    - 並列的解析值用 $P_0$（首個質數）而不是滑桿上的 $M$：$p_1=1-(1-1/P_0)^{U-1}$ 與 $p_1^K$。
  - 實作方式：每個頭一個 `Map`（索引 → 次數），另一個 `Map` 以索引組字串 `idx.join(',')` 計數；第二輪掃描依上面的定義累加三個計數。總時間 O(UK)，不做兩兩比對。
  - 每處理 2000 筆執行一次 `await new Promise(r => setTimeout(r, 0))`。計算期間按鈕停用，旁邊顯示「已處理 i / U」。
  - 輸入改變時取消進行中的計算：以遞增的 run id 判斷，過期的結果直接丟棄。
  - 數值保護：`log1p(-1/M)` 在 $M\ge10^3$ 不會失準；$p_1^K$ 用 `Math.pow`；讀數 < 1e-4 時用科學記號。
- **讀者應觀察到**：(1) 壓縮示例中 `The`、`␣the` 合併、`Thé`／`␣the` 合併、`␣café`／`␣Café` 合併，詞表 10 → 6；(2) $K=1$ 時同格即無法區分；$K$ 增加，$p_1$ 不變但 $p_1^K$ 指數下降；(3) $U\gg M$ 時每格都被共用，$E_{\text{full}}$ 仍然小，但示範雜湊的下限 $(U-1)/2^{48}$ 遠高於獨立模型；$U=10^9$ 時約 $3.6\times10^{-6}$；(4) 實測與解析值接近（$U\le20{,}000$ 時各頭近似獨立）。
- **無障礙**：token 方塊為 `<button>`，依共用的 roving tabindex 規則操作。合併關係除了底色，也用 `=` 與相同的標準 ID 文字表示。讀數區 `aria-live="polite"`，只放純文字，在 `change` 或停止輸入 500ms 後更新。實測進度不放進 live region，只在完成時朗讀一次結果。

### C5 · 預取與計算重疊（S10）

- **教的概念**：確定性位址讓傳輸提早開始，傳輸時間被前面層的計算遮住；MoE 式「到該層才知道索引」沒有可重疊的時間；傳輸量與表的總大小無關。這是本頁的時間模型，參數皆為示範值，不重現 Table 4。模型只用「量 ÷ 頻寬」估計傳輸時間，沒有考慮逐列 gather、隨機存取、延遲、PCIe 實際效率與主機端查表開銷。圖版標題下固定一行：「停頓 0 只表示本模型的估計，不保證實際沒有停頓；論文唯一的量測是 Table 4。」
