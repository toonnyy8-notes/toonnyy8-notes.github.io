 條件記憶：用查表補上 MoE 之外的另一條稀疏軸

 這篇論文在 Transformer 中加入以 N-gram 雜湊查表的記憶模組 Engram，並研究總參數固定時，記憶與專家該如何分配。

 MoE 與「稀疏」的定義見 01、02 節。

 Xin Cheng、Rui Tian 等（北京大學、DeepSeek-AI）〈Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models〉

 Only Alexander the Great could tame the horse Bucephalus.

 01 · 查表Engram 把目前 token 與前一、兩個 token 組成的片段當作鍵，直接在大型嵌入表中查出一個向量。不論表多大，每個 token 只查固定幾格。

 02 · 分配總參數與每個 token 的計算量都固定時，把約 20%–25% 的閒置參數從專家移到記憶，驗證集上的損失（越低越好）最小。

 03 · 規模27B 模型加入記憶後各類測驗都進步，一般推理題進步最多。100B 參數的表放在 CPU 記憶體，推論速度只下降不到 3%。

 01 · 計算與查表

 語言模型同時需要計算與查表

 作者把語言建模分成兩種性質不同的子任務（Sec. 1）。第一種是組合推理：依上下文把多個資訊組合起來，需要深層、動態的計算。第二種是知識檢索：文本中有相當比例是局部、靜態、刻板的片段，例如具名實體（“Alexander the Great”）與固定片語（“By the way”）。這類片段只依賴前面少數幾個 token，經典的 N-gram 模型就能以查表的方式低成本捕捉。

 問題在於標準 Transformer 沒有查表的基本運算。局部靜態模式原本可以查表解決，Transformer 卻只能用前幾層的多層注意力與 FFN 逐步「算出」它們，等於用序列深度重建一張靜態查找表。作者引用的例子是 Table 3。這張表是外部例子，轉載自 Ghandeharioun et al. (2024) 以 PatchScope 對另一個模型的分析，不是本文對 Engram 或 MoE-27B 的量測：模型讀到 “Wales” 時，第 1–2 層只把它解讀為英國的一個國家，到第 6 層才解析成完整的實體 “Diana, Princess of Wales”。Diana 這個實體要到第 6 層才解析完成，作者把它當作證據：前 5 層都花在逐步拼出一個固定的實體上，也就是把層數用來重建一張靜態查找表。作者的措辭是，這個過程「理論上可以用一次知識查找完成」（原文 “could theoretically be identified via a knowledge lookup operation”；Sec. 6.1）。

 據此，作者提出與「條件計算」互補的另一條稀疏軸：條件記憶（conditional memory）。條件記憶指依輸入內容直接查出一段儲存的參數，而不是經由多層計算重建它。本文以 Engram 模組實作條件記憶：用目前位置結尾的 2-gram、3-gram 當作鍵，在大型嵌入表中以 O(1) 查出向量，再依目前的隱藏狀態調節後加回模型（Sec. 2）。下一節先說明條件計算（MoE）如何讓參數變多而計算量不變，條件記憶沿用同一個預算框架。

 02 · 參數預算

 MoE 用路由增加參數而不增加每個 token 的計算量

 MoE（Mixture-of-Experts）把 Transformer 每層的 FFN 換成多個並列的「專家」FFN。每層有一個路由器（router），依目前 token 的隱藏狀態為它打分，只選分數最高的 top-kact $k_{\text{act}}$ ​ 個專家計算，其餘專家對這個 token 不做任何運算。DeepSeekMoE 另有共享專家，每個 token 都會經過。本文的 MoE-27B 有 2 個共享專家與 72 個路由專家，每個 token 選 top-6。這種依輸入選擇部分參數的做法稱為條件計算（Shazeer et al. 2017 提出稀疏閘控 MoE，見研究筆記）。

 為了比較不同架構，作者定義三種參數量（Sec. 3.1）：

 Ptot $P_{\text{tot}}$ ​：總可訓練參數，不含詞嵌入與 LM head。

 Pact $P_{\text{act}}$ ​：每個 token 實際啟用的參數，決定每個 token 的計算量（FLOPs）。

 Psparse=Ptot−Pact $P_{\text{sparse}}=P_{\text{tot}}-P_{\text{act}}$ ​=Ptot​−Pact​：未啟用的參數。它增加模型容量，但不增加每個 token 的 FLOPs。

 以 Table 1 為例，MoE-27B 的總參數為 26.7B，每個 token 啟用 3.8B，大部分參數屬於 Psparse $P_{\text{sparse}}$ ​。MoE 增加 Ptot $P_{\text{tot}}$ ​ 而不增加 FLOPs 的方式是：未被路由器選中的專家參數不參與該 token 的計算。Engram 的方式是：嵌入表可以非常大，但每個 token 只取固定數量的槽（每個階數、每個雜湊頭各一列），所以增加槽數只增加 Ptot $P_{\text{tot}}$ ​，不增加 Pact $P_{\text{act}}$ ​。兩者都把參數放進 Psparse $P_{\text{sparse}}$ ​，差別在選擇的依據。

 03 · tokenizer 壓縮

 先把語意相同的 token 合併

 N-gram 是連續 n $n$ 個 token 組成的片段；N-gram 嵌入是為每個 N-gram 配置一個可學向量，使用時依片段直接取出，屬於 O(1) 的查表，不需要經過任何矩陣乘法。Engram 在查表之前先處理 tokenizer 的一個特性：子詞 tokenizer 為了能把 ID 無損地還原成原文，常給語意相同的字串不同 ID，例如 Apple 與 ␣apple（␣ 表示前導空白）。若直接用原始 ID 組成 N-gram，同一個片語會被拆成多個互不相干的鍵。

 作者因此預先計算一個滿射 P:V→V′ $\mathcal P:V\to V'$ （Sec. 2.2）：依正規化後的文字（NFKC、轉小寫等）把語意相同的原始 ID 合併成同一個標準 ID，xt′=P(xt) $x'_t=\mathcal P(x_t)$ ′​=P(xt​)。對 128k 的 tokenizer，有效詞表縮小 23%（App. C 的 Table 6 寫 23.43%）。官方示範程式的正規化順序是 NFKC → NFD → 去除重音 → 小寫 → 連續空白改為單一空格 → 去頭尾空白；去頭尾空白使 ␣apple 與 apple 合併。

 04 · 多頭雜湊

 多個雜湊頭把 N-gram 映到嵌入表

 碰撞：多頭降低「無法區分」的機率

 p1=1−(1−1M)U−1 $p_1=1-\left(1-\tfrac1M\right)^{U-1}$ ​=1−(1−M1​)U−1

 10 · 有效深度

 Engram 讓淺層提早完成特徵組合

 作者的假設是：模型有了明確的查表能力後，前幾層不必再組合局部特徵，效果相當於增加深度（Sec. 6.1）。兩個工具用來檢驗這個假設。

 LogitLens 把每一層的隱藏狀態直接接到最終的 LM head，得到一個「提前輸出」的分布，再計算它與最終輸出分布的 KL 散度（衡量兩個機率分布差異的量，越小越接近）。結果：兩個 Engram 模型各層的 KL 都系統性地較小，差距在淺層最明顯（Fig. 4a），表示淺層較早完成特徵組合，較早接近最終預測。

 CKA（Centered Kernel Alignment）衡量兩組表示的相似度，值在 0 到 1 之間。作者對 Few-NERD 具名實體的最後一個 token，計算 Engram 模型第 j $j$ 層與 MoE 模型各層的 CKA，再以軟對齊指標 aj $a_j$ ​ 找出「Engram 第 j $j$ 層最像 MoE 的第幾層」。觀察到 aj>j $a_j>j$ ​>j：Engram-27B 第 5 層約對應 MoE 第 12 層（Fig. 4b–c）。也就是 Engram 的淺層表示相當於 MoE 較深層的表示。作者的結論：Engram 在功能上相當於增加有效深度。

 11 · 消融

 移除元件與關閉記憶時的變化

 元件消融（Sec. 6.2，Fig. 5）在較小的設定上進行：12 層 3B MoE（0.56B 啟用）、訓練 100B token，基準驗證損失 1.808。參考配置是 1.6B Engram、{2,3}-gram、插在第 2 與第 6 層，損失 1.768（降低 0.04）。從參考配置逐一移除元件，影響最大的三項是分支專屬融合、情境感知閘門與 tokenizer 壓縮；Fig. 5 沒有給出數值，本頁不排三者的先後。移除短卷積只稍微變差。在固定 1.6B 下加入 4-gram 稍差，作者推測它稀釋了較常見的 2/3-gram 的容量，不排除記憶更大時有益。

 敏感度分析（Sec. 6.3，Fig. 6）在推論時把 Engram 的輸出完全關掉、主幹不變，觀察各類任務還保留多少表現。事實知識類受影響最大，只保留 29%–44%（TriviaQA 29%）；閱讀理解類保留 81%–93%（C3 93%）。這表示事實知識大量依賴 Engram 查出的記憶，而閱讀理解主要依賴主幹對上下文的計算。作者提醒，這種事後消融造成訓練與推論不一致，所以只分析兩端的任務。

 12 · 預取

 確定性位址讓查表可以預取

 MoE 的路由依賴執行時的隱藏狀態，模型要算到該層才知道選哪些專家。Engram 的索引只由輸入 token ID 決定，在執行該層之前就已知道要讀哪些列（Sec. 2.5）。這種確定性位址帶來兩個系統面的好處：

 訓練：嵌入表以模型平行切分到各 GPU，前向用 All-to-All 收集被用到的列，反向把梯度分派回去；總記憶容量隨 GPU 數線性增加。

 推論：嵌入表放在主機記憶體，經 PCIe 非同步預取，與前面層的計算重疊（Fig. 2b）。插得越深，可以遮住傳輸延遲的計算時間越長。

 研究筆記整理的 PKM 等記憶層以學到的 key 比對隱藏狀態來選列，位址同樣要到執行時才知道；Engram 的位址由雜湊直接決定，所以可以預取。這是筆記的整理，論文沒有逐項比較。N-gram 的存取服從 Zipf 分布，少數模式佔大多數存取，所以常用的列可放在 HBM 或 DRAM，長尾放在 NVMe SSD（多層快取）。

 插入層的取捨：建模偏好早插入。12 層 3B MoE 上把單一模組由第 1 層掃到第 12 層，第 2 層最佳（Val Loss 1.770），越深越差；同樣 1.6B 拆成兩個模組放在第 2、6 層更好（1.768）（Sec. 6.2）。插得越早，查表結果越早進入殘差流，主幹花在重建局部模式上的層數越少；但越早的 ht $\mathbf h_t$ ​ 上下文越少、各分支差異越小，閘門越不精確。系統面則偏好晚插入，留給預取更多計算時間。Engram-27B 用第 2、15 層同時滿足兩者。

 Table 4 量測了代價（Sec. 6.4）：nano-vLLM、H800、512 條序列，把 100B 參數的 Engram 放在第二個 block、整張表放在主機 DRAM，與第一個 block 的計算重疊。4B-Dense 的吞吐量由 9,031.62 降到 8,858.28 tok/s（−1.92%，本頁推導），8B-Dense 由 6,315.52 降到 6,140.02 tok/s（−2.78%，論文寫 2.8%）。100B 表放主機記憶體，吞吐量最多只降 2.8%。每步的通訊量隨啟用的槽數增加，與表的總大小無關。這組實驗強制所有查表都走 PCIe、沒有使用快取，作者稱之為保守基準。

 14 · 研究脈絡

 研究脈絡

 論文 §7 把源頭追溯到 Shannon 的 N-gram 語言模型。之後 FastText 以子詞 N-gram 嵌入表示詞，Hash Embeddings 用多個雜湊函數降低嵌入表的大小與碰撞，這是 Eq. 1 所沿用的做法。另一條線是 MoE：稀疏閘控 MoE、Switch Transformer 與 DeepSeekMoE 讓條件計算成為大型模型的標準做法。參數式記憶（PKM、PEER）在層內放大型 key-value 儲存，以學到的 key 選列；FFN 被解讀為鍵值記憶，說明模型會用計算重建靜態知識；REALM 等檢索增強方法則使用非參數的外部記憶。N-Grammer、OverEncoding 與 SCONE 把 N-gram 嵌入擴大到語言模型，但放在輸入層，也沒有在嚴格等參數、等 FLOPs 下驗證。本文把 N-gram 查表移到中間層，並以稀疏度分配把它與 MoE 放在同一個預算下比較。每張卡片連到對應的研究筆記。
