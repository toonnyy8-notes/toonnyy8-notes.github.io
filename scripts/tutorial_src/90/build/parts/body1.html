    條件記憶：用查表補上 MoE 之外的另一條稀疏軸

    這篇論文在 Transformer 中加入以 N-gram 雜湊查表的記憶模組 Engram，並研究總參數固定時，記憶與專家該如何分配。

    MoE 與「稀疏」的定義見 01、02 節。

    Xin Cheng、Rui Tian 等（北京大學、DeepSeek-AI）〈Conditional Memory via Scalable Lookup: A New Axis of Sparsity for Large Language Models〉

    01 · 查表

    Engram 把目前 token 與前一、兩個 token 組成的片段當作鍵，直接在大型嵌入表中查出一個向量。不論表多大，每個 token 只查固定幾格。

    02 · 分配

    總參數與每個 token 的計算量都固定時，把約 20%–25% 的閒置參數從專家移到記憶，驗證集上的損失（越低越好）最小。

    03 · 規模

    27B 模型加入記憶後各類測驗都進步，一般推理題進步最多。100B 參數的表放在 CPU 記憶體，推論速度只下降不到 3%。

    01 · 計算與查表

    語言模型同時需要計算與查表

    作者把語言建模分成兩種性質不同的子任務（Sec. 1）。第一種是組合推理：依上下文把多個資訊組合起來，需要深層、動態的計算。第二種是知識檢索：文本中有相當比例是局部、靜態、刻板的片段，例如具名實體（“Alexander the Great”）與固定片語（“By the way”）。這類片段只依賴前面少數幾個 token，經典的 N-gram 模型就能以查表的方式低成本捕捉。

    問題在於標準 Transformer 沒有查表的基本運算。局部靜態模式原本可以查表解決，Transformer 卻只能用前幾層的多層注意力與 FFN 逐步「算出」它們，等於用序列深度重建一張靜態查找表。作者引用的例子是 Table 3。這張表是外部例子，轉載自 Ghandeharioun et al. (2024) 以 PatchScope 對另一個模型的分析，不是本文對 Engram 或 MoE-27B 的量測：模型讀到 “Wales” 時，第 1–2 層只把它解讀為英國的一個國家，到第 6 層才解析成完整的實體 “Diana, Princess of Wales”。Diana 這個實體要到第 6 層才解析完成，作者把它當作證據：前 5 層都花在逐步拼出一個固定的實體上，也就是把層數用來重建一張靜態查找表。作者的措辭是，這個過程「理論上可以用一次知識查找完成」（原文 “could theoretically be identified via a knowledge lookup operation”；Sec. 6.1）。

    據此，作者提出與「條件計算」互補的另一條稀疏軸：條件記憶（conditional memory）。條件記憶指依輸入內容直接查出一段儲存的參數，而不是經由多層計算重建它。本文以 Engram 模組實作條件記憶：用目前位置結尾的 2-gram、3-gram 當作鍵，在大型嵌入表中以 O(1) 查出向量，再依目前的隱藏狀態調節後加回模型（Sec. 2）。下一節先說明條件計算（MoE）如何讓參數變多而計算量不變，條件記憶沿用同一個預算框架。

    檢查理解

    作者把語言建模分成哪兩種子任務？Transformer 處理第二種有什麼問題？

    組合推理與知識檢索；局部靜態模式本可查表，但 Transformer 沒有查表運算，要用多層注意力與 FFN 重建；作者引用的外部例子 Table 3（轉載自 Ghandeharioun et al. 2024）中，Diana 實體到第 6 層才解析完成（Sec. 1、6.1）。

    02 · 參數預算

    MoE 用路由增加參數而不增加每個 token 的計算量

    MoE（Mixture-of-Experts）把 Transformer 每層的 FFN 換成多個並列的「專家」FFN。每層有一個路由器（router），依目前 token 的隱藏狀態為它打分，只選分數最高的 top-$k_{\text{act}}$ 個專家計算，其餘專家對這個 token 不做任何運算。DeepSeekMoE 另有共享專家，每個 token 都會經過。本文的 MoE-27B 有 2 個共享專家與 72 個路由專家，每個 token 選 top-6。這種依輸入選擇部分參數的做法稱為條件計算（Shazeer et al. 2017 提出稀疏閘控 MoE，見研究筆記）。

    為了比較不同架構，作者定義三種參數量（Sec. 3.1）：

    • $P_{\text{tot}}$：總可訓練參數，不含詞嵌入與 LM head。
    • $P_{\text{act}}$：每個 token 實際啟用的參數，決定每個 token 的計算量（FLOPs）。
    • $P_{\text{sparse}}=P_{\text{tot}}-P_{\text{act}}$：未啟用的參數。它增加模型容量，但不增加每個 token 的 FLOPs。

    以 Table 1 為例，MoE-27B 的總參數為 26.7B，每個 token 啟用 3.8B，大部分參數屬於 $P_{\text{sparse}}$。MoE 增加 $P_{\text{tot}}$ 而不增加 FLOPs 的方式是：未被路由器選中的專家參數不參與該 token 的計算。Engram 的方式是：嵌入表可以非常大，但每個 token 只取固定數量的槽（每個階數、每個雜湊頭各一列），所以增加槽數只增加 $P_{\text{tot}}$，不增加 $P_{\text{act}}$。兩者都把參數放進 $P_{\text{sparse}}$，差別在選擇的依據。

    $P_{\text{tot}}$、$P_{\text{act}}$、$P_{\text{sparse}}$ 各是什麼？MoE 與 Engram 如何增加 $P_{\text{tot}}$ 而不增加 FLOPs？

    03 · tokenizer 壓縮

    先把語意相同的 token 合併

    N-gram 是連續 $n$ 個 token 組成的片段；N-gram 嵌入是為每個 N-gram 配置一個可學向量，使用時依片段直接取出，屬於 O(1) 的查表，不需要經過任何矩陣乘法。Engram 在查表之前先處理 tokenizer 的一個特性：子詞 tokenizer 為了能把 ID 無損地還原成原文，常給語意相同的字串不同 ID，例如 Apple 與 ␣apple（␣ 表示前導空白）。若直接用原始 ID 組成 N-gram，同一個片語會被拆成多個互不相干的鍵。

    作者因此預先計算一個滿射 $\mathcal P:V\to V'$（Sec. 2.2）：依正規化後的文字（NFKC、轉小寫等）把語意相同的原始 ID 合併成同一個標準 ID，$x'_t=\mathcal P(x_t)$。對 128k 的 tokenizer，有效詞表縮小 23%（App. C 的 Table 6 寫 23.43%）。官方示範程式的正規化順序是 NFKC → NFD → 去除重音 → 小寫 → 連續空白改為單一空格 → 去頭尾空白；去頭尾空白使 ␣apple 與 apple 合併。

    壓縮後，位置 $t$ 結尾的後綴 $n$-gram 寫成 $g_{t,n}=(x'_{t-n+1},\dots,x'_t)$。Engram-27B 的最大階數 $N=3$，所以每個位置使用 $g_{t,2}$ 與 $g_{t,3}$ 兩個鍵。序列開頭不足 $n$ 個 token 時，示範程式以 pad ID 補齊。不同的 $n$-gram 有 $|V'|^n$ 種可能，無法逐一配置參數，所以下一步用雜湊把它們映到大小固定的表中。
