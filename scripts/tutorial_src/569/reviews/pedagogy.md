# 569 design.md 審查（教學法 + 建置就緒）

1. **P0 / C1 輸入**「滑桿 τ∈[0.01,0.999]…chip τ=1…滑桿停在右端並標「1」」。滑桿最大 0.999，無法表示 1；C3 滑桿 [0.5,0.99] 同問題。問題：狀態與滑桿值不一致，讀數、曲線、aria-valuetext 會互相矛盾。修正：狀態另設 `tauIsOne` 旗標（拖動滑桿即清除），讀數與 aria-valuetext 顯示「τ = 1（取最大值）」，滑桿停在右端但不寫回 τ 值；C2、C3、C4 同規則。

2. **P0 / 4.0 expectile 演算法**「取第一個滿足 x_{k-1}≤m+1e-12 且 x_k≥m−1e-12 的 k」。S^{hi}、S^{lo} 與 k 的邊界（k=0、k=n）未定義；浮點誤差可能找不到任何 k，只規定空支撐回 NaN。問題：前端無法只靠規格實作，極端 τ 或重複值時可能靜默回 NaN。修正：寫明 S^{lo}=前 k 項和、S^{hi}=其餘項和、k 從 0 到 n，並加退路（找不到時取一階條件殘差最小的 k，或對 m 二分法），selfTest 加重複 Q 值與 τ=0.999 的案例。

3. **P1 / C3 表格版 IQL**「資料中沒出現的狀態：不計算」。轉移到無外出資料的狀態 s'（例如軌跡在第 100 步截斷後的最後狀態、seed 2 的 (6,1)）時，V(s') 未定義，會產生 NaN。修正：規定 V(s')=0，或把這類 (s,a) 排除，並寫入 maze.py 比對。

4. **P1 / C3 控制項**。同時有 τ 滑桿、5 個 chip、σ 分段、模式分段、箭頭勾選、三種顯示切換、重新產生資料，共 7 組，加上熱圖、折線、5 項讀數；σ 與「母體」都是論文沒有的概念，在元件內才第一次出現。問題：初學者在同一個元件同時遇到 τ、近似誤差、資料有限/母體；難度跳躍。修正：預設只顯示 τ 與 σ，其餘收進「進階」`<details>`；S6 正文在元件前先各用一句話定義 σ 與「母體」，並在元件旁放三步引導（先看 τ=0.5、再 0.95、再切換母體）。

5. **P1 / C3「重新產生資料（seed + 1）」**。沒有回到 seed 1 的方法，而 LO8 的 0.0007／0.8136／1.1186 只在 seed 1 成立。另外「換 seed 結論不變」只驗證 seed 2、3 的 τ=0.95 一個數字。修正：加「回到 seed 1」按鈕並顯示目前 seed；`maze.py` 補 seed 2–5 的 τ=0.5／0.9 的 V^π 表，頁面才可宣稱結論不變。

6. **P1 / 符號先用後教**。C1 使用 μ（資料比例），符號表與 S1–S4 沒有 μ，S5 才說 μ=π_β；C2 稱「正確值 max(5,10p)」，但「資料支撐內最大值」是 S5 Theorem 3 才定義的。V_τ、Q_τ、Q^{π_β}、Q^*、𝒜_β 也不在符號表。修正：S3 介紹 μ 為「資料中該動作的比例」，符號表補 μ、Q^{π_β}、Q^*、V_τ；C2 的「正確值」改稱「資料內最好動作的期望值」並加「Theorem 3，第 05 章」前向註記。

7. **P1 / S1 長度 450–550 字**要塞進 MDP、π、Q、V、TD、target network、Eq. 1、分布偏移、LO1，另有符號表。目標讀者懂機率與神經網路但不一定懂 RL。問題：過密，「2–3 句白話」不足以教 TD 目標與 target network，且 S1、S2 全是文字，第一個元件到 S3 才出現。修正：S1 放寬到 700 字或拆成 1a/1b；加一個靜態小圖（max 取到被高估動作的數值例）支援 LO1；TD 與 target network 各給一個一行數值例。

8. **P1 / S8 clipped double Q**。LO10 要求說出它用在哪，但 Alg. 1 與符號表只有一個 Q_θ，正文只有一句。問題：初學者沒有「兩個 Q 網路取 min」的概念，答案無法由正文教會。修正：S8 加一段說明兩個 Q 網路、為何取 min（抑制高估，連回 S1），Alg. 1 註明「V 與 π 的更新用 min(Q¹,Q²)」。

9. **P1 / S4 標題與 C2 名稱**「避免把幸運的轉移當成好動作」「幸運樣本」，以及錯誤清單「τ 越大越好？」。「幸運」是比喻，問句式標題違反字面風格。修正：「另外學一個 V，避免把偶然轉移到高回報狀態的樣本當成動作的價值」；C2 名稱改「單一損失與 Eq. 5–6 的差別」；「τ 越大越好？」改成「τ 越大不一定越好」。其他如「挑中被高估的值」「被雜訊主導」建議改成「取最大值時多半落在高估的值上」「σ 大於動作差距時，貪婪動作由 σ 決定」。

10. **P1 / 390px 公式**。只處理了 Eq. 4。Eq. 1、5、7 與 \tag 在 358px 寬下會溢出；段落中的行內長式同理。修正：統一 `.katex-display{overflow-x:auto}`，加 `tabindex=0` 與 aria-label 供鍵盤捲動；Eq. 1、7 在 <600px 拆成兩行（aligned）。

11. **P1 / C1 圖 3 與 log 取樣**。τ∈[0.01,0.999] 以 1−τ 對數均分，但橫軸說「0.5 標 SARSA、右端 →1」，軸範圍、刻度與刻度尺度（線性或 −log(1−τ)）未定。問題：開發者必須自行猜；若採 log(1−τ) 軸，0.5 位置被擠。修正：規定橫軸為 x=−log10(1−τ)（0.3…3），刻度 0.5／0.9／0.99／0.999，曲線只畫 τ≥0.5。

12. **P1 / C4 下圖**。策略密度 N(ā,s²) 與行為密度（s 從 0.23 到 0.052）疊在長條上，未規定 y 軸縮放；β=30 不截斷時峰值約為行為密度的 4 倍。修正：兩條密度共用一個 y 軸，上限=max(兩者峰值)×1.1，並標示「密度」單位；長條各自正規化的說明放圖旁。

13. **P2 / C1 上圖**。縱軸為 Q 值、長條長度=μ；Q 值相同的動作（滑桿調整後常見）會重疊，「對所有動作取 max」寫死為 12，但 Q 輸入範圍到 15，會畫錯。修正：max 以 a₆ 與其他 Q 的實際最大值計算；重疊時標籤垂直錯開。

14. **P2 / 無障礙與 SVG 文字**。熱圖 36 格只有數字沒有規定 `role`／sr-only 摘要；Unicode 沒有 τ 的下標，「m_τ」「V = m_τ」在 SVG 內需 `<tspan baseline-shift>`；Alg. 1 的 θ̂ 在 JetBrains Mono 為組合字元，欄寬會錯位；`color-mix(in oklab)` 無退路。修正：熱圖 `role="img"` + 完整 sr-only 表；θ̂ 改用 \hat 的 KaTeX 或「θ_target」；color-mix 前加純色 fallback。
