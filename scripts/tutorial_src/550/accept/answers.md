# 驗收答案（Goldfish）

**LO1**
- 答：作者假設人類定義的推理模式可能限制探索，不受限的 RL 較能激發新的推理能力；人類回應也常省略反思與驗證步驟，所以 R1-Zero 直接從 V3-Base 做 RL、不先做 SFT。獎勵只根據最終答案是否正確（以及輸出格式），不對推理過程加限制。
- 段落：「獎勵只根據最終答案是否正確（以及輸出格式）」
- 信心：high

**LO2**
- 答：GRPO 不訓練價值模型，改用同一題 $G$ 個輸出的獎勵平均與標準差算優勢，$A_i=\frac{r_i-\mathrm{mean}}{\mathrm{std}}$（Eq. 3）。要取代的原因有兩個：價值模型與策略模型大小相近、成本高；只有最終結果獎勵時，從部分輸出預測最終獎勵很困難，長 CoT 中前文可能被後文推翻。
- 段落：「GRPO 用同一題 G 個輸出（含自己）的獎勵平均與標準差」
- 信心：high

**LO3**
- 答：$G=16$、4 個正確：mean = 0.25，std = $\sqrt{0.25\times0.75}\approx0.4330$。正確輸出 $A^+=\sqrt{(G-k)/k}=\sqrt3\approx1.732$；錯誤輸出 $A^-=-1/\sqrt3\approx-0.577$（以上為頁面「本頁推導」）。16 個全對（或全錯）時 std = 0，Eq. 3 分母為 0；頁面採用的處理是把這組優勢全部設為 0（論文未說明），此時只剩 $\beta>0$ 的 KL 項提供小梯度。
- 段落：「把這組的優勢全部設為 0」
- 信心：high

**LO4**
- 答：clip 讓梯度為 0 的情況：$A>0$ 且 $\rho>1+\varepsilon$（目標停在 $(1+\varepsilon)A$），或 $A<0$ 且 $\rho<1-\varepsilon$（目標停在 $(1-\varepsilon)A$）。意思是機率已朝有利方向移動超過 $\varepsilon$ 後，同一批資料不再推動它。R1 第一階段 RL 的 $\varepsilon=10$（Sec. 3.2.1）。作者說明：較小的值會截斷大量 token 的梯度、降低效能；較大的值可能使訓練不穩。
- 段落：「較小的值會截斷大量 token 的梯度」
- 信心：high

**LO5**
- 答：Eq. 2 的估計量為 $x-\log x-1$，$x=\pi_{ref}/\pi_\theta$。頁面（本頁推導）指出它對所有 $x>0$ 都 $\ge0$，只在 $x=1$ 為 0；論文稱它是 KL 散度的不偏估計量，但頁面強調這只保證 KL 的值，不保證梯度不偏。放置位置：GRPO 把 KL 估計量直接加在損失中；PPO 把每個 token 的 KL 懲罰加在獎勵中，頁面說這可能隱含懲罰回應長度。參考模型每 400 步換成最新的策略；$\beta=0.001$。
- 段落：「訓練中每 400 步把參考模型換成最新的策略」
- 信心：high

**LO6**
- 答：R1-Zero 的獎勵為 $Reward_{rule}=Reward_{acc}+Reward_{format}$（Eq. 4），兩項等權相加。準確度獎勵：數學答案以規則比對（最終答案放在指定格式，如方框），程式以編譯器執行測試案例；格式獎勵：推理過程放在 <think> 與 </think> 之間得 1。不用神經獎勵模型的理由：頁面說神經獎勵模型（結果式或過程式）在大規模 RL 中容易被 reward hacking，重新訓練又耗資源、使流程複雜。
- 段落：「重新訓練又耗資源、使流程複雜」
- 信心：high

**LO7**
- 答：每步 32 題、每題 16 個輸出（batch 512）。最大長度在第 8.2k 步之前為 32,768 tokens，之後調為 65,536；調高的那一刻，效能與回應長度都明顯跳升。AIME 2024 的 pass@1 由 15.6% 升到 77.9%，自洽解碼 cons@16 為 86.7%，頁面說超過人類參賽者的平均。
- 段落：「AIME 2024 的 pass@1 由 15.6% 升到 77.9%」
- 信心：high

**LO8**
- 答：回應長度在訓練中持續增加（Fig. 1b），作者稱為「思考時間」增加，來自模型本身的適應。十個反思詞（如 wait、mistake、however）的出現次數比訓練開始時增加 5–7 倍，但這是次數而非比率，回應變長本身也會使次數增加。"wait" 在訓練早期幾乎沒有，第 4000–7000 步偶爾出現，第 8000 步後大幅增加。
- 段落：「第 8000 步後大幅增加」
- 信心：high

**LO9**
1. 冷啟動 SFT：起點 DeepSeek-V3-Base，數千筆長 CoT 冷啟動資料，產出 Dev1。
2. 第一階段 RL：起點 Dev1，推理題，規則式準確度 + 格式 + 語言一致性獎勵（Eq. 7），產出 Dev2。
3. 拒絕取樣 + 第二次 SFT：起點 V3-Base，約 60 萬筆推理 + 約 20 萬筆非推理資料，產出 Dev3。
4. 第二階段 RL：起點 Dev3，推理題用規則獎勵；通用題用獎勵模型 + 格式；加語言獎勵，產出 R1（溫度 0.7，1,700 步，偏好獎勵只在最後 400 步加入）。
- 補充：Dev1 與 Dev3 都從 V3-Base 出發，不是繼續訓練前一個檢查點。
- 段落：「通用題用獎勵模型 + 格式；加語言獎勵」
- 信心：high

**LO10**
- 答：R1-Zero 到 Dev1：指令遵循與偏好評測上升（IF-Eval 46.6 → 71.7），推理下降（AIME 2024 77.9 → 59.0），作者歸因於冷啟動資料量小。最後一個 RL 階段（Dev3 → R1）主要提升通用指令與偏好：AlpacaEval 2.0 上升 +25.5（62.1 → 87.6），ArenaHard 上升 +16.7（75.6 → 92.3）；程式與數學只小幅提升。
- 段落：「IF-Eval 46.6 → 71.7」
- 信心：high

**LO11**
- 答：$\text{pass@1}=\frac1k\sum_{i=1}^k p_i$，$p_i$ 表示第 $i$ 個回應是否正確。取樣溫度 0.6、top-p 0.95；AIME 與 GPQA 用 $k=64$，MATH 與 Codeforces 用 16，LiveCodeBench 用 8。改用取樣是因為 greedy decoding 在長輸出上重複率高。AIME 2024：R1 的 pass@1 為 79.8%，OpenAI-o1-1217 為 79.2%。
- 段落：「R1 的 pass@1 為 79.8%」
- 信心：high

**LO12**
- 答：Distill-Qwen-32B 的 AIME 2024 pass@1 為 72.6%，Qwen2.5-32B-Zero（直接 RL）為 47.0%。作者的結論：把強模型蒸餾到小模型效果很好；小模型靠大規模 RL 需要大量運算，而且可能不及蒸餾；要超越人類智慧的邊界，可能仍需要更強的 base model 與更大規模的 RL。早期實驗：7B dense 與 16B MoE 做純 RL 在 AIME 上沒有有意義的提升，回應變長時傾向重複；改用 32B dense、230B MoE、671B MoE 後才看到大幅提升，因此作者認為 RL 效果高度依賴模型容量。
- 段落：「蒸餾經濟有效，但要超越人類智慧的邊界」
- 信心：high

## 讀者可能卡住的地方

1. Eq. 1 的 $\rho_i$ 是整段輸出的機率比，但 ε 段落談的是 token 層級的梯度截斷；頁面說實作細節未說明，讀者不知道實際在哪一層計算。
2. 全對或全錯群組「優勢設為 0」是頁面採用的處理，不是論文規定；標準差除以 G 或 G−1 的差別只是整體縮放，讀者容易以為方向會改變。
3. 數學式排版載入失敗（頁面開頭已註明），公式以原始 TeX 呈現；$x=\pi_{ref}/\pi_\theta$ 的方向、"rollout"、"off-policy" 等詞只有一句帶過，不易對照。
4. C4 的「下降前 3」列出 Codeforces Rating 1746 → 2029，但這是上升，標示與數字矛盾（Table 3 的數字本身是 1746 → 2029）。
5. 86.7% 在頁面出現三次，指標各不相同（R1-Zero 的 cons@16、R1 的 64 樣本多數決、Distill-Llama-70B 的 cons@64），加上 pass@1、pass@64 等數字並列，讀者容易混淆。
