 DeepSeek-R1：以強化學習訓練推理能力

 這篇論文不先讓模型模仿人寫的推理，直接依答案對錯與格式給獎勵來訓練，再用四個階段補上可讀性，最後用它的輸出教小模型。

 DeepSeek-AI（2025；v2 2026）〈DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning〉

 01 · 不先模仿DeepSeek-R1-Zero 沒有先模仿人寫的解題過程，只依答案對錯與格式給獎勵，在 AIME 2024（美國數學邀請賽的題目）上的正確率由 15.6% 升到 77.9%。

 01 · 動機

 推理能力過去依賴人工標註的思維鏈

 大型語言模型（large language model, LLM）讀入一段文字，逐個 token（字或字的片段）產生回應。要讓它解數學題或寫程式，常見的做法有兩種：一是思維鏈（chain-of-thought, CoT）提示，在提示中示範或要求「一步一步想」，讓模型先寫出中間步驟；二是在後訓練（post-training）階段，讓模型模仿人工標註的高品質多步推理軌跡（Sec. 1）。

 作者指出這兩種做法的限制：它們依賴人工標註，難以擴展，也會帶入標註者的認知偏誤；模型被要求複製人類的思考過程，表現上限受人類範例限制，無法探索「更好、非人類式」的推理路徑（Sec. 1）。傳統後訓練是先做監督式微調（supervised fine-tuning, SFT：以交叉熵損失模仿標註好的回應），再做強化學習（reinforcement learning, RL）（App. A.2）。作者主張 SFT 這一步可能妨礙模型探索，因為人類寫的回應常省略明確的反思與驗證步驟（App. A.2）。

 R1-Zero 為什麼不先做 SFT。作者的假設是：人類定義的推理模式可能限制模型的探索，不受限的 RL 較能激發新的推理能力；人類回應也常省略反思與驗證步驟。因此 DeepSeek-R1-Zero 從 DeepSeek-V3-Base 直接做 RL，獎勵只根據最終答案是否正確（以及輸出格式），不對推理過程本身加任何限制（Sec. 1、App. A.2）。

 為了用 RL 描述這件事，本頁把 LLM 看成一個策略（policy）πθ $\pi_\theta$ ​：給定問題 q $q$ ，它產生完整輸出 o $o$ （思考過程加答案）的機率記為 πθ(o∣q) $\pi_\theta(o\mid q)$ ​(o∣q)，θ $\theta$ 是模型參數。這個機率等於各 token 條件機率的乘積本頁推導（機率連鎖律）。RL 只需要對整段輸出打一個分數，不需要每一步的標註，這是能跳過人工推理軌跡的前提。

 R1-Zero 使用的提示模板只規定格式（Table 1）：先在 <think> 與 </think> 之間寫推理過程，再在 <answer> 與 </answer> 之間寫答案。作者刻意只限制結構、不限制內容，以觀察 RL 過程中模型行為的變化（Sec. 2.3）。

 02 · 強化學習

 強化學習把答案對錯變成訓練訊號

 RL 的基本循環是：用目前的策略對一批問題產生輸出（這一步稱為 rollout，即用目前策略實際生成一批輸出），替每個輸出算一個獎勵（reward，例如答對得 1、答錯得 0），再更新參數，提高高獎勵輸出的機率、降低低獎勵輸出的機率。這類「沿著提高期望獎勵的方向調整輸出機率」的方法稱為策略梯度（policy gradient）。

 只看獎勵本身會有一個問題：如果一題很簡單，大部分輸出都拿到 1，每個輸出都會被加強，訊號無法區分好壞。因此實務上比較的是優勢（advantage）：該輸出的獎勵減去一個基準線（baseline，即「這題的預期獎勵」）。優勢為正的輸出被加強，為負的被削弱。

 LLM 常用的 RL 演算法是 PPO（Proximal Policy Optimization, Schulman et al. 2017）。PPO 以廣義優勢估計（Generalized Advantage Estimation, GAE）計算優勢，基準線由另外訓練的價值模型（value model）提供：價值模型讀入「到目前為止已產生的部分輸出」，預測最後會拿到多少獎勵（App. A.3）。

 作者列出價值模型的兩個成本（App. A.3）。第一，價值模型的大小通常與策略模型相近，帶來大量記憶體與運算負擔。第二，只有最終結果獎勵時，從部分輸出預測最終獎勵本身就很困難；長 CoT 中，前面寫的內容可能被後面的反思推翻，更難預測。此外，PPO 把每個 token 的 KL 懲罰（下一章說明）加進獎勵中。

 Fig. 4 在 DeepSeek-Coder-V2-Lite（16B MoE，2.4B 啟用參數）上比較 PPO 與 GRPO（下一章的方法）解 MATH 題：GAE 的係數 λ=0.95 $\lambda=0.95$ （多數開源實作的預設值）時 PPO 明顯較差；調到 λ=1.0 $\lambda=1.0$ 後接近 GRPO。作者的結論是 PPO 需要額外調參，在資源有限時 GRPO 較實際（App. A.3）。

 06 · R1-Zero

 純 RL 讓回應變長，並出現 wait 等詞

 先定義本章用到的評測名詞。AIME 是美國數學邀請賽（American Invitational Mathematics Examination），每題答案是一個整數。pass@1 是每題取樣多次、計算平均正確率（第 08 章詳述）；cons@16 是每題取樣 16 次、以多數決的答案計算正確率。GPQA Diamond 是研究所程度的物理、化學、生物多選題（App. D.1）。

 R1-Zero 的訓練設定與結果。R1-Zero 每個訓練步取 32 題、每題 16 個輸出，batch 為 512；學習率 3e-6、KL 係數 0.001、取樣溫度 1，共訓練 10,400 步（1.6 個 epoch），每 400 步更新參考模型（Sec. 2.1）。輸出最大長度在第 8.2k 步之前是 32,768 tokens，之後調為 65,536；調高的那一刻，效能與回應長度都明顯跳升（Sec. 2.1）。AIME 2024 的 pass@1 由 15.6% 升到 77.9%，自洽解碼達 86.7%（R1-Zero，cons@16 自洽解碼），超過人類參賽者的平均（Sec. 2.3、Fig. 1a）。R1-Zero 在 GPQA Diamond 的 pass@1 為 75.8（Table 3）。

 訓練中出現的推理行為。R1-Zero 在訓練集上的平均回應長度隨訓練持續增加（Fig. 1b），作者稱之為「思考時間」（thinking time）增加，來自模型本身的適應而非外部修改（Sec. 2.3）。作者另外統計十個反思詞（作者稱；wait、mistake、however、but、retry、error、verify、wrong、evaluate、check，由 3 位人類專家選出）：它們的出現次數比訓練開始時增加 5–7 倍（App. C.2、Fig. 9a）。這是次數，不是比率；回應變長本身也會使次數增加。"wait" 一詞在訓練早期幾乎沒有，第 4000–7000 步偶爾出現，第 8000 步後大幅增加（App. C.2、Fig. 9b）。作者稱之為 aha moment：一個中間版本在解題中寫出「Wait, wait. Wait. That's an aha moment I can flag here.」（等等。這是我可以標記的頓悟時刻。）然後重新逐步檢查（Table 2）。

 依 MATH 難度分層（App. C.1、Fig. 8）：等級 1–3 很快達到 0.90–0.95；等級 4 由約 0.78 升到 0.95；等級 5 由約 0.55 升到 0.90。等級 1 在 500 題中只有 43 題，95–97% 的正確率只代表 1–2 題未解。

 R1-Zero 也有問題：輸出可讀性差，同一段 CoT 會中英混雜；規則式 RL 只針對推理任務，寫作與開放問答的能力有限（Sec. 1、Sec. 3）。作者推測語言混雜與 base model 的訓練資料主要是中英文有關（App. A.1）。

 長度上限為什麼重要：超過上限的輸出被截斷，沒有答案，準確度獎勵是 0。上限因此壓住了「能被強化的長度」；調高上限後，原本會被截斷、但能答對的長輸出開始拿到正的優勢。下面的玩具只示範這個機制。

 09 · 蒸餾

 蒸餾比直接對小模型做 RL 更有效

 蒸餾（distillation）在這裡是指：用大模型的輸出當 SFT 資料訓練小模型。作者以第 07 章的 80 萬筆樣本對 Qwen2.5 與 Llama 做 SFT，不加 RL 階段（App. F）；訓練 2–3 個 epoch，cosine 學習率降到初始值的 1/10，最大長度 32,768，batch 64（App. B.4.3）。

 Table 15 中，AIME 2024 的 pass@1：Distill-Qwen-1.5B 28.9、7B 55.5、14B 69.7、32B 72.6，Distill-Llama-8B 50.4、70B 70.0；GPT-4o-0513 為 9.3，Claude-3.5-Sonnet-1022 為 16.0。1.5B 模型只在數學評測勝過 GPT-4o（MATH-500 83.9 對 74.6），GPQA Diamond（33.8 對 49.9）與 LiveCodeBench（16.9 對 32.9）仍較低。學生模型越大，表現越好。

 蒸餾與小模型直接 RL 的比較。作者對 Qwen2.5-32B-Base 以數學、程式、STEM 資料做超過 10K 步的 RL，得到 Qwen2.5-32B-Zero（學習率 2e-6，其餘同 R1 第一階段 RL 設定，最大長度固定 32,768；App. B.4.1）。它的 AIME 2024 pass@1 為 47.0，而 Distill-Qwen-32B 為 72.6，也就是 72.6 對 47.0（Table 16）。作者由此得到兩個結論：把強模型蒸餾到小模型效果很好，小模型靠大規模 RL 需要大量運算，而且可能不及蒸餾；蒸餾經濟有效，但要超越人類智慧的邊界，可能仍需要更強的 base model 與更大規模的 RL（App. F.1）。作者在開發初期也試過以 7B dense 與 16B MoE 的模型做純 RL，在 AIME 上沒有有意義的提升，回應變長時傾向重複；改用 32B dense、230B MoE、671B MoE 後才看到大幅提升。作者因此認為 RL 從 base 出發的效果高度依賴模型容量（App. G.1）。

 10 · 失敗與發現

 失敗嘗試與關鍵發現

 驗證器（App. G.1）。R1-Zero 的效果高度依賴獎勵訊號是否可靠。作者目前的經驗是，規則式獎勵與「以 LLM 對照標準答案判斷對錯」兩種方式能減輕 reward hacking；後者適合答案簡短明確的任務，不容易推廣到開放生成與長文寫作。

 迭代流程（App. G.1）。RL 讓模型探索人工標註達不到的推理軌跡；SFT 處理難以定義可靠獎勵的任務，例如開放問答與創意寫作。只用 RL 會在定義不良的任務上 reward hacking，只用 SFT 則無法透過探索最佳化推理，所以作者認為兩者都不可缺少。

 過程獎勵模型（process reward model, PRM）的三個限制（App. G.2）。PRM 對推理的每一步打分。作者列出：一般推理中難以明確定義「一步」；難以判斷中間步驟是否正確，自動標註效果不佳、人工標註又難以擴展；一旦引入模型式 PRM，必然導致 reward hacking，重新訓練又增加資源與流程複雜度。PRM 在重排前 N 個回應或引導搜尋上有用，但相對於大規模 RL 的額外成本，優勢有限。

 蒙地卡羅樹搜尋（MCTS）的兩個挑戰（App. G.2）。作者仿照 AlphaGo 與 AlphaZero，把答案拆成小段做樹搜尋，並以預訓練的價值模型引導。但 token 生成的搜尋空間比西洋棋大上指數倍，限制每個節點的最大擴展數又可能陷入局部最佳；價值模型直接影響每一步搜尋的品質，而細粒度的價值模型很難訓練，無法像 AlphaGo 那樣逐步自我改進。作者的結論是，MCTS 搭配預訓練價值模型可以改善推論，但以自我搜尋反覆提升模型仍很困難。

 reward hacking 實例（App. B.5、Fig. 6）。以有用性獎勵模型訓練時，獎勵分數持續上升，但 CodeForces 的 test pass@1 下降。這是第二階段 RL 只在最後 400 步加入偏好獎勵的原因。

 常見錯誤

 以為 R1 完全沒有 SFT：只有 R1-Zero 沒有 SFT；R1 有冷啟動 SFT 與 80 萬筆的第二次 SFT（Sec. 3、App. B.4.2）。

 以為 Dev3 由 Dev2 繼續微調：第二次 SFT 微調的是 DeepSeek-V3-Base，Dev2 只用來拒絕取樣產生資料（App. B.4.2、B.3.3）。

 全對或全錯的群組照算 Eq. 3：std = 0，需要保護；這些題目沒有獎勵訊號，只剩 β > 0 時的 KL 梯度本頁推導。

 期待格式獎勵在所有輸出都合規時仍有作用：常數獎勵不改變優勢本頁推導。

 沿用 PPO 原論文常用的 ε = 0.2（本文未使用此值）：R1 第一階段 RL 用 ε = 10，此時負優勢一側的裁剪不會啟動。

 把 KL 懲罰加在每個 token 的獎勵中（PPO 做法）：GRPO 加在損失中；前者可能隱含懲罰長度（App. A.3）。

 以 greedy decoding 評測長推理模型：論文改用溫度 0.6、top-p 0.95 的 pass@1（App. D.1）。

 在小模型上直接複製純 RL：7B dense、16B MoE 沒有成功（App. G.1）；小模型用蒸餾較好（App. F.1）。

 在偏好獎勵上訓練太久：第二階段 RL 只在最後 400 步加偏好獎勵，更多步會 reward hacking（Sec. 3.2.2、App. B.5）。

 用 few-shot 提示評測或使用 R1：few-shot 一致降低表現，建議 zero-shot 直接描述問題與輸出格式（Sec. 6、App. D.1）。

 12 · 安全與限制

 安全評估與限制

 安全（App. D.3）。官方服務另有風險控制系統：使用者問題先比對關鍵字，命中者連同 Listing 8 的審查提示送給 DeepSeek-V3 判斷是否撤回回應。Table 9 六個公開安全基準的平均分數，R1 為 95.0，括號內的模型本身分數為 85.9。Table 11 的越獄攻擊中，R1（無風控）的不安全比例由 25.2% 升到 85.9%；加上風控後不安全比例為 4.3%，拒答比例 87.3%。50 種語言的安全分數，R1 加風控為 85.9%、模型本身為 74.2%（D.3.4）。85.9 在這三處分別是不同的指標。作者建議部署開源模型的開發者採用類似的風控（D.3.5）。

 能力限制（Sec. 6）。結構化輸出與工具使用較弱；簡單問題仍有過度思考，token 效率有改進空間；針對中英文最佳化，其他語言的問題可能以英文推理或回答；對提示敏感，few-shot 會降低表現；軟體工程任務評估時間長，沒有大規模 RL，相對 DeepSeek-V3 提升有限。

 方法限制（Sec. 6）。純 RL 依賴可靠的獎勵訊號；寫作等任務難以建構可靠的獎勵模型，以模型打分時容易被利用。對無法可靠評估的複雜任務，擴展純 RL 仍是開放問題。
