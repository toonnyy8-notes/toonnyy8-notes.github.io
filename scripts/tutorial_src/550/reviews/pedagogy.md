Review of design.md (No. 550). I found no P0 items, meaning nothing blocks the build outright. Items are ordered by severity.

1. P1 — C1 (S3), "滑桿 f（格式合規率）… r_i=acc_i+fmt_i（Eq. 4）". C1 uses the format reward and Eq. 4 in S3, but S5 is where Eq. 4 and the format reward are taught. The format slider and the "常數獎勵不改變優勢" point therefore come before their concept. Fix: either move the f slider and the constant-shift material to S5 (or a second mini-widget there), or add one S3 prose paragraph defining "準確度獎勵 + 格式獎勵" before C1. LO6 teaches Eq. 4 only in S5.

2. P1 — C4 (S7) and the flow bar. The bar is linear (R1-Zero → Dev1 → Dev2 → Dev3 → R1), and Δ = v_s − v_{s-1} is computed for consecutive nodes. Dev1 does not derive from R1-Zero. Dev3 does not derive from Dev2, because it starts from V3-Base (the design's own 常見錯誤 #2). The "上升/下降前 3" for Dev1 and Dev3 therefore compares models that are not a before-and-after pair. Fix: label those two cards "與前一節點比較（非同一條訓練線）", draw Dev3 as branching from V3-Base, and fix the order of the fields in the card.

3. P1 — S4 is too dense (450–550 字). It packs Eq. 1, Eq. 2, clip, ε, unbiasedness, the KL position difference, reference updates, rollout/mini-batch and ρ=1, and it carries LO4 and LO5. The body never says why ρ exists (sampling from π_old, then updating more than once). It also never explains "不偏" or the expectation notation E_{q~P(Q),…}. Fix: split S4 into S4a (ρ, clip, ε) and S4b (KL, reference model, rollout), and add two sentences on the purpose of the ratio and a plain-language reading of the E notation.

4. P1 — S2 never defines "優勢 / baseline". The S2 outline covers reward, policy-gradient intuition, PPO, value model and GAE. Eq. 3 in S3 uses advantage without defining it, and LO2 asks "GRPO 取代價值模型" without saying what the value model is for. Fix: add a sentence in S2 such as "優勢 = 此輸出的獎勵 − 預期獎勵（基準線）；價值模型負責估計基準線".

5. P1 — Terms used before they are taught. Examples: hero subtitle "GRPO／蒸餾／規則式獎勵"; S6 and the hero use pass@1, cons@16 and AIME, which S8 defines; and S5/S2 use "reward hacking", "rollout", "拒絕取樣". The symbol table is collapsed in S1, so readers will not see it. Fix: first-use one-line definitions in prose, with pass@1 and AIME defined in S6 itself.

6. P1 — C3 (S6) "較長的推理正確率較高". The toy hard-codes the conclusion that longer reasoning gets more correct answers, so "回應變長" is an input, not something the widget shows. A reader could take it as evidence for the paper's claim. The design also says the S=1000 result (no recovery) runs opposite to the paper. The policy-gradient formula g_j, the softmax over logits and the lognormal length model are also not taught in S2. Fix: state the assumption in the first line of the plate ("本頁假設長推導正確率較高；此圖只示範 Eq. 1–3 的機制"). Cut the description of the toy's internals from the body, and tie the widget to LO7/LO8 only through the cap-truncation point.

7. P1 — C2 y-ranges are unspecified. With A=2 and ε=10, ρA reaches about 40 while the KL term is about 0.002, so the −βD curve is invisible. dJ/dx therefore spans a huge range. Fix: fix the y-axis to [−4, 4] and clamp or arrow-mark values outside it. Also give the log10 ε slider and the chips a defined sync rule (the chip value is shown on the slider, and the slider snaps to chip values within a tolerance). Also write one sentence on what "對 x 的梯度" means, since x=log ρ is new to beginners.

8. P1 — 390px layout of C1 and C3. With G up to 64 there would be 64 buttons of ≥44px and 64 bars, which cannot fit in 390px; these two requirements conflict. Fix: put the cards in a wrapping grid (8 per row) with scrollable bars, or show a compact dot strip for G>16 and keep the cards for G≤16. Specify that C3's two charts stack at <600px.

9. P1 — C1 manual mode has no state spec. It does not say whether a manual toggle affects acc only or also fmt, what happens when G, p or f change afterwards (reset or keep), or how "重新抽樣" interacts with manual mode. Fix: say that the first slider move after a manual edit discards the edits and shows a "回到抽樣模式" button.

10. P1 — Eq. 1 split and equation tags. §6.3 says "公式右側以等寬字標論文編號" and "Eq. 1 在 <600px 拆兩行", but the formulas use `\tag{Eq. 1}`, which KaTeX renders in math font and parentheses. CSS cannot break a KaTeX line. Fix: write two versions of Eq. 1 (one `aligned` version, shown at <600px) and drop `\tag` in favour of a mono label outside the equation. Add a KaTeX CDN failure fallback (a `<noscript>` or an onerror message), because otherwise raw `$$` text shows.

11. P1 — Live-region flooding. "所有讀數區 aria-live=polite" gives about 6 live regions in C1 and C2, and keyboard arrows on a 0.01-step slider (600 positions) trigger updates. Fix: one shared debounced live region per component (as announce() already does) carrying a single summary sentence, with PageUp/PageDown steps of 0.1 on x.

12. P2 — C3 runtime. The spec requires "< 16 ms per segment" but estimates "< 30 ms" in total. `requestIdleCallback` has no `timeout`, so it may never run on a busy page, and re-clicking during computation or animation is undefined. Fix: `requestIdleCallback(fn,{timeout:200})`, and a run-token that cancels the previous run on a new click. Cross-engine differences in `Math.log/cos/exp` can change trajectories, so selfTest tolerances such as ±0.01 may fail in some browsers. Set looser tolerances (about ±0.03), or run the selfTest only in Chromium.

13. P2 — C4 labels, ties and semantics. Slope-chart end labels for up to 20 selected metrics will collide at 390px; there is no collision-avoidance rule. Fix: limit the selection to 8, or add a minimum 14px y-gap with leader lines. Compute Δ in integer tenths to avoid float tie-sorting errors. The five stage buttons should be `role="radiogroup"` with arrow-key navigation.

14. P2 — Dark mode and glyph coverage. `--c-3` and `--c-4` are checked only against `--surface`; there are no dark values. The hatch and pattern fills are undefined for dark mode. Glyphs such as π₄, A⁺, A⁻ and ₄ may fall back in IBM Plex and Noto Sans TC. Fix: define dark values for each token, define the patterns with `currentColor` or CSS variables, and write "π4" and "A+" in plain text if fallback glyphs look wrong. The P0(p) value-less readout "< 1e-300" is unreachable (the minimum is about 1e-19), so drop it and use a log-scale y-axis in the small chart so small values stay visible.

15. P2 — Wording and objectives. "反思／思考時間／自我演化／探索" personify the model. Where the author's term must stay, mark it "作者稱"; in the S6 title, replace "出現反思" with "出現 'wait' 等詞". Several LO answers are split across two sections (LO2: S2/S3, LO6: S5/S10, LO12: S9/S10), which conflicts with "一段完整內文出現在指定章節". Put each full answer paragraph in one section and refer to the other from there. Also define the schema of `timeline.json` (fields, date format) so `renderTimeline` can be built from the spec alone.
