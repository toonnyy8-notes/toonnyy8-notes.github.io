## 1. 介紹（步驟 6-1）

### 1.1 一段話總結

這篇綜述把大型語言模型（LLM）裡各種「記憶」機制放進同一個分類框架。作者只談**模型層級**的記憶（存在於模型架構或推論期動態之中），排除代理層級、提示層級的記憶與外部 RAG 流程（§II、§IV-B f）。框架有三個大致正交的軸（§II）：**表示**（representation：隱式 implicit／顯式 explicit，問「存什麼、怎麼存取」）、**更新動態**（update dynamics：離線 offline／線上 online，問「何時、如何更新」）、**持續性**（persistence：短期／長期，問「能影響計算多久」）。更新軸內再細分五種**更新規則**（Table II）：最佳化式寫入、狀態轉移、訊號閘控、准入／淘汰／整併、目標誘導或結構式更新。依表示軸，正文分成兩大塊：§III 隱式記憶（注意力與 KV 快取、稀疏與選擇性注意力、遞迴序列記憶），§IV 顯式記憶（可寫參數模組如 Titans 與 TTT、查表記憶如 kNN-LM 與 Engram、MoE 條件參數、多時間尺度更新）。§V 討論混合架構、記憶管理與評測，§VI 列出開放問題。Table I 以三軸標註 47 列〔本頁推導：計數〕，其中部分列合併多個系統（例如「Mamba / Mamba-2」「Jamba / Jamba-1.5」「Mixtral / Mixtral 8x7B」「Kalman Linear Attention / Gated KalmaNet」），頁面一律說「47 列」，不說「47 個系統」。

### 1.2 研究動機（§I）

1. 記憶正從「計算的副產品」變成明確的架構設計維度：Titans [8]、TTT-E2E [9] 在部署時更新參數；Engram [10] 把記憶儲存與稠密計算分開；Nested Learning [11] 模糊訓練與推論的界線；MoE [12][13] 依輸入選擇性啟用參數子集，構成一種條件記憶（§I 第 2 段、Fig. 1）。
2. 注意力快取、遞迴序列狀態、測試時調適、檢索模組、條件參數路由常被分開研究，但都在回答同構的問題：**存什麼、何時與如何更新、如何與前向計算互動、保留多久、儲存粒度為何**（§I 第 3 段）。
3. 缺乏統一框架，方法比較、系統層級權衡分析與找出未探索的設計空間都很困難。

### 1.3 貢獻（§I 末）

1. 一個統一的記憶分類法與術語，區分隱式、顯式、持久、可調適的記憶機制（§II）。
2. 系統性回顧計算驅動與參數化記憶，涵蓋混合架構、多時間尺度更新與條件參數路由（§III、§IV）。
3. 分析系統層級權衡與多維度評測方法，整理開放問題（§V、§VI）。

另有一份定位比較（§II-D、Table III）：既有綜述多以代理（[53][57]）、認知類比（[54]）、生命週期操作（[55]）或模型生命週期（[56]）組織；本文的視角是「架構基底如何在模型計算中儲存、更新、保留資訊」。

#### 步驟 1：先劃定「記憶」的範圍（§II 開頭、§II-A c、§II-D、§IV-B f）

- 只談模型層級：記憶「實例化於模型架構或其推論期動態之中」。排除依賴外部協作或工程流程的代理層級、提示層級記憶系統。
- 不談預訓練後固定的靜態參數（例如 attention 或 MLP 權重），即使它們編碼知識；焦點是會隨時間演變、或主動儲存與檢索上下文或經驗資訊的機制（§II-A c）。這條排除規則與 MoE 的歸類有張力：MoE 專家也是訓練後固定的參數，Fig. 2 卻寫「Offline: … (Pretraining, MoE)」，Table I 也把 MoE 各列放在顯式下。頁面在 S1 先提醒「MoE 是例外，見 S8」，再在 S8 說明作者把它放在「中間位置」（不一致清單第 5 條）。
- 對話紀錄、使用者檔案、工具輸出、資料庫等，只有在其儲存、存取或更新機制實例化於模型架構內或與之緊密耦合時才納入（§II-D）。
- 與 RAG 的界線：RAG 依賴架構外的文件庫、向量資料庫與協作流程；本文討論的查表記憶把持久儲存嵌在模型結構中（§IV-B f）。
- 作者強調分類「不是僵硬的分類，而是揭示共同結構的概念框架」（§II 開頭）。下一步需要它：框架的三個軸就是用來回答 §I 的五個問題。

#### 步驟 2：表示軸——隱式與顯式（§II-A）

- **隱式記憶**：資訊作為前向計算的副產品儲存，與內部動態緊密耦合；沒有顯式的讀、寫或查表介面，只能經由計算圖隱式存取。例：RNN、線性注意力、SSM 的演化狀態，以及 Transformer 的 KV 快取。
- 關鍵細節：KV 快取雖然**實體化為顯式張量**，但存取語意由架構固定，缺乏獨立定址或更新控制，因此仍是暫時的計算狀態，不是獨立的儲存模組。
- **顯式記憶**：獨立的儲存元件，具明確存取語意，通常支援顯式定址、檢索與更新，且這些操作不能化約為標準前向計算或離線反向傳播。形式可為外部表、聯想緩衝或專用記憶模組。
- 顯式**不限於非參數結構**：附加的參數化模組，只要「被設計並作為記憶運作，具有清楚的讀寫語意與可控的更新策略」，也算顯式。區分依據不是參數形式。
- §IV 開頭再補一句：顯式記憶的定義性質是**自主性**（autonomy）——儲存的資訊獨立於當下的計算圖存在，能以不同於標準前向傳播的機制更新、存取或維護。

#### 步驟 3：更新動態軸——離線與線上，以及五種更新規則（§II-B、Table II）

- **離線**：只在訓練期更新（通常以梯度最佳化），推論時固定。例：某些檢索嵌入、端到端訓練的記憶層、MoE。
- **線上**：推論期也能更新，頻率可以是每個 token、每個片段或每個批次，規則可不同於標準反向傳播。
- 只看「何時」不夠：同樣是線上，遞迴狀態用閉式狀態轉移更新、fast-weight 模組用梯度最佳化、混合模型可能只在不確定性或誤差超過門檻時才更新可存取的 KV 集合。因此作者把**更新規則**當作更新軸內的第二層視角（不是第四個主軸），整理成 Table II：

| 更新規則 | 機制 | 論文舉例 | 主要風險 |
| --- | --- | --- | --- |
| 最佳化式寫入（optimization-based writing） | 以最小化顯式目標更新記憶參數或 fast weights，可在訓練或推論期 | TTT-E2E、Titans、In-Place TTT、Nested Learning | 漂移、不穩定、目標不匹配 |
| 狀態轉移（state-transition updates） | 以學習的轉移、delta rule、投影或濾波方程更新隱藏狀態 | Mamba、Gated Delta Networks、Gated DeltaNet-2、Kaczmarz LA、Kalman LA | 壓縮損失、狀態干擾 |
| 訊號閘控寫入或路由（signal-gated） | 以驚奇度、不確定性、預測誤差或效用訊號決定是否寫入、准入快取或啟用昂貴路徑 | Titans、GDWM、AMOR、HAM | 校準、門檻敏感、延遲才顯現的相關性 |
| 准入、淘汰與整併（admission, eviction, consolidation） | 決定哪些條目被准入、保留、壓縮、淘汰或改寫 | StreamingLLM、RATTENTION、HAM、Bottlenecked Transformers | 不可逆的損失、檢索偏差 |
| 目標誘導或結構式更新（objective-induced or structural） | 由輔助目標、架構排程、層替換或離線建構塑造記憶行為，而非逐例線上寫入 | Engram、MoE [12][41]、Priming、Next-Latent Prediction | 僵化、目標不匹配、測試時適應力有限 |

- 規則不互斥：有的架構把最佳化式寫入與驚奇度調節結合（Titans 同時出現在兩列），有的把狀態轉移與訊號閘控的 KV 准入結合（HAM）。

#### 步驟 4：持續性軸——有效視野，而非儲存大小（§II-C）

- 持續性指「儲存的資訊能繼續影響計算的有效時間範圍」，不只取決於狀態是否實體保留，也取決於**儲存粒度與壓縮率**。
- 一個機制可以存很多高保真的局部項目，卻因儲存隨序列長度快速成長而視野短；反之，小而緊湊的遞迴或參數化狀態，可經由大幅壓縮維持長得多的上下文視野。
- **短期**：細粒度、通常受限於局部視窗、片段或一次推論。KV 快取是典型：以高保真、低壓縮保存 token 層級狀態，但儲存隨保留的 token 數成長，難以無限擴展；視野受視窗大小、快取預算、淘汰策略或會話邊界限制。
- **長期**：在延伸的上下文、某些情況下跨會話保留資訊或其影響，不一定需要大型未壓縮儲存。遞迴序列記憶可能只維持固定大小的狀態；顯式儲存、記憶槽與測試時更新的參數則是另一條路。長期記憶的特徵是延伸的有效視野，「而非儲存大小本身」。
- **三軸大致正交**（§II-C c）：顯式記憶可以離線或線上；線上記憶依更新與淘汰策略可短期或長期。
- 〔本頁推導〕Table I 的 47 列只落在 8 個組合中的 5 個：隱式／線上／短期 10、隱式／線上／長期 19、隱式／離線／長期 1（Next-Latent Prediction）、顯式／離線／長期 10、顯式／線上／長期 7；任何「離線＋短期」或「顯式＋短期」的組合都是 0。頁面據此說明「軸在概念上正交，但現有系統分布不均」，並註明 Table I 依「主要機制」標註（Table I 標題）。

#### 步驟 5：隱式記憶之一——注意力與 KV 快取（§III-A、§III-B）

- 自注意力是「可微、內容定址的暫時工作記憶」：每個新 token 以**附加**新條目隱式更新 KV 快取，檢索由即時計算的注意力權重完成（§III-A a）。
- 容量直接綁定上下文視窗；MLA（DeepSeek-V2 [58]）把 key 與 value 共同壓縮成潛向量，改變 KV 記憶的粒度與效率，但不改變其隱式語意（§III-A b）。延長上下文不一定轉化為有效利用：長上下文模型常無法利用名目容量 [59][60]。
- StreamingLLM：滑動視窗注意力＋少量保留的 attention sink token，不需重新訓練即可在無界串流上穩定生成；從記憶觀點看是**隱式淘汰策略**——多數過去狀態持續被覆寫，少數被保留以錨定注意力（§III-A c）。
- HyperMLP 把自迴歸注意力重寫成輸入條件的兩層 MLP，隱藏寬度隨序列長度成長；仍屬隱式（§III-A d）。
- §III-B 的統一觀點：稀疏、選擇、局部–全域結構，都是對線上記憶系統加上**准入、存取、保留**的控制。固定稀疏（Sparse Transformer、BigBird、Longformer）決定每步可存取哪些條目，「不增加容量，只重塑存取路徑」；內容路由（MoBA 把 KV 切塊並把每個 query 路由到少數相關區塊；NSA 結合壓縮區塊摘要、選擇性保留的細粒度區塊與局部視窗）屬於自適應存取控制；選擇性注意力是隱式准入控制；RATTENTION 分析滑動視窗大小與保留全域 token 數的權衡，顯示少量精選的全域記憶就能大幅改善效能。結論：注意力式記憶常常不是靠存更多，而是靠控制資訊如何被准入、存取與保留（§III-B e）。

#### 步驟 6：隱式記憶之二——遞迴序列記憶（§III-C、Fig. 3）

- 把歷史壓縮進與前向計算耦合的演化潛狀態：經典 RNN／LSTM（[62][63]）、線性注意力遞迴、SSM。
- 線性注意力把注意力核化並利用結合律，把因果注意力寫成線性時間更新的遞迴狀態 [64]；GLA 對矩陣值狀態加入資料相依的衰減 [65]；Mamba／Mamba-2 引入選擇性更新與 SSD 形式 [4][5]；GDN 以輸入條件的 delta rule 做內容感知的保留 [23]（§III-C b）。
- Fig. 3 把兩類寫成：

$$S_t=\alpha_tS_{t-1}-\beta_tS_{t-1}k_tk_t^\top+\gamma_tv_tk_t^\top,\qquad \text{Memory Size}=d_v\times d_k\tag{Fig. 3，線性注意力}$$
$$h_t=A_th_{t-1}+B_tx_t,\qquad \text{Memory Size}=d\times N\tag{Fig. 3，SSM}$$

  圖中 $q_t$ 與 $C_t$ 以虛線連到記憶方塊，表示讀取。〔本頁推導〕讀出寫成 $o_t=S_tq_t$（以 key 查詢時為 $S_tk_i$）；論文圖中沒有寫出讀出式。
- 〔本頁推導〕三項各自的作用：$\alpha_tS_{t-1}$ 讓整個狀態以比例 $\alpha_t$ 保留（$\alpha_t<1$ 為衰減／遺忘）；$-\beta_tS_{t-1}k_tk_t^\top$ 擦除狀態在 $k_t$ 方向上原本存的值；$+\gamma_tv_tk_t^\top$ 把新值 $v_t$ 綁到 $k_t$ 上寫入。係數與文獻的對應（頁面 C2 的預設按鈕，論文沒有逐一寫出，本頁依 §III-C 描述與原論文的標準形式整理）：
  - 線性注意力 [64]：$\alpha=1,\beta=0,\gamma=1$（純加法寫入）。
  - 衰減式（GLA 類）：$\beta=0$，$\alpha<1$。這是兩層簡化：原方法的衰減是資料相依的（§III-C b 只說「data-dependent decay」，沒給形式），而且 GLA 的衰減是逐通道（對角矩陣），不是單一純量；本頁用一個常數純量 $\alpha$ 代替。Mamba／Mamba-2 本身對應 Fig. 3 的第二條式子 $h_t=A_th_{t-1}+B_tx_t$，頁面不把 Mamba 寫成第一條式子的某組係數。
  - Delta rule（GDN 中 delta 部分）：$\alpha=1$，$\beta=\gamma$。
  - Gated delta（GDN）：原式 $S_t=\alpha_t(S_{t-1}-b_tS_{t-1}k_tk_t^\top)+b_tv_tk_t^\top$，展開後對應 $\alpha=\alpha_t,\ \beta=\alpha_tb_t,\ \gamma=b_t$。這段換算要原樣寫進 S5 正文。C2 的預設「Gated delta (0.9, 0.9, 1)」就是 $\alpha_t=0.9,b_t=1$；它的 $\alpha\ne1$、$\beta\ne\gamma$，不在 LO7「delta rule：$\alpha=1,\beta=\gamma$」的對應內，按鈕旁加一行註記說明。
- 〔本頁推導〕delta rule 的覆寫性質：若 $\|k_t\|=1$ 且 $\alpha=\beta=\gamma=1$，寫入後 $S_tk_t=S_{t-1}k_t-S_{t-1}k_t(k_t^\top k_t)+v_t(k_t^\top k_t)=v_t$，該 key 的舊值被完全取代；純加法則讀出 $S_{t-1}k_t+v_t$，同一 key 重複寫入時得到舊值與新值之和。
- 〔本頁推導〕加法寫入的干擾：$T$ 筆寫入、以 $k_i$ 讀取得 $S_Tk_i=v_i(k_i^\top k_i)+\sum_{j\ne i}v_j(k_j^\top k_i)$。只有鍵互相正交時第二項才為 0，而 $d_k$ 維中最多只有 $d_k$ 個互相正交的鍵；隨機單位鍵在 $T>1$ 時就已經互相干擾（$d=32,T=16$，$T<d$，平均串擾仍有 0.674）。隨機單位鍵時每個交叉項的 $(k_j^\top k_i)^2$ 期望為 $1/d_k$；串擾 $e_i$ 扣掉了落在 $v_i$ 方向的分量，粗估 $e_i$ 的均方根約為 $\sqrt{(T-1)(d-1)/d^2}$（20 個 seed 平均：$d=8,T=16$ 為 1.264 vs. 粗估 1.281；$d=32,T=16$ 為 0.672 vs. 0.674）。這就是 Table II「壓縮損失與狀態干擾」與 §III-D a「記憶跨度與表示保真度的權衡」的最小例子。
- 其他變體（§III-C c–g）：Gated DeltaNet-2 分離 key 側擦除與 value 側寫入；Kaczmarz LA 把寫入視為 key 正規化的投影步；Kalman LA 與 Gated KalmaNet 以濾波或線上回歸依估計品質調節更新；RWKV-7 以向量值狀態閘與上下文內學習率推廣 delta rule；KDA（Kimi Linear 的遞迴核心）引入逐通道對角衰減；DeltaProduct 組合多個 Householder 更新；Comba 用純量加低秩轉移與閉迴路回饋；Mamba-3 改進離散化並加入複數值更新與 MIMO 形式，仍是固定大小狀態（Table I 2026；筆記 `llmmem-implicit-recurrent-state`）；Log-Linear Attention 以 Fenwick tree 階層取代單一固定狀態，狀態數隨長度對數成長，介於常數狀態與逐 token KV 之間；RetNet、Jamba、MoM 為遞迴–注意力混合；Next-Latent Prediction 以預測未來潛狀態的目標塑造隱藏表示，是離線、目標誘導的機制，不是新的測試時寫入規則。
- §III-C h：多數遞迴序列記憶屬於狀態轉移更新，差別在每個 token 如何改變並分配壓縮狀態。

#### 步驟 7：隱式記憶的三個限制（§III-D）

1. **容量有界且難以控制**（a）：注意力模型的容量隨上下文視窗與 KV 快取大小，受平方或線性時間複雜度與硬體限制；長上下文模型常無法有效利用名目長度；狀態式模型原則上可處理無界序列，但壓縮進固定大小狀態，產生記憶跨度與表示保真度的權衡。
2. **缺乏可調適的讀寫語意**（b）：資訊只依計算圖（注意力權重或狀態轉移）儲存與取回。
3. **跨脈絡持續性有限**（c）：內容常綁在少數前向傳遞或推論會話上，計算結束即丟棄；快取狀態快照或多狀態混合主要改善同一延伸序列內的保留，而非跨會話持久。
- 這三點「劃定了僅靠計算耦合記憶能達到的邊界」，並引出把儲存與內部計算分開的顯式記憶（§III-D d）。頁面 C3 用每層記憶大小對序列長度的曲線呈現第 1 點與 §II-C 的「視野不等於儲存大小」。

#### 步驟 8：顯式記憶之一——可寫參數模組（§IV-A；Titans 連到 No. 243）

- 早期 fast weights（[68][69]）：快速權重短時間尺度更新以存近期資訊，慢權重存長期知識；MANN、DNC 引入可學讀寫的顯式記憶矩陣（a）。
- **Titans [8]**：專用記憶模組在推論期以**驚奇度驅動的梯度訊號**更新，只改記憶參數、不改骨幹。作者把它歸為顯式，因為資訊存在跨越單次前向計算的持久參數中，並由不同於標準預訓練的規則更新（b）。Table I：顯式／線上／長期，主範式「Parametric with Test-Time Training」，2025。Table II 同時列在最佳化式寫入與訊號閘控兩列。§IV-D a 稱其為「短時間尺度顯式記憶：在一次推論中動態演化的持久參數」，逐 token 調整。§V-A c 描述 Titans 的雙記憶：Transformer 提供傳統短期記憶，輔助模組跨互動累積任務資訊。
- TTT 與 TTT-E2E [9]：在推論期對輸入資料最佳化輔助參數子集；MEMORYLLM [44]：嵌在各層的固定大小潛記憶池，以只有前向的自我更新改寫；Nested Learning [11]：不同參數子集以不同頻率更新（b）。
- In-Place TTT [48] 把 FFN 的下投影矩陣當作可重用的 fast-weight 記憶，逐塊更新；顯式在功能意義上成立——指定的參數子集在專門的測試時目標下作為可寫記憶運作。GDWM [49] 依上下文效用閘控測試時更新（c）。
- **邊界提醒**（c）：[72] 指出一大類帶 key–value binding 的 TTT 內迴圈更新可改寫成學習的線性注意力；作者因此主張只有具「明確指定、自主更新之儲存基底」的變體才在主分類中當作顯式記憶。
- LM2 [45] 以閘控的專用記憶槽與隱藏狀態交互（d）；更新規則觀點（e）：Titans、TTT-E2E、In-Place TTT 都是線上＋最佳化式寫入，GDWM 再加訊號閘控，MEMORYLLM 與 LM2 是槽導向或前向更新變體。
- 解耦學習動態（f）：骨幹存一般語言能力、記憶參數存上下文或任務資訊，減輕災難性干擾，但引入容量限制、更新穩定性與過擬合暫態訊號的風險。與隱式的差別（g）**不是使用頻率**（參數化記憶也可能每個 token 都參與前向計算），而是持續性與自主性。

#### 步驟 9：顯式記憶之二——查表記憶與 MoE（§IV-B、§IV-C；Engram 連到 No. 090）

- kNN-LM [40]：在預訓練模型旁加上 context–target 配對的持久資料庫；資料庫不屬於標準前向計算圖，跨推論呼叫存在，以獨立的最近鄰機制查詢，因此比 KV 快取更明確地屬於顯式記憶（a）。
- 邊界類別（b）：Memorizing Transformers [73] 與 LongMem [74] 有顯式索引與檢索機制，但存的主要仍是模型計算的中間狀態，被視為顯式資料庫記憶與隱式活化記憶之間的邊界類別，不列入 Table I。
- **Engram [10]**（c）：可擴展的條件記憶，資訊存在稀疏啟用的槽中，以結構化雜湊檢索；不以完整注意力重算歷史，而依當前隱藏狀態做選擇性查表；記憶槽是推論後不會自動丟棄的持久元件。作者強調 Engram **把記憶稀疏與專家稀疏分開**：MoE 層稀疏啟用參數化變換，Engram 稀疏定址儲存的記憶條目，所以查表記憶不應化約為條件計算。核心貢獻是可擴展的定址基底，其容量可獨立於稠密計算成長，「受索引方案的準確度與碰撞行為所限」。Table I：顯式／離線／長期，主範式「Hashed Lookup Slots」，2026；Table II 列為目標誘導或結構式更新。
- PlugLM [43] 以可微的插入式 key–value 記憶取代部分 FFN（動機：FFN 本身就像隱式 key–value 儲存）；ExplicitLM [46] 的記憶庫條目是人類可讀的 token 序列（d）。MemoryLLM（FFN）[50] 把 FFN 重新詮釋為不依上下文的逐 token 檢索模組，可預先計算為 token 層級查表（e）。
- 查表記憶的三個結構性質（g）：條目可個別定址，而非壓進單一演化狀態；容量隨槽數或資料庫大小擴展，不受固定隱藏維度限制；檢索通常以內容為基礎，帶來稀疏與條件計算。更新多為結構式或准入式：表可離線建構，推論期動態決定哪些條目可存取。挑戰是記憶成長、索引效率與干擾管理。
- **MoE**（§IV-C）：

$$y=\sum_{i\in S(h)}g_i(h)\cdot\mathrm{Expert}_i(h)\tag{Eq. 1}$$

  路由器對 $E$ 個專家產生稀疏閘控分布，$S(h)$ 是被選中的小子集。Switch Transformer [41] 與 GLaM [42] 顯示稀疏專家啟用可把模型容量擴到兆級參數，同時讓每個 token 的 FLOPs 幾乎不變。記憶觀點：每個專家是一塊持久的參數化記憶，路由網路對這個儲存庫做依上下文的定址；MoE 從參數空間直接取回**變換**，而檢索式機制存取外部 key–value。Mixtral 每層八個專家取 top-2 [13]；DeepSeek-MoE 用細粒度專家切分與負載平衡 [12]。作者把 MoE 放在參數化記憶與查表記憶之間的中間位置。
- 〔本頁推導〕C4 的雜湊碰撞公式：$n$ 個不同鍵獨立均勻雜湊到 $M$ 個槽時，某個鍵與至少一個其他鍵共用槽的機率為 $1-(1-1/M)^{n-1}$，期望占用槽數為 $M\big(1-(1-1/M)^n\big)$。這是單一雜湊函數的教科書模型，不代表 Engram 的實際索引設計（論文 §IV-B 只說「structured hashing」，細節見 No. 090）。

#### 步驟 10：多時間尺度更新與顯式記憶的風險（§IV-D、§IV-E）

- 記憶參數結構上與骨幹分開，更新排程不必與訓練或推論步一致，因此不同子集可用不同頻率演化（§IV-D）。Nested Learning 以階層化的更新頻率形成快到慢的連續譜（b）；慢–快參數分解回到 fast/slow weights（c）。穩定性–可塑性（d）：更新頻繁增加適應力但易過擬合暫態訊號，更新慢保持穩定但反應遲鈍；作者結論：「時間控制對顯式記憶與結構持久性同樣核心」。
- §IV-E 列出六項風險：容量成長與擴展（a，查表系統可隨新條目無界成長，需要索引、修剪與壓縮）；干擾與記憶漂移（b，測試時快速調適可能破壞已學表示，查表中過時或冗餘條目會偏差檢索）；最佳化與收斂（c，驚奇度學習規則或輔助損失未必有預訓練的最佳化保證）；跨回合一致性（d，何時重置、如何分離長短期儲存，類似持續學習）；架構複雜度與可解釋性（e）；參數穩定的幾何限制（f，Lie 群上的正交低秩調適 [75] 與 Muon-OGD [76] 降低跨任務干擾；作者認為更新規則的幾何可能與儲存形式同樣重要）。與隱式比較（g）：選擇隱式或顯式「不只是容量問題，而是系統設計哲學」。

#### 步驟 11：混合架構、記憶管理與評測（§V）

- 混合（§V-A）：Samba 交錯 Mamba 式選擇性 SSM 層與滑動視窗注意力（a）；LightTransfer 把預訓練 Transformer 中的「lazy」層換成串流元件；Priming 把混合化當作從預訓練 Transformer 到混合 SSM 的知識轉移。固定串列或混合頭模型（OLMo Hybrid、Kimi Linear、Hymba、Falcon-H1）以靜態選擇分配高保真注意力路徑；[80] 指出全注意力的配置位置是召回–效率權衡的核心決定因素。**AMOR** 在遞迴骨幹上附加事後注意力精修塊，只對正規化輸出熵高的位置啟用；**HAM** 讓遞迴記憶處理每個 token，稀疏 KV 快取只存遞迴狀態難以預測的 token，快取成長由門檻或學習的路由器控制（b）。作者的歸納：固定混合是排程或結構式分配，AMOR 閘控「是否執行注意力精修」，HAM 閘控「token 是否准入 KV 快取」，兩者都依不確定性或預測誤差更新可存取的記憶集合。隱式＋顯式儲存的組合（c）：Titans 的雙記憶，以及受 Engram 啟發、在早期層加入可擴展 key 檢索的系統。多時間尺度混合（d）與多元件設計（e，Hydra、Expansion Span）。三項權衡（f）：高解析召回 vs. 全域脈絡、計算效率、模組化與重用。
- 記憶管理（§V-B）：KV 快取壓縮與量化（CommVQ）；Memory Caching 存遞迴記憶的片段快照；PagedAttention 把 KV 快取改成可分頁區塊；Bottlenecked Transformers 週期性整併或改寫快取，仍較接近短期隱式工作記憶；滑動視窗優先近期、稀疏全域連結保留遠距錨點。結論：記憶管理是架構設計軸，不是事後工程。
- 評測（§V-C）：長上下文檢索與召回（NIAH、LongBench、RULER、L-Eval，揭示注意力稀釋與近因偏差）；結構化依賴與推理（SCROLLS、NarrativeQA 類）；遺忘、干擾與穩定性；效率–效能權衡（以上下文長度與記憶占用的函數報告）；隱式與顯式的評測協定不同（顯式需評更新一致性、檢索精度與延遲、對記憶成長與干擾的穩健性）；統一指標：把記憶表現分解成**容量、保真度、持續性、效率**等正交軸（f）。

#### 步驟 12：開放問題與結論（§VI、§VII）

六個方向：統一的記憶理論（在狀態轉移觀點下，以保留保真度、干擾穩健性、資訊壓縮效率刻畫容量，形式化穩定性–可塑性）；持續與終身參數記憶；穩健且可解釋的更新規則（逐一對應 Table II 的五種規則風險，例如訊號閘控依賴驚奇度、熵或預測誤差能否忠實反映未來相關性；准入與淘汰面臨不可逆問題；目標是可診斷、必要時可逆）；自適應記憶分配與控制（由靜態組合走向學習的控制器）；硬體–演算法協同設計；有原則的多維度評測（儲存容量、檢索保真度、時間持續性、抗干擾、計算效率，以及控制干擾注入、記憶衰減量測、更新一致性分析等壓力測試）。§VII：沒有單一記憶範式滿足所有需求——token 層級注意力以可擴展性換高保真召回；遞迴序列記憶提供壓縮的長視野但有干擾；顯式記憶增強時間持續性但帶來更新穩定與定址的複雜度；因此 LLM 設計正轉向自適應協調這些互補基底的混合架構。

### C2 · 線性注意力狀態的寫入與讀取（S5）

- **教的概念**：Fig. 3 統一式中 $\alpha,\beta,\gamma$ 的作用；固定大小狀態的串擾（壓縮損失、狀態干擾）；衰減造成的遺忘；delta rule 的覆寫。
- **簡化**（頁面寫出）：$d_k=d_v=d$；鍵與值是隨機單位向量（不是學習的投影）；係數為常數（原方法多為資料相依）；讀出用 $S_Tk_i$〔本頁推導〕。
- **讀者操作**：
  - 預設按鈕四個：「線性注意力（1, 0, 1）」「衰減（0.9, 0, 1）」「Delta rule（1, 1, 1）」「Gated delta（0.9, 0.9, 1）」，括號為 $(\alpha,\beta,\gamma)$；預設「線性注意力」。按鈕列下方一行小字：「衰減是純量簡化（GLA 原為逐通道衰減）；Gated delta 對應 $\alpha_t=0.9,b_t=1$，$\alpha\ne1$，不屬於 LO7 的 delta rule 係數（$\alpha=1,\beta=\gamma$）。」
  - 滑桿 $\alpha\in[0,1]$、$\beta\in[0,1]$、$\gamma\in[0,1]$，步長 0.01；拖動後預設按鈕取消選取。
  - 滑桿 $d\in\{4,8,16,32\}$（預設 8）、寫入數 $T\in[1,48]$ 整數（預設 16）。
  - 鍵模式分段按鈕：「隨機單位鍵」（預設）／「正交鍵（第 t 步用 $e_{t\bmod d}$）」——$T>d$ 時正交鍵會重複，用來示範覆寫。
  - 「重新抽樣」：seed 從 7 開始，每按一次加 1。
  - 「平均 20 次」：以 seed 7–26 各跑一次 `c2run`，讀數區多一列「20 次平均：平均 e、e 的均方根」；目前參數改變時這列清空（不自動重算，避免拖曳時每格跑 20 次）。
- **計算**（`c2run`，core.js，逐字內嵌）：PRNG `mulberry32(seed)`；`gauss` 為 Box–Muller 只取 cos 分支。第 $t$ 步先抽 $d$ 個高斯數正規化為 $k_t$，再抽 $d$ 個正規化為 $v_t$；正交模式仍照常抽 $k_t$（丟棄）以保持各模式的 $v_t$ 相同，再以 $e_{t\bmod d}$ 取代。$S_0=0$；每步先算 $S_{t-1}k_t$，再 $S\leftarrow\alpha S-\beta(S_{t-1}k_t)k_t^\top+\gamma v_tk_t^\top$。結束後對每個 $i$：$r_i=S_Tk_i$，訊號係數 $c_i=\langle r_i,v_i\rangle$（$\|v_i\|=1$），串擾 $e_i=\|r_i-c_iv_i\|$；另算 $\|S_T\|_F$。正交模式中 $i+d<T$ 的項標「被覆寫」。
- **數值防護**：正規化時範數 $<10^{-12}$ 則改用 $e_0$；係數範圍限制在 $[0,1]$，且 $\|k\|=1$，所以每步乘上的 $\alpha I-\beta kk^\top$ 特徵值為 $\alpha$ 與 $\alpha-\beta$（$\beta>\alpha$ 時為負，但仍在 $[-1,0]$），絕對值都 $\le1$，因此**不會放大舊狀態**；但寫入項 $\gamma vk^\top$ 每步都加進來，$\|S\|_F$ 仍會隨 $T$ 成長（例：$\alpha=1,\beta=0$ 時每步矩陣就是 $I$）〔本頁推導〕。頁面寫成這句，不寫「狀態不會發散」。$T\le48,d\le32$ 時每次重算 ≤ 48·32²·3 次乘加。
- **邊界值**：$T\le d$ 的正交模式沒有任何 key 重複，不會出現「被覆寫」；$\alpha=0$ 時讀數仍由遞迴直接計算（不用 $\alpha^{T-i}$ 公式），沒有 $0^0$ 問題；只有在「正交鍵、$\beta=0$」時才顯示提示文字「理論值 $c_i=\gamma\alpha^{T-i}$」，用 JS `**`（`0**0===1`，對應 $c_T=\gamma$，正確）。
- **顯示**（元件內所有符號與讀數一律 Unicode，例「cᵢ」「eᵢ」「‖S‖F」「√((T−1)(d−1))/d」；元件不呼叫 `renderMath`；`aria-label` 與 live 文字不含 TeX）：
  - 左：長條圖，橫軸寫入位置 $i=1..T$，每個位置兩根並排長條：$c_i$（`--c-par` 實心，標「訊號」）與 $e_i$（`--c-perp` 斜線填充，標「串擾」）；縱軸固定 $[-0.5,2]$。**裁切規則**：值 $>2$ 的長條畫到 2 為止，頂端加一個朝上的實心三角形（寬 = 長條寬，高 6px），三角形上方直接寫數值（一位小數，例「6.5」）；值 $<-0.5$ 同理畫到底並加朝下三角形。長條太密（$T>24$ 且長條寬 <8px）時不寫數值，改在圖下方列出「超出範圍：位置 3（e = 6.5）、…」，最多 6 筆，其餘寫「另 n 筆」。不靠 hover。$c=1$ 參考虛線固定畫出（它在 $[-0.5,2]$ 內，不受裁切影響），標「完整取回」。「被覆寫」位置在橫軸下方加「×」與文字。
  - 右：$S_T$ 熱圖（$d\times d$，發散色＋每格以亮度表示）。下方一個 `<button aria-pressed>`「以數字顯示」（Tab 可達，Enter／Space 切換），切換為數值表，表中負值帶「−」號，因此正負號不必靠顏色讀出。`aria-label` 給出 $\|S_T\|_F$ 與最大絕對值。
  - 讀數：平均 $c$、平均 $e$、最後一筆的 $c_T,e_T$、$\|S_T\|_F$；串擾參考列並排三個數：「本次抽樣 e 的均方根 ｜ 粗估 √((T−1)(d−1))/d（本頁推導）｜ 20 次平均（按鈕產生）」，列尾小字「單次抽樣會偏離粗估；粗估只適用於隨機鍵、加法寫入（β = 0）」。β≠0 或正交模式時這列整列灰化並寫「不適用」。
  - 圖版底部一行：「讀數由本頁依 Fig. 3 的遞迴式即時計算；係數與文獻的對應、讀出式為本頁推導。」
- **讀者應觀察到**：（1）正交鍵、$T\le d$：線性注意力與 delta rule 全部 $c_i=1,e_i=0$；衰減時 $c_i=\alpha^{T-i}$（$d=T=8,\alpha=0.9$：第 1 筆 0.478）。（2）隨機鍵：即使 $T<d$ 也有串擾（$d=32,T=16$ 平均 $e$=0.674）；預設 $d=8,T=16$ 時線性注意力平均 $e$=1.054；delta rule 最後一筆恆為 $c_T=1,e_T=0$〔本頁推導：$\|k_T\|=1$ 時 $S_Tk_T=(\alpha-\beta)S_{T-1}k_T+\gamma v_T$，所以只要 $\alpha=\beta$ 且 $\gamma=1$ 就讀回 $v_T$；Delta rule (1,1,1) 與 Gated delta (0.9,0.9,1) 都滿足〕。（3）正交鍵、$d=8$、$T=9$：第 $t=d+1=9$ 步重用第 1 筆的 key，加法讀出 $v_1+v_9$，delta rule 讀出 $v_9$。（4）$d$ 加大，同樣 $T$ 下串擾變小（狀態大小 $d_v\times d_k$ 就是容量）。
- **無障礙**：滑桿有 `<label>` 與 `aria-valuetext`；長條以實心／斜線區分並有圖例文字；經全頁共用的 `announce()` 只在滑桿 `change`（放開）、按鈕按下時宣告「平均訊號 0.81，平均串擾 1.05」（≤20 字），拖曳中的 `input` 事件不宣告；熱圖有數值表替代。
- **效能**：`input` 事件只記下新值並 `requestAnimationFrame` 排一次重畫（同一畫格內多次 input 合併成一次），兩張 SVG 在同一個 rAF 回呼內重畫。

### C3 · 每層記憶大小與序列長度（S6）

- **教的概念**：§III-D a 的容量限制與 §II-C「視野不等於儲存大小」：KV 快取隨長度線性成長、滑動視窗封頂、遞迴狀態固定、Log-Linear 對數成長、HAM 只為准入 token 付 KV 成本。
- **簡化**（頁面寫出）：只算每層要保存的浮點數個數，不算位元組、不算參數；配置為**本頁示例設定**（論文沒有數字）：頭數 $n_h=8$、每頭維度 $d_h=128$（$d_k=d_v=d_h$）、MLA 潛向量維度 $d_c=512$（不含位置編碼分量）、SSM 狀態維度 $N=16$、模型寬 $d=n_hd_h=1024$；StreamingLLM 的 sink 數 $s=4$。
- **讀者操作**：滑桿 $\log_2L\in[8,20]$ 步長 0.25（$L=\mathrm{round}(2^x)$，預設 15，$L=32768$）；視窗 $W\in\{512,1024,2048,4096,8192\}$（預設 4096）；HAM 准入比例 $\rho\in[0,0.5]$ 步長 0.01（預設 0.1）；勾選框逐條顯示／隱藏曲線。
- **計算**（`footprint`，core.js）：
  - 完整 KV 快取：$2Ln_hd_h$
  - 滑動視窗＋sink：$2\min(L,W+s)\,n_hd_h$
  - MLA：$Ld_c$
  - 線性注意力／delta 狀態：$n_hd_kd_v$（常數）
  - SSM：$d\cdot N$（常數）。讀數表與圖上在 SSM 旁加「（示例設定的結果，非 SSM 的固有優勢）」：它比線性狀態小 8 倍，完全來自本頁選的 $N=16$ 對 $d_h=128$，論文沒有給數字。
  - Log-Linear：$n_hd_kd_v\cdot(\lfloor\log_2L\rfloor+1)$——〔本頁推導〕以 Fenwick tree 前綴分解的層數上界估計狀態個數；論文只說「隨長度對數成長」。因為取上界，$L=256$ 時（1,179,648）反而大於完整 KV（524,288），讀數表在此情形加註「上界估計，短序列時偏大」。
  - HAM：$n_hd_kd_v+2\lceil\rho L\rceil n_hd_h$——〔本頁推導〕依 §V-A b「遞迴記憶處理每個 token、稀疏 KV 只存難預測的 token」的最簡模型，$\rho$ 為准入比例。
- **顯示**：log–log 折線圖，橫軸 $L\in[2^8,2^{20}]$，縱軸浮點數 $[10^4,10^{10}]$；每條曲線不同線型＋終點直接標籤（不只靠色）；目前 $L$ 的垂直指標線。終點標籤文字：推導式的兩條寫「Log-Linear（本頁推導）」「HAM（本頁推導）」，SSM 寫「SSM（示例設定）」，標籤本身就帶標記，不只在圖版底註。線性狀態與 SSM 是水平常數線，圖例文字寫「常數」。**標籤避讓**：終點標籤依 y 由上到下排序，相鄰兩個的垂直間距不足 14px 時把下方的往下推，推到圖框底仍不夠就往上推，必要時加一條細引線連回曲線終點。取消勾選只隱藏該曲線與其標籤，讀數表的列保留（灰字標「圖上已隱藏」）。讀數表是主要的資訊載體，圖是輔助。下方讀數表：機制、目前大小（千分位）、相對完整 KV 的比例、「可精確存取的過去 token 數」（KV：$L$；視窗：$\min(L,W+s)$；MLA：$L$（壓縮後）；遞迴／SSM：「無逐 token 條目，靠壓縮」；Log-Linear：「近期細、遠期粗的摘要」；HAM：「$\lceil\rho L\rceil$ 個准入 token＋遞迴狀態」）。≥480px 為一般表格（外包 `overflow-x:auto` 只作保險）；<480px 改成每個機制一張小卡（`<dl>`：機制名＋線型示意，下列「目前大小」「相對完整 KV」「可精確存取」三行），7 張垂直堆疊，不產生水平捲動。
- **數值防護**：$\log_2$ 只作用在 $L\ge256$；縱軸下界 $10^4$ 以下的值（SSM 16,384 不會低於）以軸底標記；千分位用 `toLocaleString('zh-TW')`。
- **讀者應觀察到**：（1）$L=32768$ 時完整 KV 為 67,108,864，是線性狀態 131,072 的 512 倍；（2）$L>W+s$ 後滑動視窗封頂於 8,396,800；（3）遞迴狀態與 SSM 不隨 $L$ 改變，但「可精確存取的 token」欄變成「靠壓縮」——這就是 §II-C 與 §III-D a 的權衡；（4）HAM 的斜率與 KV 相同但乘上 $\rho$。
- **無障礙**：滑桿 `aria-valuetext`（例「L = 32,768」）；圖 `role="img"` 與 `aria-label` 摘要當前各值（純文字，不含 TeX）；讀數表是主要資訊載體；滑桿放開時經 `announce()` 宣告「L = 32,768，完整 KV 是線性狀態的 512 倍」（≤20 字）。

### C4 · 雜湊查表槽與 MoE 的稀疏（S8）

- **教的概念**：查表記憶的容量隨槽數擴展、每個 token 的讀取量不變；容量受碰撞行為限制（§IV-B c、g）；對照 MoE 每個 token 啟用的專家比例（Eq. 1、§IV-C）。
- **簡化**（頁面寫出，標「本頁示例設定」）：單一均勻雜湊函數、鍵互不相同；每個 token 每張表讀一個槽。這些都不是 Engram 的實際設計，論文沒有給 Engram 每個 token 讀幾個槽（§IV-B c 只說容量「subject to the accuracy and collision behavior of the indexing scheme」；細節見 No. 090）。
- **讀者操作**：滑桿 $\log_{10}n\in[2,7]$ 步長 0.1（預設 5）、$\log_{10}M\in[3,8]$ 步長 0.1（預設 6）；「重新抽樣」（玩具格的 seed 從 7 起，每按加 1）。
- **計算**（`hashStats`、`hashSim`、`nVis`，core.js）：
  - 負載 $n/M$；碰撞比例 $1-(1-1/M)^{n-1}$；期望占用 $M(1-(1-1/M)^n)$。以 `log1p(-1/M)` 與 `expm1` 計算，避免 $M$ 很大時 $1-1/M$ 捨入成 1；$n\le1$ 時碰撞比例為 0。
  - 玩具格：$M_v=1024$ 槽（32×32），$n_v=\min(4096,\max(1,\mathrm{round}(1024\,n/M)))$ 個鍵，以 `mulberry32(seed)` 依序取 `floor(r()*1024)` 作為槽位；格子三態：空（空心，描邊 1.5px）、1 個鍵（實心）、≥2 個鍵（實心＋中央一個 `--bg` 色圓點，形狀可辨，不放數字，因為 390px 時格寬只有約 10px）。格子是純展示、不可點，不需要觸控尺寸。各重數的計數列在格子下方一行文字：「空 n₀ 槽｜1 鍵 n₁ 槽｜2 鍵 n₂ 槽｜3 鍵以上 n₃ 槽」。讀數「本次抽樣碰撞比例」與「期望（$n_v$、$M_v$ 代入公式）」並列，註明玩具是一次隨機抽樣。
  - **封頂**：$n/M>4$ 時 $n_v$ 封頂於 4096（$n_v/M_v=4$）。這時玩具格標題改為「玩具格已封頂：n_v/M_v = 4（上方 n/M = …）」，玩具讀數一律以 $n_v$、$M_v$ 表示，不與標題的 $n/M$ 混用。驗收第 4 列（$n/M=10$）就是封頂情形。
  - MoE 對照列（兩列分開，中間一行粗體「兩個比例的分母不同，不可直接比較」）：「Mixtral：每層 8 個專家取 top-2，每個 token 啟用 2/8 = 25% 的**專家**（§IV-C [13]，論文數字）」；「查表（本頁示例設定）：若每個 token 每張表讀 1 個槽，讀到的是全部**槽**的 $1/M$」。百分比 ≥0.01% 時用一般小數（兩位有效數字），更小時用科學記號（例 $M=10^6$：1×10⁻⁴ %；$M=10^8$：1×10⁻⁶ %）。
- **顯示**：左為玩具格；右為讀數卡（負載、碰撞比例、期望占用、每 token 讀取比例），下方一條 $n/M$ 從 0.001 到 10 的碰撞比例曲線（對數橫軸）並標出目前點。
