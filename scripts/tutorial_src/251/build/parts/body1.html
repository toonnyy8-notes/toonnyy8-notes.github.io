    LLM 的記憶：一張三軸分類地圖

    這篇綜述以表示、更新動態、持續性三個軸，整理注意力快取、遞迴狀態、測試時更新的參數、查表記憶與 MoE。

    Sining Zhoubian、Dan Zhang、Evgeny Kharlamov、Jie Tang（2026）〈Memory for Large Language Models〉

    01 · 記憶指什麼

    記憶在這裡指模型內部保存、並影響後續輸出的資訊，例如：注意力為每個讀過的 token 留下的 key–value 向量；遞迴模型讀完前文後帶到下一步的一組數值；推論時還會被改動的參數；以及可以用索引直接查的表格。

    02 · 三個問題

    三個問題決定一個機制的位置：它有沒有獨立的讀寫介面？推論時會不會被更新？能影響計算多久？

    03 · 兩個例子

    TitansEOnL 在推論時以梯度更新一個記憶模組；EngramEOffL 把記憶存在以雜湊定址的槽中。兩者都被歸為顯式長期記憶：前者線上更新，後者離線（訓練期）更新。

    三軸標記依序表示 表示／更新／持續：實心＝顯式（E）、線上（On）、長期（L）；空心＝隱式（I）、離線（Off）、短期（S）。

    01 · 範圍

    本文的記憶是模型層級的機制

    作者觀察到，記憶正從「計算的副產品」變成一個明確的架構設計維度（§I）。Titans 與 TTT-E2E 在部署時更新參數；Engram 把記憶儲存與稠密計算分開；Nested Learning 讓訓練與推論的界線變得模糊；MoE 依輸入只啟用一部分參數，構成一種條件記憶。條件記憶指只有被路由器選中時才參與計算的參數，例如 MoE 的專家。

    注意力快取、遞迴序列狀態、測試時調適、檢索模組與條件參數路由過去多被分開研究，但作者認為它們都在回答同一組問題：存什麼、何時與如何更新、如何與前向計算互動、保留多久、儲存粒度為何（§I）。缺少統一的框架時，方法之間難以比較，系統層級的權衡也難以分析。

    本文的範圍因此限定為模型層級的記憶：只納入實例化於模型架構或其推論期動態之中的機制（§II）。依賴外部協作或工程流程的代理層級記憶與提示層級記憶被排除；外部 RAG 流程也被排除，因為它依賴架構外的文件庫、向量資料庫與協作流程，而本文討論的查表記憶把持久儲存嵌在模型結構中（§IV-B f）。預訓練後固定的靜態參數（例如 attention 或 MLP 權重）即使編碼了知識，原則上也不討論，焦點是會隨時間演變、或主動儲存與檢索資訊的機制（§II-A c）。MoE 是例外：它的專家也是訓練後固定的參數，作者卻把它放在顯式參數化記憶與查表記憶之間的中間位置（§IV-C），理由見 08。

    對話紀錄、使用者檔案、工具輸出與資料庫等，只有在其儲存、存取或更新機制實例化於模型架構內、或與架構緊密耦合時才納入（§II-D）。作者也強調，這套分類「不是僵硬的分類，而是揭示共同結構的概念框架」（§II 開頭）。下表摘錄 Table III：既有綜述多以代理、認知類比或生命週期組織，本文的視角是架構。

    02 · 三個軸

    三個軸分別回答存什麼、何時更新、保留多久

    作者用三個大致正交的軸描述每個記憶機制（§II）。表示軸（representation）分隱式與顯式，回答「存什麼、如何存取」；更新動態軸（update dynamics）分離線與線上，回答「何時、如何更新」；持續性軸（persistence）分短期與長期，回答「資訊能影響計算多久」。

    軸的順序：§I 的貢獻列表寫成「表示、持續性、更新動態」，摘要、§II 與 §VII 寫成「表示、更新動態、持續性」。本頁採用 §II 的順序。

    表示軸：有沒有獨立的讀寫介面

    隱式記憶把資訊當作前向計算的副產品儲存，與模型內部動態緊密耦合；它沒有顯式的讀、寫或查表介面，只能經由計算圖存取。例子是 RNN、線性注意力與 SSM 的演化狀態，以及 Transformer 的 KV 快取。這裡的「狀態」指模型讀完前文後留下、並帶到下一步的數值，例如 RNN 的隱藏向量。顯式記憶是獨立的儲存元件，具有明確的存取語意，通常支援顯式的定址、檢索與更新，而且這些操作不能化約為標準的前向計算或離線反向傳播（§II-A）。

    區分隱式與顯式的判準是有無獨立且可控的儲存／檢索介面。KV 快取雖然實體化為顯式的張量，但它的存取語意由架構固定，沒有獨立定址或更新控制，因此仍是暫時的計算狀態，屬於隱式。反過來，顯式不限於非參數結構：附加的參數模組只要被設計並作為記憶運作、具有清楚的讀寫語意與可控的更新策略，就是顯式，與是否為參數形式無關（§II-A）。§IV 開頭再補充一點：顯式記憶的定義性質是自主性（autonomy），也就是儲存的資訊獨立於當下的計算圖存在，能以不同於標準前向傳播的機制更新、存取或維護。

    更新動態軸：推論時會不會更新

    離線記憶只在訓練期更新，通常以梯度最佳化，推論時固定，例如端到端訓練的記憶層與 MoE。線上記憶在推論期也能更新，頻率可以是每個 token、每個片段或每個批次，更新規則也可以不同於標準反向傳播（§II-B）。只看「何時」並不夠，下一節的更新規則補上「如何」。

    持續性軸：有效視野，而非儲存大小

    持續性指儲存的資訊能繼續影響計算的有效時間範圍，簡稱有效視野：過去的資訊還能影響目前輸出的距離。它不只取決於狀態是否實體保留，也取決於儲存粒度與壓縮率（§II-C）。短期記憶細粒度，通常受限於局部視窗、片段或一次推論；長期記憶在延伸的上下文、某些情況下跨會話保留資訊或其影響，不一定需要大型的未壓縮儲存。

    持續性取決於儲存粒度與壓縮率。KV 快取以高保真、低壓縮的方式保存每個 token 的狀態，儲存隨 token 數成長，難以無限擴展，有效視野因而受視窗大小、快取預算、淘汰策略或會話邊界限制，被歸為短期。遞迴狀態的大小固定，可以靠大幅壓縮維持較長的有效視野，因此可能被歸為長期；§II-C 的用詞是「may」，不是保證。長期記憶的特徵是延伸的有效視野，而非儲存大小本身。06 的 C3 會把這兩種情形畫成曲線。

    作者指出三個軸在概念上大致正交（§II-C c）：顯式記憶可以離線或線上，線上記憶依更新與淘汰策略可以短期或長期。

    本章用到的四個術語
    術語意義
    隱式／顯式記憶是否有獨立且可控的儲存或檢索介面（§II-A）
    離線／線上更新只在訓練期，或推論期也能更新（§II-B）
    短期／長期資訊能持續影響計算的有效視野（§II-C）

    檢查理解

    三個軸是什麼？各問什麼？

    表示（隱式／顯式）：存什麼、如何存取；更新動態（離線／線上）：何時、如何更新；持續性（短期／長期）：資訊能影響計算多久（§II）。

    KV 快取已是實體張量，為何仍算隱式？什麼讓參數模組算顯式？

    判準是有無獨立且可控的儲存／檢索介面；KV 快取的存取語意由架構固定、無獨立定址或更新控制；參數模組若被設計並作為記憶運作、具清楚讀寫語意與可控更新策略即為顯式，與是否為參數形式無關（§II-A）。

    為什麼儲存隨 token 數成長的 KV 快取被歸為短期，而大小固定的遞迴狀態反而可能被歸為長期？

    持續性取決於儲存粒度與壓縮率：KV 快取高保真低壓縮，儲存隨 token 數成長，因而受視窗與快取預算限制；遞迴狀態大小固定，可以靠壓縮維持較長的有效視野（§II-C 用「may」，不是保證）。

    04 · 注意力

    注意力是內容定址的短期隱式記憶

    作者把自注意力描述為「可微、內容定址的暫時工作記憶」（§III-A a）。內容定址指讀取時不靠位置編號，而是比較 query 與每個 key 的相似度。

    以記憶的語言描述，KV 快取的寫入是每個新 token 以附加一筆 key–value 條目的方式隱式更新快取；讀取由即時計算的注意力權重完成（§III-A a）。StreamingLLM 使用滑動視窗注意力，再保留少量 attention sink token，不需重新訓練就能在無界串流上穩定生成；從記憶觀點看，它是一種隱式淘汰策略：滑動視窗持續覆寫多數過去狀態，少數 attention sink token 被保留下來錨定注意力（§III-A c）。

    注意力記憶的容量直接綁定上下文視窗。MLA（DeepSeek-V2）把 key 與 value 共同壓縮成潛向量，改變 KV 記憶的粒度與效率，但不改變其隱式語意（§III-A b）。延長上下文也不一定轉化為有效利用：長上下文模型常無法利用名目上的容量。HyperMLP 把自迴歸注意力改寫成輸入條件的兩層 MLP，隱藏寬度隨序列長度成長，仍屬隱式（§III-A d）。

    §III-B 提出一個統一的觀點：稀疏、選擇與局部–全域結構，都是對線上記憶系統加上准入、存取與保留的控制。固定稀疏（Sparse Transformer、BigBird、Longformer）決定每一步可以存取哪些條目，不增加容量，只重塑存取路徑。MoBA 把 KV 切成區塊，把每個 query 路由到少數相關區塊；NSA 結合壓縮的區塊摘要、選擇性保留的細粒度區塊與局部視窗；兩者屬於自適應存取控制。選擇性注意力（Selective Attention）是隱式的准入控制。RATTENTION 分析滑動視窗大小與保留的全域 token 數之間的權衡，顯示少量精選的全域記憶就能大幅改善效能。作者的結論是：注意力式記憶常常不是靠存更多，而是靠控制資訊如何被准入、存取與保留（§III-B e）。

    檢查理解

    KV 快取如何「寫入」與「讀取」？StreamingLLM 在記憶觀點下是什麼？

    每個新 token 以附加條目寫入，讀取由即時計算的注意力權重完成；StreamingLLM 是隱式淘汰策略：滑動視窗持續覆寫多數過去狀態，保留少量 attention sink token 錨定注意力（§III-A a、c）。
