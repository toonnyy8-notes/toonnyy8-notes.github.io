    Transformer 的 token 縮減與解析度還原

    從 ViT 的 token 合併到像素擴散的 RTI 與 HiT，七期研究在八個設計軸上的選擇。

    起點論文：〈Elastic Token Compression for Pixel-Space Diffusion Transformers〉（RTI，2026）與〈Hierarchical Diffusion Transformer for End-to-End Image Generation〉（HiT，2026）

    01 · 成本

    Transformer 每層的計算量大約與 token 數成正比；擴散模型每一步、每一層都對每個 patch 付相同的計算。

    02 · 取捨

    七期研究的差別在於：哪些 token 合成一組、在網路哪裡合、合完之後怎麼回到每個 patch。

    03 · 兩個端點

    RTI 把相鄰且相似的 patch 合成連續區域，用來加速現成模型；HiT 讓模型自己學分組、允許相隔很遠的 patch 同組，從頭訓練以提升品質。

    01 · 先備

    先備：擴散 Transformer 與評估指標

    本頁假設讀者知道 Transformer 的注意力（attention）：一張影像先切成固定大小的方塊（patch），每個 patch 變成一個向量，稱為 token；每一層讓所有 token 兩兩計算注意力，再各自通過一個 MLP。以下只定義後文會用到的詞。

    擴散模型與 DiT。擴散模型從純噪聲出發，反覆用一個網路把噪聲一步步去除，得到影像。以 Transformer 作為這個去噪網路的模型稱為 DiT（Diffusion Transformer）。本頁採用 RTI 與 JiT 的時間方向：取樣狀態寫成 $x_t=t\,x+(1-t)\,\varepsilon$，其中 $x$ 是乾淨影像、$\varepsilon$ 是標準高斯噪聲；$t=1$ 時是乾淨影像，$t=0$ 時是純噪聲。生成時從 $t=0$ 走到 $t=1$，每一個取樣步（sampling step）都要把整個網路跑一次。

    x-prediction。網路直接輸出它對乾淨影像 $x$ 的預測，稱為 x-prediction。JiT 與 RTI 所改造的 MiniT2I 都屬於這一類。因為要對每個 patch 都輸出一個預測，擴散模型的輸出是稠密的。

    注意力的三個詞。每個 token 經三個線性投影得到 query、key、value：query 是「要找什麼」，key 是「我有什麼」，value 是「被取走的內容」；一個 token 的輸出是所有 value 的加權平均，權重由它的 query 與各 key 的內積決定。softmax 把一組數 $z_i$ 轉成總和為 1 的正權重 $e^{z_i}/\sum_k e^{z_k}$。兩個向量的餘弦相似度是它們夾角的餘弦 $a^\top b/(\lVert a\rVert\lVert b\rVert)$，介於 −1 與 1，越接近 1 表示方向越像。

    CFG。Classifier-free guidance：每一步分別跑一次有條件（例如給文字）與無條件的預測，再把兩者的差放大後相加。所以一步其實要跑兩個分支。

    latent 與 pixel-space。latent 擴散先用一個另外訓練的 VAE 把影像壓成較小的格點，再在那個空間生成；pixel-space（像素空間）擴散直接在像素上生成，不需要 VAE。

    評估指標。FID 衡量生成影像與真實影像的分布距離，越低越好；GenEval 衡量文字到影像模型是否畫對物件、數量、顏色與位置，是正確率，越高越好。牆鐘時間（wall-clock time）是實際花費的秒數，FLOPs 是浮點運算次數；兩者不一定成正比。

    LoRA 與 RoPE。LoRA 凍結原本的權重，只訓練一個低秩的增量。RoPE（rotary position embedding）以一組不同頻率的旋轉相量 $e^{i\omega p}$ 表示位置 $p$，注意力只看兩個 token 的相位差。

    02 · 成本

    token 數決定 Transformer 的成本

    考慮一個標準 Transformer block，序列長度（token 數）為 $L$、模型寬度為 $d$、MLP 的隱藏寬度為 $m\cdot d$（擴張比 $m$）。把一次乘加計為 2 次運算，前向 FLOPs 由三部分組成：QKV 與輸出投影 $8Ld^2$；MLP $4mLd^2$；注意力分數 $QK^\top$ 與加權 $AV$ 共 $4L^2d$。

    $$C(L)=(8+4m)\,L\,d^2+4L^2d\;\overset{m=4}{=}\;24Ld^2+4L^2d$$
    本頁推導

    一個 block 的 FLOPs 在 $m=4$ 時是 $C(L)=24Ld^2+4L^2d$。其中注意力的二次項占總成本的比例是 $4L^2d/(24Ld^2+4L^2d)=L/(6d+L)$；取 $d=768$、$L=1024$，二次項只占 18.2%（$L=256$ 為 5.3%，$L=4096$ 為 47.1%，$L=16384$ 為 78.1%）。所以在 DiT 常見的 256–1024 個 token 下，成本大約與 token 數成正比：token 減半，block 成本約減半；注意力的二次項要到數千個 token 以上才成為主項。本頁推導這也與 ToMeSD、ToDo 在大圖上加速最多一致（ToDo 摘要：一般尺寸至多 2×，2048×2048 至多 4.5× 以上僅摘要）；ToMeSD 作者對小圖加速較少的解釋是「擴散模型不是瓶頸」（ToMeSD Sec. 5）。

    第二點：牆鐘時間可能比 FLOPs 下降得更快。RTI App. A（Fig. 10）在 RTX 4090、batch 4 下量測，每個預算的實際時間都低於解析 FLOPs 曲線，作者歸因於這些長度下的注意力受記憶體頻寬限制。

    pixel-space 模型的 token 特別多。JiT（Li 與 He，2025）以 patch 16 處理 256² 影像，得到 16×16 = 256 個 token；RTI 改造的文字到影像模型 MiniT2I-B/16 在 512²、patch 16 下有 32×32 = 1024 個 token（RTI Sec. 3.1）。RTI 的說法是：latent 模型在 VAE 中「一次付清」低階空間冗餘，pixel-space 模型則在每個 block 都付一次（RTI Sec. 1）。HiT 的出發點不同：一個 patch 一個 token 貫穿整個骨幹，不鼓勵模型在較粗的層級上總結內容，所以 HiT 把分組當作提升品質與訓練效率的手段，而不只是加速（HiT Sec. 1）。

    本節重點：一個 block 的 FLOPs 是 $C(L)=24Ld^2+4L^2d$（$m=4$）；$d=768$、$L=1024$ 時注意力二次項比例 $L/(6d+L)=18.2\%$；在 256–1024 個 token 下成本約與 token 數成正比，token 減半成本約減半；二次項要到數千個 token 以上才成為主項。

    檢查理解

    一個 block 的 FLOPs 怎麼寫？$d=768$、$L=1024$ 時注意力二次項占多少？token 減半時成本約如何變化？

    $C(L)=24Ld^2+4L^2d$（$m=4$）；二次項比例 $L/(6d+L)=18.2\%$；在 256–1024 個 token 下成本約與 token 數成正比，減半約減半，二次項到數千 token 才成為主項。

    04 · 第 0 期（2020–2021）

    第 0 期：沙漏結構讓中段在短序列上運算

    最早的問題來自語言模型：長序列讓 Transformer 太貴，但語言建模需要每個 token 都有輸出，所以縮短之後還得還原。Funnel-Transformer（2020）逐步把隱藏序列壓短，把省下的 FLOPs 用來加深或加寬模型；需要逐 token 輸出時，再以解碼器從短序列還原僅摘要。

    Hourglass（Nawrot 等人，2021）的結構是：shorten（以縮短係數 $k$ 把相鄰 token 合成一個）→ 中段 Transformer 只在短序列上運算 → upsample 並加上殘差 → 全長的 Transformer 層，所以兩端保持全長、只有中段變短。在自回歸設定下，縮短前要先把序列右移 $k-1$ 個 token，避免偷看未來（Sec. 2）。它的分組是固定步幅，與內容無關：每 $k$ 個相鄰 token 一組，不看那些 token 是什麼。

    Hourglass 也比較了三種上採樣（Sec. 2.3）：直接重複（無法區分組內位置）、線性上採樣（每個組內位置一個投影）、以及注意力上採樣 $x=U(x,x')+\mathrm{Attention}(Q=U(x,x'),K=V=x')$，其中 $U(x,x')=x+\mathrm{LinearUpsampling}(x')$。這個結構在 ImageNet32 影像生成達到 3.741 bits/dim（Sec. 3.4）。

    同期的 Perceiver IO（2021）走另一條路：以固定數量的 latent 向量經 cross-attention 讀入任意長度的輸入，在 latent 上運算，再以輸出查詢讀出，成本對輸入輸出長度呈線性僅摘要。它不做空間分組；RTI 在凍結骨幹上重實作的 Latent Array 基線同時失去了分組、連續與位置（RTI Sec. 4.2）。

    這一期證明「中段在短序列上運算、兩端保持全長」可行。限制是分組完全固定，與內容無關。

    檢查理解

    Hourglass 的結構是什麼？它的分組有什麼限制？

    shorten → 中段在短序列上運算 → upsample＋殘差 → 全長層，兩端全長；分組為固定步幅，與內容無關。

    05 · 第 1 期（2021–2022）

    第 1 期：ViT 分類以剪枝與合併減少 token

    Vision Transformer（ViT）對每個 patch 等量計算，背景 patch 也一樣。DynamicViT（2021）用一個預測模組估計每個 token 的重要性並剪掉不重要的 token；剪去 66% 的 token 時 FLOPs 降低 31%–37%，精度下降 0.5% 以內僅摘要。剪枝的缺點是被剪掉的資訊就消失了。

    ToMe（Token Merging，Bolya 等人，2022）改成合併。它在每個 block 中執行二部軟配對（bipartite soft matching）：ToMe 每層把 token 交替分成 A、B 兩個集合（程式碼中 A 取偶數索引、B 取奇數索引），每個 A 連一條邊到 B 中最相似的 token（以 key 的餘弦相似度衡量），保留最相似的 $r$ 條邊，把相連的 token 依大小加權平均合併，最後把兩個集合串回去（Sec. 3）。所以每層減少 $r$ 個 token，而且全部可以平行計算，不需要迭代的分群演算法。

    合併後，一個 token 可能代表好幾個原始 patch；記它代表的 patch 數為 $s$（token 大小）。若不處理，兩個相同的 key 合成一個後，在 softmax 中的權重就變小了。ToMe 的 proportional attention（Eq. 1）在注意力 logit 上加 $\log s$：

    $$A=\mathrm{softmax}\!\Big(\frac{QK^\top}{\sqrt d}+\log s\Big)$$
    ToMe Eq. 1

    本頁推導因為 $e^{\,q\cdot k/\sqrt d+\log s}=s\,e^{\,q\cdot k/\sqrt d}$，加 $\log s$ 等於把該 key（以及它的 value）複製 $s$ 份。下一節的 C1 會數值驗證這個恆等式。

    ToMe 能直接用在現成模型、不需要訓練：ViT-L@512 與 ViT-H@518 吞吐量提高 2×，精度下降 0.2–0.3%僅摘要。它在分類中不需要還原：分類只用 CLS token 的輸出，被合併的 token 不必回到原本的位置。這也是它的限制：把同樣的做法搬到需要每個 patch 都有輸出的擴散模型時，沒有還原機制；而且它只依外觀分組，不顧空間位置。

    本節重點：ToMe 每層把 token 交替分成 A、B 兩個集合，每個 A 連到最相似的 B（key 的餘弦相似度），保留最相似的 $r$ 條邊，依大小加權平均合併；proportional attention 加 $\log s$，等於把該 key 複製 $s$ 份；分類只用 CLS token 的輸出，被合併的 token 不必回到原位置，所以不需要還原。

    檢查理解

    ToMe 每層如何合併？為什麼要加 $\log s$？為什麼分類不需要還原？

    交替分成 A、B，每個 A 連到最相似的 B（key 餘弦），保留最相似的 $r$ 條邊，依大小加權平均合併；加 $\log s$ 等於把該 key 複製 $s$ 份；分類只用 CLS token，被合併的 token 不必回到原位置。

    06 · 第 2 期（2023–2024）

    第 2 期：擴散的稠密輸出需要把合併還原

    擴散模型要對每個 token 預測，CFG 每步要跑兩個分支，而且同一張圖在幾十個取樣步中重複計算。以下把被併入別人的 token 稱為 src，接收的 token 稱為 dst；把合併結果送回原本每個位置的動作稱為 unmerge。

    ToMeSD（Bolya 與 Hoffman，2023）在每個元件（self-attention、cross-attention、MLP）之前合併、之後 unmerge。它的 unmerge 是直接複製：若 $x^*_{1,2}=(x_1+x_2)/2$，則 $x'_1=x'_2=x^*_{1,2}$（Sec. 3.1，Eq. 1）。ToMeSD 的 unmerge 把合併結果複製回所有來源位置，同一組的 token 因此完全相同。它也改以比例 $r\%$ 取代固定個數。

    分割方式（Sec. 4.1）：ToMe 的交替分割使 dst 形成規則的欄位，等於沿列方向把解析度減半。ToMeSD 因此改用隨機 2×2 dst——每個 2×2 區域隨機挑一個 dst——並且在整個 batch 固定隨機性，讓 CFG 的條件與無條件分支以相同方式配置 dst，兩個分支才一致。設計實驗顯示只對 self-attention 合併最划算（Tab. 3）。ToMeSD 在 SD v1.5、512² 上的結果（Tab. 4）：基線 FID 33.12、每張 3.09 秒；$r=50\%$ 時 FID 33.02、每張 1.65 s/im；$r=60\%$ 時 FID 33.37、1.52 s/im。

    ToDo（2024）換一個假設：空間相鄰的 token 本來就相似，所以用最近鄰下採樣 $D(\cdot)$ 取代相似度配對，成本 $O(n)$（Sec. 2.2）。更重要的是它只對 key、value 下採樣，保留全部 query：

    $$\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\!\Big(\frac{Q\,D(K)^\top}{\sqrt{d_k}}\Big)D(V)$$
    ToDo Sec. 2.2

    ToDo 只對 K、V 下採樣、保留全部 query，每個 query 仍各自得到一個輸出，輸出仍是全長，所以不需要 unmerge。ToDo 的合併比例 0.75、0.89 指被移除的比例，等於 2×、3× 下採樣（Sec. 3）。同期的 AT-EDM 以注意力圖排序剪枝並依去噪步調整剪枝預算，Importance-Based Token Merging 以 CFG 等現成訊號保護重要 token僅摘要。

    這一期第一次把 token 縮減用在稠密生成上而不需訓練，並開始處理 CFG 與時間步。限制是群組仍由外觀相似度決定，可能把畫面兩端的 patch 併在一起；unmerge 是純複製；ToDo 只省注意力項。

    縮減的位置決定加速上限

    本節用到兩種配置。RTI 改造的 MiniT2I-B/16 有 17 個 block：前 3 個與後 3 個保持全解析度，中間 11 個（核心）在縮短的序列上運算，記作 3＋11＋3（RTI Sec. 3.2）。HiT 有 18 個 block，分成 3/3/6/3/3 五段：最外兩段全解析度，中間兩段縮一次，核心再縮一次（HiT Sec. 3.1；細節在 S10、S13）。每種策略都和「相同 block 數的稠密模型」比較。

    Amdahl 定律指出：只加速系統的一部分時，總加速受不加速部分的比例限制。RTI B/16 的 3＋11＋3 個 block 只縮中段時，即使核心的成本降到 0，兩端 6 個 block 仍要全長計算，所以不計文字時加速上限是 $17/6=2.83\times$：3＋11＋3＝17 個 block，若中段 11 個的成本為 0，仍剩下 6 個全長 block，稠密成本 17 除以剩下的 6 就是上限 $17/6$。RTI B/16 在 $R=256$（$\kappa=0.25$）實測 2.15×，加速約在 2.5× 飽和（Tab. 1、Sec. 4.2）；實測高於本頁 FLOPs 模型的 2.03×，因為牆鐘時間比 FLOPs 下降得快（App. A）。文字流全長也是 RTI 上限的一部分：$n_{\text{txt}}=256$ 時模型上限降為 2.17×（RTI Sec. 5 把文字流列為限制）。

    08 · 第 3 期（2022–2025）

    第 3 期：學得的路由讓比例可學，但刪除而非總結

    免訓練方法的比例要手調，而且與層、時間步無關。這一期的代表做法是讓模型學「哪些 token 要算」。Mixture-of-Depths（MoD，2024，語言模型）在每層放一個 router，選出 top-$k$ 個 token 進入注意力與 MLP，其餘 token 沿殘差流直接跳過這一層。DiffCR（2024）把同樣的想法用在 DiT：每層一個 router 預測 token 重要性，並讓每層、每個時間步的壓縮比例也可微地學出來；在 PixArt-Σ 上品質與未壓縮模型相當，同時省下 20.68% 延遲與 8.33% 記憶體（Sec. 4）。

    學得路由（MoD、DiffCR）屬於跳過，也就是刪除：未被選中的 token 沿殘差流繞過 block，不被總結，它們的資訊不參與這一層的計算。RTI 在凍結的 MiniT2I 上重實作了這類方法（Token Skip）：GenEval 82.3，只有 1.19× 加速，比 RTI（2.15×）低 2.4 點；作者指出 Token Skip 的 576 個 token 不是同一種預算，而它的速度又慢得多，所以 2.4 點低估了差距（Tab. 1、Sec. 4.2）。

    其他同類方法只列出：DyDiT 依時間步調整寬度並跳過不必要的空間位置，DiT-XL FLOPs 降低 51%、加速 1.73×；FlexiDiT 把預訓練 DiT 轉為多預算模型；Sparse Guidance 以 token 稀疏度作為引導訊號僅摘要。架構層級的 RIN 以一組 latent 承擔全域注意力，U-ViT 以長 skip 連接淺層與深層僅摘要。它們在 S14 的對照表中各占一列。

    第 4–5 期：像素擴散用固定網格，動態切塊讓切分可學

    第 4 期：pixel-space 擴散的回歸。latent 擴散依賴另外訓練的 VAE；直接在像素上建模則 token 太多。HDiT（Crowson 等人，2024）把 Hourglass 結構帶到像素擴散：編碼端每一層以 Pixel-UnShuffle 把 2×2 個 token 合併成一個，解碼端以 Pixel-Shuffle 拆開，skip 以可學係數線性插值（lerp）合併；高解析度層用鄰域注意力、最內層用全域注意力，整體成本對像素數為 $O(n)$，在 FFHQ-1024² 達到 FID 5.23（Tab. 3）。RTI 與 HiT 都沒有引用 HDiT，本頁依主題補入。JiT（2025）則以 x-prediction 搭配大 patch（16、32）的單純 Transformer 在像素上生成僅摘要。JiT 用大 patch（16、32），HDiT 用固定 2×2 Pixel-UnShuffle 合併的沙漏結構，兩者控制 token 數的方式都與內容無關：平坦的天空與細節多的招牌分到同樣多的 token。這是 RTI 與 HiT 的共同起點。

    第 5 期：內容自適應的切分。Quadformer 以 quadtree 產生大小不一的 patch，BLT 依下一個 byte 的熵切出長度不一的 patch僅摘要。H-Net（Hwang 等人，2025）讓切塊與主任務一起訓練。它的 routing（Eq. 4）以兩個學得投影 $q_t=W_q\hat x_t$、$k_t=W_k\hat x_t$ 比較相鄰向量：

    $$p_t=\tfrac12\Big(1-\frac{q_t^\top k_{t-1}}{\lVert q_t\rVert\,\lVert k_{t-1}\rVert}\Big)\in[0,1],\qquad b_t=\mathbb 1\{p_t\ge0.5\}$$
    H-Net Eq. 4

    H-Net 以相鄰向量的餘弦決定邊界：$p_t=\tfrac12(1-\cos(q_t,k_{t-1}))$ 是邊界機率，$p_t\ge0.5$ 的位置就是邊界（$p_1=1$）。downsampler 只保留邊界位置的向量；還原時先以 EMA 平滑，再把每個壓縮向量重複到下一個邊界，並乘上 straight-through 的信心值（Sec. 2.2）。壓縮程度由 ratio loss（一個額外的損失項：實際切塊比例偏離目標時變大）控制（Sec. 2.2.3，Eq. 10）：

    $$\mathcal L_{\text{ratio}}=\frac{N_{\text H}}{N_{\text H}-1}\big((N_{\text H}-1)FG+(1-F)(1-G)\big)$$
    H-Net Eq. 10

    其中 $N_{\text H}$ 是目標壓縮比（論文記為 $N$），$F$ 是實際被選為邊界的比例（不可微），$G$ 是平均邊界機率（可微）；$F=G=1/N_{\text H}$ 時損失達到最小值 1。這個 ratio loss 只控制平均比例：個別序列的切塊數可以多於或少於目標。

    這一期讓 token 數隨內容變化，並證明切塊可以和主任務一起訓練。限制是 H-Net 處理一維序列；tokenizer 類方法改變輸入表示，不能用在已釋出的 checkpoint（RTI Sec. 2）。

    本節重點：JiT 用大 patch（16、32），HDiT 用固定 2×2 Pixel-UnShuffle 合併的沙漏結構，兩者都與內容無關；H-Net 以相鄰向量的餘弦 $p_t=\tfrac12(1-\cos(q_t,k_{t-1}))$ 決定邊界，$p_t\ge0.5$ 為邊界，ratio loss 只控制平均比例。

    第 6 期：三種分組規則——固定網格、Hilbert 切割、平均連結

    2026 年的方法在擴散 Transformer 中加入彈性或自適應的 token。ELIT 在 DiT 中插入可變長度的 latent 介面，以 Read、Write 兩個 cross-attention 在空間 token 與 latent 之間搬移資訊；為了省成本，它把空間 token 分成固定網格的群組，訓練時隨機丟棄尾端 latent，使一個模型支援多種預算（彈性預算）。DC-DiT 把 H-Net 式的動態切塊帶到 2D latent DiT，router 以局部可預測性給出邊界機率。以下用三條規則說明這一期的分組選擇。

    11 · 預算與量測

    預算型態與兩個量測：EV 與連通性

    比較分組規則需要量測。記 patch $j$ 所屬的組為 $c(j)$，組內特徵平均為 $\bar h_{c(j)}$，全部 patch 的平均為 $\bar h$。RTI 用保留變異 EV（App. C.1，Eq. 5）衡量「用組平均代表每個 patch」後還剩多少資訊：

    $$\mathrm{EV}=1-\frac{\sum_j\lVert h_j-\bar h_{c(j)}\rVert^2}{\sum_j\lVert h_j-\bar h\rVert^2}$$
    RTI Eq. 5

    EV = 1 表示組平均完整攜帶原本的特徵，EV = 0 表示不比一個常數好。另外兩個量測看位置：spread 是每個 patch 到其組中心的平均距離（單位為格；本頁對全部 patch 平均，RTI Tab. 4 對每組平均）；連通組比例是在格子上相連成一塊的組所占的比例。

    分組規則也決定預算型態（軸 F）。RTI 每張精確 $R$ 個區域；固定網格與 ToMe 式合併也是每張固定個數。門檻法則不同：HiT 的群組數由門檻與內容決定，只有整個批次的平均保留比例受壓縮損失約束（Eq. 4，目標 $\rho=1/r$），門檻 $\tau$ 在訓練前以 1,024 個雜訊樣本校準後凍結（Sec. 4.1）。所以 HiT 單張影像、單個時間步的群組數可以多於或少於目標。

    RTI 量到相似度分組的代價：以 ToMe 式相似度分組（Feat Sim）在同一介面中取代 Hilbert 區域，Feat Sim 的群組散布 5.16 格，RTI 只有 0.49 格（Tab. 4，$R=256$），GenEval 低 4.2 點（Sec. 4.2）。RTI 的結論是失去連續性就失去位置。

    12 · 還原

    還原方式決定同一組內能否各自更新

    縮短的核心只為每一組產生一個結果，但擴散模型要對每個 patch 輸出（軸 D）。進入縮短段之前每個 patch 的特徵稱為核心前特徵，記為 $h_j$。前面各期出現過五種還原：不需要（分類）、複製回來源（ToMeSD 的 unmerge，也稱廣播，broadcast）、殘差寫回、skip connection（U-ViT、HDiT 的 lerp、HiT 的投影 skip），以及 Hourglass 的注意力上採樣。

    本頁推導廣播只能讓同組共用一個更新：同一組的 patch 拿到同一個值。若第 $j$ 個 patch 的理想輸出是 $y_j$，同組共用一個值時，最好的選擇是組平均 $\bar y_{c}$，最小誤差就是目標在組內的變異 $\sum_c\sum_{j\in c}\lVert y_j-\bar y_c\rVert^2$。殘差寫回則保留每個 patch 的核心前特徵，並據此個別化更新。RTI 的 WRITE（Eq. 4）是

    $$h_j^{\text{out}}=h_j^{\text{in}}+g\big([\,h_j^{\text{in}}\,\Vert\,z'_{c(j)}-z_{c(j)}\,]\big)$$
    RTI Eq. 4

    其中 $h^{\text{in}}$、$h^{\text{out}}$ 是核心前、後的特徵（論文以層索引 $s_0$、$s_1+1$ 表示），$z_c$、$z'_c$ 是區域 token 進、出核心時的值，$g$ 是小型可學映射：每個 patch 以自己的特徵與區域的變化量產生自己的更新。HiT 則以同一組軟權重把核心處理後的群組特徵混回每個 token（軟混合：每個 token 得到所有群組結果的加權平均，權重是它對各群組的軟指派），再加上一個投影 skip（把核心前的特徵乘上一個可學的線性投影後直接加回，HiT 初始化為恆等）。

    哪個消融只改還原？HiT 只改讀回方式的消融：把軟混合換成硬查表（每個 token 只取自己所屬群組的結果），FID 由 6.61 惡化為 7.97（Tab. 3）。RTI 以平均池化＋廣播取代整個 READ/WRITE，GenEval 低 7.2（Sec. 4.3），但這同時改變了池化與還原，不能只歸因於還原。

    純玩具，不是 RTI 或 HiT 的行為：目標 y 為乾淨風景 patch，核心前特徵 h 為取樣狀態 x_t 的 patch（原始像素），分組沿用 C3 的方法與 R，並假設核心對每組恰好輸出目標的組平均。只示範廣播的誤差下界與殘差路徑的作用。

    x_t（核心前）
    還原結果 ŷ(β)

    還原：ŷ_j(β) = ȳ_c + β(h_j − h̄_c)。β = 0 為廣播；β = 1 為殘差加回，與 RTI Eq. 4 只是類比（Eq. 4 的 g 作用在串接上、為學得映射）；β* 為最小平方最佳。相對誤差 E(β) 以「全部用一個平均值」的誤差為分母。E(0) = 1 − EV（以目標計算）與 E(β*) ≤ min(E(0), E(1)) 為本頁推導。

    在這個玩具中（RTI 分組、$R=32$），$t=1$ 時廣播留下 9.85% 的組內變異，$\beta=1$ 的誤差為 0；$t=0.95$ 時三者為廣播 0.0985、殘差 0.0347、最佳 $\beta^*=0.760$ 時 0.0277。換成固定網格，廣播誤差升到 0.2768，殘差誤差幾乎不變（0.0353）：廣播的誤差直接由分組決定，殘差路徑讓分組的影響變小。原始像素帶有噪聲，所以 $t=0.8$ 時 $\beta^*$ 降到 0.127。

    本節重點：廣播只能讓同組共用一個更新，最小誤差是目標在組內的變異；殘差寫回保留每個 patch 的核心前特徵並據此個別化更新；只改還原的證據是 HiT 的消融：硬查表讀回 FID 7.97，軟混合 6.61；RTI 的 −7.2 同時改了池化與還原。

    廣播（unmerge）的最小誤差是什麼？殘差寫回多了什麼？哪個消融只改還原？

    廣播只能讓同組共用一個更新，最小誤差是目標在組內的變異；殘差寫回保留每個 patch 的核心前特徵並據此個別化更新；HiT 只改讀回方式的消融：硬查表 FID 7.97 對軟混合 6.61（RTI 的 −7.2 同時改了池化與還原）。

    13 · RTI 與 HiT

    RTI 與 HiT 在八個設計軸上的選擇對照

    RTI 的目的是推論加速：凍結骨幹＋LoRA 加速，只訓練 rank-32 的 LoRA 與 READ/WRITE（B/16 可訓練參數 16.3M，5.9%）；分組是無參數的 Hilbert 連續區域；預算是每張精確 $R$ 個，訓練時每步自 {64, 128, 256, 512} 隨機抽 $R$，所以一個 checkpoint 支援任意預算（彈性），連未見過的預算也能用；位置以區域內 patch 的平均 RoPE 相量表示。結果（Tab. 1，512²）：B/16 稠密 GenEval 87.2，RTI $R=512$ 為 87.8（1.84×）、$R=256$ 為 84.7（2.15×）；L/16 在 $R=256$ 為 86.3（2.59×）。

    HiT 的目的是品質與訓練效率：從頭訓練求品質；分組用學得親和度＋平均連結、可非局部；預算是批次平均、單張可變；compact 層預設不加 RoPE。結果：ImageNet-256 上 HiT-XL/16 在 600 epochs 達到 FID 1.48（Tab. 1），FID ≈ 2.16 時訓練計算比 JiT-H/16 少 2.4×（Fig. 1d）；文字到影像 512² 五項平均 65.93，MiniT2I-B/16 為 64.64，名目 GFLOPs 139.4 對 201.6（乘加計 1、以目標群組數計，Tab. 2、Sec. 4.1）。學得分組優於固定空間配對（FID 6.61 對 7.11，Tab. 7）。

    分組必須空間連續嗎？

    −4.2RTI：相似度分組（Feat Sim）比 Hilbert 區域低的 GenEval 點數，散布 5.16 格對 0.49 格

    這兩個結果看起來指向不同方向，但不能直接比較。RTI 的對照是凍結骨幹上的免學習相似度分組，骨幹依賴 RoPE；HiT 的對照是形狀固定的空間配對（第一階段水平、第二階段垂直，本身連續），而且 HiT 的軟池化讓每個 token 都能貢獻給每個群。兩篇都沒有在同一設定下比較「內容自適應且連續」與「學得且非局部」兩種分組。

    3. 合併 token 的位置表示仍無定論：HiT 各位置變體的差距小。
    4. 與步數縮減的關係：RTI App. B.3（Fig. 7，MiniT2I-L/16、$R=256$）中，每張影像低於約 3 秒時 token 壓縮優於減少步數（1.8 秒：少步稠密 GenEval 65.9、RTI 82.7），高於約 5 秒時相反（11.2 秒：稠密 87.6、RTI 86.3）。
