# R-Zero 設計文件 fidelity review

驗證腳本 c1/c2/c3/data_check 皆已執行。輸出與 design.md 第 5 節的驗收表一致（C2 的 nltk/sklearn 交叉檢查在系統 python 下跳過，未重跑）。下列問題都在腳本範圍之外。

1. **P0 步驟 9「題目難度與偽標籤正確率」。** 原文：「固定的 Step-15 Solver 在三輪題目上的正確率 59.0 → 57.0 → 47.0」。論文 Table 5 的 Solver (step 15) 欄是 59.0（D15）、53.0（D30）、47.0（D45）。57.0 是 Solver (step 30) 在 D15 的值，所以這段取錯了格。Sec. 4.4 文字只引了 59.0 與 47.0。修正：59.0 → 53.0 → 47.0。

2. **P1 C3 讀者應觀察 (5)。** 原文：「長條上的 P(正確|c) 隨 c 增加」。我用 `c3_enum.py` 的函式檢查，這只在正確答案是最常見答案時成立。q=0.3、K=3、s=0.5 時 P(正確|c) 為 .29→.36（c=5）→.18（c=10），先升後降。K=1、q=0.3 時，c=5..10 為 .50、.16、.03、.01、0、0，單調下降。步驟 5 引用的 K=5、s=0.2、q=0.3 是少數支持 Sec. 2.3「低一致性不可靠」的設定。修正：改寫為「取決於正確答案是否為最常見答案」，並說明在一致錯誤的區域，c 越高標籤越不可靠。這與論文的品質控制說法相反。

3. **P1 1.3「貢獻（作者列出的三項）」。** 論文 Intro 沒有列出貢獻清單，全文也沒有 "contributions" 一詞（只在 Sec. 4.1 出現 "contribution of each key component"）。這三項是設計者的歸納。修正：改標「本文件整理」，或刪除「作者列出」。

4. **P1 LO4 / 步驟 2 的 App. F。** 論文 App. F 說下界是針對 Solver 的 success probability，前提是熵正則化的最佳策略 S*、二元獎勵，且 β 是熵正則化溫度。論文直接把這個 p̂ 換成多數決一致性比例。但一致性比例不是對真實答案的成功率，而 App. F 的設定需要的是後者。design 已說「引用、未證明」，但沒說理論的 p̂ 與實作的 p̂ 並不同義。修正：LO4 參考答案加一句這個前提與落差。

5. **P2 C2 讀者應觀察 (1)。** 原文：「第 1、2 題…在任何門檻都同群」。滑桿範圍是 0.10–0.95，而 d12=0.151（來自 c2 輸出），所以 τ≤0.15 時兩題不會合併。修正：改為「τ>0.15 時」，或把滑桿下限提高到 0.20。

6. **P2 步驟 3 / LO5「群組不產生梯度」。** 論文 App. I.1 的損失含 βKL 項。獎勵全同時，策略梯度項為零，但 KL 項在多步更新中仍有梯度（只在 π_θ=π_old 的那一刻梯度為零）。修正：寫成「優勢為 0，策略梯度項為零」。

7. **P2 步驟 9 Table 4。** 原文「優於單用任一種」。論文只用文字陳述這句，沒有給平均欄。Table 4 的逐項數字中 Human 在 AMC、Minerva、Olympiad 較高，我計算的數學平均是 Human 50.55、R-Zero+Human 51.03。Table 4 的 Human 平均 50.55 與 Fig. 4 的虛線基準 48.99 也不一致，design 沒提到。修正：加註「論文文字陳述，Table 4 逐項並非全勝」，並把這個不一致列入 R1。

8. **P2 「多數決」用詞。** 論文是 "most frequent response"（plurality），不要求過半。c=3 時也叫「多數決」，可能讓讀者以為需超過 50%。修正：S2 首次出現時寫明「出現最多次，不必過半」。

9. **P2 步驟 10「實作常見錯誤」。** 八條中第 8 條（監控外部驗證集）與第 5 條的理由是設計者的建議，論文沒寫，但條目沒有標籤。修正：標〔本頁建議〕，避免讀成論文結論。

10. **P2 步驟 5 〔本頁推導〕。** 原文：「70% 機率給同一錯誤答案，c 常落在 6–8，題目通過篩選」。c=8–10 的機率約 38% 會被篩掉（pass=0.616，來自 c3 輸出）。數字有給，但語氣偏強。修正：加「約六成通過」。

11. **P2 C4 / Table 7。** 論文寫 500 題取自「a later training iteration」，卻給了 Step 15–60 四欄。design 把四欄畫成逐步曲線，也沒說明這個口徑模糊。另外 Table 5（GPT-4o，79.0%）與 Table 7（Gemini，71.0%）不可混用，R2 已記。修正：C4 假設行註明「標註樣本口徑論文未明確」。

12. **P2 檔頭第 5 行。** 「`tut/32/notes/` 目前尚未產生」已過時，notes 目錄已有 8 個 md 與 timeline.json。修正：更新，並移除 6.3 的佔位降級方案。

13. **P2 1.1 與 LO10。** 「Abstract、Fig. 3、Table 3」作為 42.58 → 49.07 的出處。Abstract 只給 +6.49，沒有 42.58 與 49.07 這兩個數字。修正：出處改為 Fig. 3、Table 3，並註明 Abstract 的 +6.49 與之吻合。
