## 2. 教師必須算對的 5 個推導

### 2.1 低溫取樣 ≠ 冪分佈（式(4)–(8)）

固定前綴 x_<t。

- 冪分佈的條件分佈，式(4)(7)：p_pow(x_t|x_<t) ∝ Σ_{x_>t} p(x_0,…,x_T)^α （次方的和）
- 由式(5)，p(x_t|x_<t) = Σ_{x_>t} p(x_{0:T}) / Σ_{x_≥t} p(x_{0:T})，所以低溫，式(6)(8)：p_temp(x_t|x_<t) ∝ ( Σ_{x_>t} p(x_0,…,x_T) )^α （和的次方）

〔顧問推導〕把聯合分佈拆成 p(x_<t)·p(x_t|x_<t)·p(x_>t|x_≤t)，前綴項是常數，可得

  p_pow(x_t|x_<t) ∝ p(x_t|x_<t)^α · F(x_≤t)， F(x_≤t) = Σ_{x_>t} p(x_>t|x_≤t)^α

也就是「冪分佈 = 低溫權重 × 未來修正項 F」。α≥1 時 0<F≤1，F=1 當且僅當選了 x_t 之後未來只有一條路。低溫取樣等於把所有 F 當成 1。這一行是整篇論文最值得教的式子。

成立條件與例外〔顧問推導〕：
- 論文的證明只指出兩個式子形式不同，真正的反例是 Example 1。
- 兩者會相等的情形：α=1；每個候選 token 的 F 相同（例如未來都是確定的，或 p 在序列上均勻）；最後一個位置 t=T（沒有未來，F≡1）。所以論文證明裡「在每個時間步 t 都不同」這句話在 t=T 不成立。
- 式(5)論文稱為「Bayes rule」，其實是條件機率定義加邊際化。

### 2.2 Example 1 的數字（α=2.0）

論文給的：p(aa)=0.00、p(ab)=0.40、p(ba)=0.25、p(bb)=0.25；p(x_0=a)=0.40、p(x_0=b)=0.50。

- p_pow(x_0=a) ∝ 0.00²+0.40² = 0.160；p_pow(x_0=b) ∝ 0.25²+0.25² = 0.125 → 偏好 a
- p_temp(x_0=a) ∝ (0.00+0.40)² = 0.160；p_temp(x_0=b) ∝ (0.25+0.25)² = 0.250 → 偏好 b

〔顧問推導〕正規化後與延伸：
- 這四個機率加起來是 0.90，不是 1（見第 3 節）。排序結論不受影響，因為兩邊都只比相對權重。
- 正規化的第一個 token 機率：冪分佈 a = 0.160/0.285 = 0.561；低溫 a = 0.160/0.410 = 0.390。
- 整條序列：冪分佈 ab=0.561、ba=bb=0.219；低溫 ab=0.390、ba=bb=0.305。注意低溫下 ab 仍是機率最高的單一序列，差別在於低溫把 61% 的質量放到 b 開頭的序列。
- α 的臨界值：冪分佈偏好 a ⇔ 0.4^α > 2·0.25^α ⇔ 1.6^α > 2 ⇔ α > ln2/ln1.6 ≈ 1.475。
- 若要一個總和為 1 的雙 token 版本：p(ab)=0.45、p(ba)=p(bb)=0.275 可用（0.2025 對 0.15125）。直接把 0.25 改成 0.30 不行（0.16 對 0.18，結論反轉）。一般條件是 0.5 < ε′ < 1/(1+2^{−1/2}) ≈ 0.586。

### 2.3 Proposition 3（式(14)(15)）

設定：positive pivotal token x_t 邊際權重 ε，只有 1 條未來，該序列 likelihood 為 ε；negative pivotal token x′_t 邊際權重 ε′，均分到 N 條未來，每條 ε′/N。

- 冪分佈權重：x_t 為 ε^α；x′_t 為 N·(ε′/N)^α = ε′^α / N^{α−1}
- 低溫權重：ε^α 對 ε′^α
- 冪分佈偏好 x_t ⇔ ε^α > ε′^α/N^{α−1} ⇔ ε > ε′/N^{1−1/α}
- 低溫偏好 x′_t ⇔ ε < ε′
- 合起來是式(14)：ε′/N^{1−1/α} < ε < ε′
- 式(15)：ε′/N^{1−1/α} > ε′/N，所以式(14)也保證 ε > ε′/N，即 x_t 的那條未來比 x′_t 的任何一條都高。

條件〔顧問推導〕：式(15)的嚴格不等號需要 N>1。α=1 時式(14)的區間是空的。α→∞ 時下界趨近 ε′/N。用 Example 1 驗算：ε=0.4、ε′=0.5、N=2、α=2，下界 0.5/√2=0.354 < 0.4 < 0.5，成立。

「upweight」一詞有兩種意思〔顧問推導〕：論文指的是兩個 token 的相對排序（誰權重大）。若改問「相對於 base 的比值 ε/ε′ 是否變大」，冪分佈的條件是較寬的 ε > ε′/N，低溫則在 ε<ε′ 時一律變小。教學時固定用論文的意思，不要混用。

### 2.4 Algorithm 1 的接受率（式(9)）

式(9)：A(x, x^i) = min{1, [p^α(x)·q(x^i|x)] / [p^α(x^i)·q(x|x^i)]}。

對隨機重取提議，選到位置 m、目前區塊結尾為 L=(k+1)B：
- q(x′|x) = (1/L)·∏_{t=m}^{L} p_prop(x′_t|x′_<t)，反向 q(x|x′) = (1/L)·∏_{t=m}^{L} p_prop(x_t|x_<t)
- x 與 x′ 在 m 之前相同，p 的前綴項與 1/L 相消

  比值 = ∏_{t=m}^{L} [ p(x′_t|x′_<t)^α / p_prop(x′_t|x′_<t) ] ÷ ∏_{t=m}^{L} [ p(x_t|x_<t)^α / p_prop(x_t|x_<t) ]

〔顧問推導〕代入論文在推理任務用的設定 p_prop = base model 配溫度 1/α，即 p_prop(v|x_<t) = p(v|x_<t)^α / Z_t(x_<t)，Z_t(x_<t) = Σ_v p(v|x_<t)^α：

  比值 = ∏_{t=m}^{L} Z_t(x′_<t) / Z_t(x_<t)

每個 token 自己的 p^α 全部相消，只剩每一步低溫分佈的正規化常數。Z_t 越大表示那一步的 next-token 分佈越尖。寫成 Rényi 熵 H_α：Z_t = exp(−(α−1)H_α)，所以新後綴的逐步 Rényi-α 熵總和較低時必定接受。這與 2.1 的修正項 F 是同一件事，也和 Fig. 4 右圖的 confidence（式(13)，用的是 Shannon 熵）方向一致。

用 Example 1 驗算〔顧問推導〕：a 之後的分佈是 (0,1)，Z=1；b 之後是 (0.5,0.5)，Z=0.5。低溫提議給 a 0.390、b 0.610；乘上 Z 得 0.390 對 0.305，正規化後 a=0.561，等於 2.2 的冪分佈。

條件與注意：
- 上面的化簡只在 p_prop 的溫度正好是 1/α 且與目標用同一個模型時成立。AlpacaEval 用 τ=0.5，化簡後還會留下 p 的次方項。
- 同一個 x′ 可由多個 m 產生（m 落在 x 與 x′ 的共同前綴內也可以），真正的 q 是對 m 求和。演算法用的是「已選定的 m」那一項的比值。這仍然正確，因為 m 的選取與狀態無關，每個固定 m 的核各自滿足 detailed balance，混合後也滿足〔顧問推導〕。論文沒有討論這點，只說「by symmetry」。
- MH 正確性的一行證明（論文沒寫，引用 Neal 1993）〔顧問推導〕：π(x)q(x′|x)A(x′,x) = min{π(x)q(x′|x), π(x′)q(x|x′)}，對 x、x′ 對稱，所以 π 是平穩分佈。
- 計算上不需要額外的 forward pass：生成新後綴時同一份 logits 同時給出 p 與 p_prop 的值，目前狀態的值可以快取〔顧問推導，論文未說明〕。

### 2.5 Token 成本（式(12)）

式(12)：E_tokens = N_MCMC · Σ_{k=1}^{⌈T/B⌉} kB/2 ≈ N_MCMC·T²/(4B)。
推導：Σ_{k=1}^{K} kB/2 = (B/2)·K(K+1)/2 ≈ BK²/4，代入 K=T/B。
相對於一般推論的倍數 = N_MCMC·T/(4B) = 10×679/(4×192) = 8.84（與論文相符）。

〔顧問推導〕這個近似在論文自己的參數下偏低：
- K=⌈679/192⌉=4，Σk=10，而近似用的 K²/2=(3.54)²/2=6.26。
- 照式(12)的精確和：10×96×10 = 9600 token，9600/679 ≈ 14.1 倍。
- 把最後一個區塊截到 679：10×(192+384+576+679)/2 = 9155，≈ 13.5 倍。
- 都還沒算每個區塊初始化延伸的 token（共約 T 個，再加 1 倍）。
- 成本與 T² 成正比，用平均長度 679 代入會低估平均成本（E[T²] ≥ E[T]²）。
- T=T_max=3072 時，近似給 40 倍。
教學時可說「論文報告 8.84 倍；照它自己的求和式精確算約 13–14 倍」，並標明後者是推導。

## 3. 常見誤讀、內部不一致、未說明之處

### 3.1 從摘要或圖看起來成立、但論文沒有顯示的事

1. 「取樣法打敗 RL」。Table 1 在 MATH500（GRPO 的訓練領域）上，兩個 Qwen 模型都是 GRPO 較高：0.748 對 0.785、0.706 對 0.740。GPQA 兩個 Qwen 也是 GRPO 較高：0.389 對 0.399、0.318 對 0.354。只有 Phi-3.5 在這兩欄贏。
2. Phi-3.5 的 GRPO 基線很弱。MATH500 上 GRPO 0.406 對 base 0.400，HumanEval 上 GRPO 0.134 低於 base 0.213。文中的「+59.8%」（0.732−0.134）是對一個比 base 還差的基線算的。
3. 「+25.2%」「+51.9%」是百分點，且是對 base（未說明溫度，推測為 1）的差。對低溫基線的增量小得多：Qwen2.5-Math 的 MATH500 是 0.690 → 0.748（+5.8 點），而低溫取樣只花 1 倍 token。
4. 低溫不總是輸。Phi-3.5 的 AlpacaEval：低溫 18.15 高於 power sampling 17.65。「consistently outperforms on AlpacaEval」只對 GRPO 成立。
5. 「演算法從 p^α 取樣」。Algorithm 1 的 Output 寫 ∼p^α，但那是 N_MCMC→∞ 的極限。實驗用 N_MCMC=10，論文沒有任何 mixing 診斷，也沒有量測輸出離 p^α 多遠。§5.3 自己說步數越少離目標越遠。
6. 「冪分佈證明了能規劃」。Prop. 3 只在單一未來對 N 條均勻未來的極端模型下成立，而且比較的是 likelihood，不是正確性。
7. 「高 likelihood = 正確」。Fig. 4 是相關性；§5.3 明說直接最大化 likelihood 不一定對推理最好，α=4.0 是中間值。
8. 「dataset-free、不需調參」。α、B、N_MCMC 是在 MATH500（測試集）上掃出來的（Fig. 6）；AlpacaEval 另換提議溫度，HumanEval 的 pass@k 另換 α=1.67。
9. 「成本和 GRPO 一個 epoch 差不多」。這是假設每題 8 個 rollout、資料集一樣大的估計；GRPO 是一次性成本，power sampling 是每次查詢都要付。論文也沒有報告延遲，MH 是循序的。
10. Fig. 1 右圖的 Score（1.61、2.38、2.88）是 AlpacaEval 2.0 的長度校正勝率（對 GPT-4-turbo），單位是百分比，Qwen2.5-Math 的絕對值很低。不要畫成和左圖同尺度的準確率。
11. 「single-shot」指最後只交一個答案、沒用驗證器；生成過程中其實產生了許多候選。
12. Algorithm 1 第 10 行「fix the new prefix」容易讀成前面的區塊被凍結。第 5 行的 m 是在 {1,…,(k+1)B} 均勻抽，所以較早的 token 在後面階段仍會被重取；前一階段的結果只是初始化。
13. 中間目標 π_k ∝ p(x_{0:kB})^α 是「前綴邊際的 α 次方」，不是 p^α(x_{0:T}) 在前綴上的邊際。這正是 Prop. 1 的同一個差別，發生在區塊層級〔顧問推導〕。因為前綴沒有被凍結，漸近上不影響正確性，但有限步數下是偏差來源。

### 3.2 內部不一致

- 式(2)寫 α∈[1,∞]。α=1 時兩邊相等，嚴格不等號不成立；應為 α>1。
- Example 1 的機率總和是 0.90（p(x_0=a)+p(x_0=b)=0.90）。
- Prop. 1 的證明說每個時間步的條件分佈都不同；t=T 時相同（見 2.1）。
- Algorithm 1 第 3 行說要從 π_{k+1} 取樣，第 7 行的接受率卻寫 π_k。應為 π_{k+1}。
- 式(12)上方的文字說取樣 π_k 時每步平均重取 kB/2；照 Algorithm 1 的索引，第 k 圈（從 0 起算）的序列長 (k+1)B。求和從 k=1 到 ⌈T/B⌉，兩者對得上，只是索引偏一格。
- x_{0:kB} 有 kB+1 個 token，論文稱「長度 kB」。§4.2 抽 t∈[1,T] 機率 1/T，所以 x_0 永遠不重取（未說明 x_0 是否代表 prompt）。
- 式(9)寫 A(x, x^i)，Algorithm 1 寫 A(x′, x)；鏈的上標 x^0,…,x^n 與 token 下標 x_0 容易混淆；Algorithm 1 的 p_prop(x|x′) 沒有正式定義。
- Fig. 5 圖說稱曲線「strictly better than both GRPO and the base model」；k=1 時依 Table 1 是 GRPO 較高（0.785 對 0.748），內文寫的是「for k>1」。
- 附錄 A.2 把 α=1.67 稱為「this temperature」。
- 附錄 A.2：HumanEval 上 GRPO 的 pass@k 直到 k=16 都高於 base，與「RL 喪失多樣性」的說法在這個基準上不一致，論文自己承認並給了猜測（程式題可有多個正解）。
- §5.3 的 N_MCMC 段落：2→10 步的差「不超過 3–4%」，0→2 步的跳升「substantial (3–4%)」，同一個數字一邊說小一邊說大。Fig. 6 的數值沒有出現在文字中，「超過 10 步後大致持平」標明 not plotted。
- 〔顧問推導〕Table 1 的 0.785（Qwen2.5-Math GRPO，MATH500）不是 1/500 的倍數（0.785×500=392.5）；同欄其他數字都是整數題數。可能是多次平均或引用值，論文未說明。
- 〔顧問推導〕Table 1 中 Qwen2.5-Math-7B 與 Qwen2.5-7B 的 base 在 HumanEval（0.329）和 GPQA（0.278）兩欄完全相同。可能是巧合，論文未說明。
- 〔顧問推導〕題數換算：GPQA 198 題，0.389 對 0.399 是 77 對 79 題；HumanEval 164 題，0.573 對 0.537 是 94 對 88 題。論文沒有誤差棒、沒有種子數。

### 3.3 未說明的設定

- 「Low-temperature」列的溫度（推測 τ=1/α=0.25）。
- 主結果 Table 1 的 N_MCMC：只在 §5.3 成本估計處以「our experimental parameters N_MCMC=10」出現。
- AlpacaEval 用的 α（只說提議 τ=0.5）。
- HumanEval 在 Table 1 用哪個 α（§5.1 說推理任務 α=4.0，A.2 的 pass@k 用 1.67）。

## 5. 初學者的先備知識（教學順序）

1. 離散機率分佈、正規化、未正規化的權重（只知道比例也能談「誰比較可能」）。
2. 條件機率與鏈式法則：聯合機率是條件機率的連乘，式(1)。邊際化就是把未來全部加起來。
3. 自回歸語言模型：token、next-token 分佈、逐個取樣；一條序列的 likelihood 與 log-likelihood。
4. 溫度取樣：對 next-token 機率取 1/τ 次方再正規化，式(3)；τ 小時更貪婪。
5. 銳化與冪分佈 p^α：式(2)與 Fig. 2。先在單一分佈上看，再搬到序列上。
6. 「次方的和」對「和的次方」：用 Example 1 的四個數字手算一次，再給 2.1 的修正項 F。
7. 為什麼不能直接從 p^α 取樣：正規化常數要對所有序列求和。
8. Markov chain 與平穩分佈；接受/拒絕的想法；Metropolis-Hastings 的接受率式(9)與 detailed balance（一行即可）。
9. 提議分佈、不可約與非週期、mixing time（只需直覺：鏈要走多久才像目標分佈）。
10. Algorithm 1 的區塊結構與成本式(12)。
11. RL 後訓練的概念：驗證器給獎勵、GRPO 是其中一種演算法、「分佈銳化」假說。不需要 GRPO 的數學。
12. 評測用語：單次準確率、pass@k、多樣性崩塌；MATH500、HumanEval、GPQA Diamond、AlpacaEval 2.0 各測什麼。
13. 熵與 confidence，式(13)：平均負熵，值 ≤ 0，越接近 0 越有把握。只在講 Fig. 4 時需要。
