# 571 Decision Transformer 驗收答案（僅依 page.txt）

**LO1**
- 答：離線 RL 只能使用由任意策略收集的固定、有限軌跡資料，不能與環境互動；一般線上 RL 可以。較難的原因是代理不能探索環境，也不能收集額外回饋；資料中的策略可能很差（例如隨機行動）。目標是「從固定、有限的經驗產生最有效的行為」，也就是學到比資料中的策略更好的行為。
- 出處：「只能使用由任意策略收集的固定、有限軌跡資料」
- 信心：high

**LO2**
- 答：作者列的三個問題：(1) bootstrapping 是 deadly triad 之一，會使 RL 不穩定；(2) 為 TD 學習而折扣未來獎勵，可能造成短視行為；(3) Bellman 備份傳遞獎勵很慢，且容易受「干擾」訊號影響。
  Sec. 5.7 的推測：離線 TD 方法先學一個近似的價值函數再對它做最佳化，最佳化會放大並利用近似誤差，所以需要策略正則化或價值悲觀。DT 不把學到的函數當作最佳化目標，因此不需要這些保守措施。
- 出處：「不把學到的函數當作最佳化目標」
- 信心：high

**LO3**
- 答：C2 的鏈有 H 個狀態，α=1 時要做 H 次同步備份，V₁ 才不為 0（第 n 次備份後恰好最右邊 n 個狀態有值）。H=30、γ=0.99 時，之後 V₁ 停在極限 γ^(H−1) = 0.747。α<1 時大約慢 1/α 倍：H=30、γ=1 時，V₁ 達到極限一半所需次數在 α=1、0.5、0.25、0.1 時分別為 30、59、119、297。
  RTG（returns-to-go）：對已結束的離線軌跡做一次由後往前的後綴和，每個時間步立即得到報酬 1，不需要迭代，也不折扣。
- 出處：「所以要做 H 次備份 V1 才不為 0」
- 信心：high

**LO4**
- 答：R̂_t = Σ_{t'=t}^{T} r_{t'}，即從時間步 t 到結尾的獎勵總和，沒有折扣，數值與報酬 R_t 相同。
  不直接輸入獎勵，因為作者希望模型依據「未來想得到的報酬」產生動作，而不是依據「過去得到的獎勵」。
- 出處：「依據「未來想得到的報酬」產生動作」
- 信心：high

**LO5**
- 答：脈絡長度 K 個時間步，每個時間步有 RTG、狀態、動作三個 token，共 3K 個 token。頁面給的 K：Atari 30、Pong 50、Gym 20、Reacher 5。
  一般位置嵌入是每個 token 一個位置向量（第 1、2、3… 個 token）。DT 則是每個時間步學一個時間步嵌入，加到該時間步的三個 token 上，而不是每個 token 一個（Alg. 1 註解寫 note: not per-token）。
- 出處：「每個時間步學一個時間步嵌入」
- 信心：high

**LO6**
- 答：主實驗中，狀態 s_t 所在位置的輸出用來預測 a_t（依 Sec. 3 內文）。損失：離散動作用交叉熵，連續動作用均方誤差，各時間步取平均，且只在動作上計算損失。主實驗不預測狀態或 RTG。
- 出處：「離散動作用交叉熵損失，連續動作用均方誤差」
- 信心：high

**LO7**
- 答：測試時先指定目標報酬 G（例如成功為 1、失敗為 0）與起始狀態。每執行一步，RTG 更新為 R[-1] − r，即把目標報酬減去這一步得到的獎勵，並只保留最後 K 個時間步。
  Atari 的目標報酬取資料最大報酬的 1× 或 5×：Breakout 90、Pong 20 約 1×；Qbert 2500、Seaquest 1450 約 5×。Gym 依專家表現設定，HalfCheetah 用 50%；頁面表 9 的目標值為 HalfCheetah 6000、Hopper 3600、Walker 5000、Reacher 50。
- 出處：「把目標報酬減去這一步得到的獎勵」
- 信心：high

**LO8**
- 答：訓練資料是離線資料集（固定的軌跡）。訓練時從中抽出長度 K 的片段組成 minibatch。D4RL 的三種資料集為 Medium、Medium-Replay、Medium-Expert；Atari 為 DQN-replay 的 1%。
  生成時以目標 RTG（以及起始狀態）為條件，逐步產生動作。
  拼接：論文的最短路徑例中，生成路徑有 15.8% 是拼接而成。本頁的簡化重現在 19 個起點中有 2 個（11%），兩者不能直接比較。頁面未提供 Atari 或 D4RL 主實驗中拼接所占的比例。
- 出處：「後者占生成路徑的 15.8%」
- 信心：medium（拼接比例出自最短路徑例，不是主實驗）

**LO9**
- 答：Atari 用 DQN-replay 的 1%：線上 DQN 代理訓練中看到的 5,000 萬筆轉移中的 50 萬筆。
  分數正規化：100 × (raw − random) ÷ (gamer − random)，100 = 職業玩家、0 = 隨機策略。
  DT 與 CQL：4 款中 3 款與 CQL 相當（competitive）。Breakout DT 267.5 vs CQL 211.1；Pong 106.1 vs 111.9；Seaquest 2.5 vs 1.7；Qbert 落後，15.4 vs 104.2。
- 出處：「5,000 萬筆轉移中的 50 萬筆」
- 信心：high

**LO11**
- 答 (a)：資料充足（D4RL）時，%BC 可與其他離線 RL 方法持平或更好，DT 在多數環境與最好的 %BC 相當。資料少（Atari 1%）時，%BC 弱、DT 較好。例：Breakout 的 10%BC 28.5、25%BC 73.5、40%BC 108.2、100%BC 138.9，DT 為 267.5。

- 出處 (a)：「資料少時（Atari 的 1%），%BC 弱、DT 較好」；(b)：「Pong 106.1→2.5」
- 信心：high

## 初學者可能卡住的地方

1. **R_t、r_t、R̂_t 的分別**：r_t 是單步獎勵，R_t 是報酬，R̂_t（RTG）數值與 R_t 相同但頁面用不同記號。初學者容易把「獎勵」與「報酬」混用。
2. **deadly triad、價值悲觀、Bellman 備份**：頁面只給一句定義，沒有解釋為什麼三者會讓 TD 不穩定，Sec. 5.7 的推測也只給結論。
3. **C2 的閉式解與 α 的影響**：Pr[Bin(n,α) ≥ m] 的推導頁面標為可略過；「極限的一半」與「慢 1/α 倍」的數字沒有說明來源（是本頁推導）。
4. **預測位置不一致**：Sec. 3 內文說由狀態位置預測動作，Alg. 1 註解寫 action prediction tokens；另外 3j−2、3j−1、3j 的位置編號與「看到 3m−1 個 token」的計數，初學者不易對應。
5. **測試時的 RTG 與不同版本混用**：G、RTG、R[-1] − r 的關係，以及 Atari 目標報酬 1× 或 5× 的選擇；另外最短路徑例的 GPT 會同時預測 RTG token，與主實驗只預測動作不同，頁面沒有在每處都標清楚。
