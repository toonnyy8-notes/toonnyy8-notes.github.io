LoopCD 入門
章節

    LoopCD讓迴圈語言模型用較早一次迴圈的預測，修正最後一次迴圈選出的 token

    迴圈語言模型會把同一段神經網路層重複執行很多次，每執行一次，就修正一次對下一個 token 的預測。LoopCD 在選 token 時，把最後一次迴圈的分數減去較早一次迴圈的分數。這樣做不需要重新訓練，生成速度只慢 1% 到 2%，卻能修正一部分推理錯誤。

    從第 1 章開始讀 直接操作 LoopCD

    閱讀前只需要知道一件事：語言模型是一次產生一個 token 來寫出文字的。其他概念頁面中都會說明。
    論文：Byeongho Yu、Junhyuk So、Eunhyeok Park（浦項科技大學），arXiv 2609.24196，2026 年 9 月。

    章節
      1

      語言模型怎麼選下一個 token

      語言模型產生文字時，一次只產生一個 token。token 是模型處理文字的單位，可能是一個字、一個英文單字的一部分、一個數字或一個符號。

      每產生一個 token，模型都做三件事：

      1. 對詞彙表中的每一個 token 算出一個分數，叫做 logit。分數越高，模型越想選它。
      2. 用 softmax 函數把所有 logit 換成機率。所有機率加起來等於 1。
      3. 根據機率選出一個 token。最常用的做法叫 greedy decoding（貪婪解碼）：直接選機率最高的那一個。
      softmax：把 logit z 換成機率 pp(v) = ezv ⁄ Σu ezu

      entropy（熵）衡量機率分得有多散：

      H = − Σv p(v) log p(v)

      如果全部機率都在同一個 token 上，H = 0，代表模型很確定。如果 4 個 token 的機率一樣，H = log 4 ≈ 1.39，這是 4 個候選時的最大值。第 4 章會用 entropy 判斷模型在哪些位置不確定。

      小結logit 是分數，softmax 把分數變成機率，greedy decoding 選機率最高的 token，entropy 表示機率有多分散。
      2

      迴圈語言模型：同一段層重複執行

      一般的 Transformer 語言模型由很多層堆疊而成，每一層都有自己的權重（訓練時學到的參數）。輸入依序通過第 1 層、第 2 層，一直到最後一層，最後輸出 logit。

      迴圈語言模型（Looped Language Model，簡稱 LoopLM）把中間一段層設計成循環區塊，讓資料重複通過這段層很多次。每通過一次叫做一次迴圈（iteration）。每次迴圈用的都是同一組權重，所以模型可以用很少的參數做很多層的計算。

      論文用 (p, k ⊗ d, l) 描述這種結構：

      p
      前段的層數，資料進入迴圈前先通過這些層
      k
      循環區塊裡的層數
      d
      循環區塊重複執行的次數
      l
      後段的層數，迴圈結束後才通過

      迴圈進行時，模型修改的是隱藏狀態：每個位置上的一個長向量（一長串數字），表示模型目前對上下文的理解。迴圈期間不輸出任何文字，所以這種推理被稱為潛在推理（latent reasoning）。相比之下，chain-of-thought 是把推理步驟寫成文字輸出。

      論文的實驗使用兩個公開的 LoopLM：Huginn-0125，預設跑 32 次迴圈；Ouro-1.4B，最後一次迴圈是第 4 次，訓練時使用了更多資料和算力。

      小結LoopLM 重複使用同一段層，用少量參數換取更深的計算。每一次迴圈都在修正隱藏狀態，正常情況下只有最後一次迴圈的結果被拿來選 token。
      3

      看見每一次迴圈的預測

      正常情況下，只有最後一次迴圈的隱藏狀態會被送去輸出頭，也就是把隱藏狀態轉成 logit 的最後一步。

      不過，我們可以把第 1 次、第 2 次，任何一次迴圈之後的隱藏狀態都送進同一個輸出頭，讀出「如果模型在這一次就停下來，它會選哪個 token」。這個方法叫做 logit lens。LoopCD 用的就是這些中間結果。

      小結logit lens 讓我們看到每一次迴圈的中間預測。有些 token 的預測會穩定變好，有些則先衝高再掉下來。
      4

      Easy token 與 hard token

      作者用 logit lens 觀察 Huginn-0125 產生的每一個 token，發現兩種變化方式：

      • easy token：迴圈越多次，模型對最後答案越有把握。大約 89.3% 的 token 屬於這一類。
      • hard token：模型在早期迴圈就很有把握，之後把握變小，好像想改答案但沒有改完。這類 token 約佔推理文字的 10% 到 15%。

      作者用 margin（差距）來區分兩者。先找出第 32 次迴圈 logit 最高的 token，記為 y*。第 i 次迴圈的 margin 是 y* 的 logit 比其他 token 中最高的 logit 多出多少：

      margin 與下降量mi = zi(y*) − maxv ≠ y* zi(v)
      d = mpeak − mfinal，　d ≥ 1.5 時為 hard token

      mpeak 是 32 次迴圈中最大的 margin，mfinal 是第 32 次的 margin。下降量 d 大於或等於 1.5 的 token 被歸為 hard token。

      為什麼 hard token 重要

      作者提出三項證據，說明 hard token 和推理錯誤有關。

      第三項證據是 entropy。作者把整段推理中每個位置的 entropy 取平均，稱為 trace entropy：

      Htr = (1⁄N) Σi=1…N Hi

      在數學題資料集 GSM8K 上，答錯的推理通常 Htr 較高，答對的較低。而 hard token 正是 entropy 偏高的位置。

      哪些 token 最常是 hard token？作者統計 Huginn-0125 在 600 題 GSM8K 上的輸出，出現最多的是：

      數字：0、1、2、3、4、5 運算符號：=、+、$ 標點：.、, 推理步驟的開頭：The、So 其他：is、of、answer

      這些 token 決定計算的中間數值和推理的段落結構，選錯一個，後面整段都可能跟著錯。

      小結hard token 只佔約一成，但它們集中在數字、運算符號和步驟開頭，而且和答錯高度相關。如果能修正這些位置，推理就可能變正確。
      5

      對比解碼：用比較弱的預測來扣分

      對比解碼（contrastive decoding，CD）是 Li 等人在 2023 年提出的方法。它同時使用兩個預測來源：比較強的 expert（專家）和比較弱的 amateur（業餘者）。

      想法是：兩者都會犯的錯，例如重複同一句話或回答空泛，在弱的那一方機率會更高。因此用 expert 的 log 機率減去 amateur 的 log 機率，amateur 特別偏好的 token 就會被扣分；只有 expert 明顯比 amateur 更看好的 token 會得到高分。

      對比解碼的分數score(v) = log pexpert(v) − λ · log pamateur(v)

      λ（lambda）控制扣分的強度。λ = 0 時沒有扣分，結果就和只用 expert 一樣。

      後來的研究發現，amateur 不一定要是另一個模型。它可以是同一個模型的淺層輸出、剪枝後的同一個模型，或是加了干擾的輸入。重點是 amateur 的預測要比 expert 差，而且它的錯誤方向能提供參考。

      小結對比解碼用「expert 減去 λ 倍 amateur」的分數選 token。LoopCD 的 amateur 是同一個模型較早的一次迴圈。
      6

      LoopCD 的計算方法

      在每一個解碼步驟 t，LoopCD 對每個候選 token v 算出分數：

      論文式 (2)st(v) = log pt(ℓe)(v) − λ log pt(ℓa)(v)　　p(v) = est(v) ⁄ Σu est(u)
      ℓe
      expert 迴圈：最後一次迴圈。Huginn-0125 是第 32 次，Ouro-1.4B 是第 4 次。
      ℓa
      amateur 迴圈：較早的一次迴圈，例如 Huginn-0125 的第 8 次。
      λ
      對比係數，論文在 0.1、0.2、0.3 之中挑選。

      另外還有一條合理性限制（adaptive plausibility constraint）：只考慮 expert 認為還算合理的 token。機率低於 expert 第一名的 α 倍的 token 直接排除，論文設定 α = 0.1。

      論文式 (3)Vhead = { v : p(ℓe)(v) ≥ α · maxw p(ℓe)(w) }

      為什麼需要這條限制？假設某個 token 在 expert 和 amateur 眼中都幾乎不可能，但 amateur 給的機率更低。相減之後它的分數反而很高，會被錯誤選中。下面的操作台可以關掉這條限制，把 λ 調大，親眼看到這種情況。

      每個解碼步驟的流程：

      1. 照常把迴圈跑完。跑到第 ℓa 次時，把當下的隱藏狀態轉成 log 機率存起來。這不需要重跑迴圈，只多一次轉成 logit 的計算。
      2. 用最後一次迴圈的機率找出 Vhead。
      3. 對 Vhead 中每個 token 算分數 s。
      4. 把分數做 softmax，選最高者，或依機率抽樣。
      # 一個解碼步驟（Python 風格的虛擬碼）
h = prelude(x)
for i in range(1, L_e + 1):
    h = recurrent_block(h)                 # 每次用同一組權重
    if i == L_a:
        logp_a = log_softmax(to_logits(h))  # 第 L_a 次的預測，順便存下
logp_e = log_softmax(to_logits(h))          # 最後一次的預測

keep  = logp_e >= logp_e.max() + log(alpha)  # 合理性限制，alpha = 0.1
score = logp_e - lam * logp_a
score[~keep] = -inf
next_token = score.argmax()

      7

      為什麼它主要改到 hard token

      LoopCD 對每一個 token 都做同樣的計算，不需要先判斷誰是 hard token。可是它的效果自然集中在 hard token 上。用兩個候選 y、z 的分數差就能看出原因。

      設第 ℓ 次迴圈時，y 比 z 多出的 log 機率是 Δ(ℓ)。套用 LoopCD 之後，兩者的分數差可以拆成兩項：

      LoopCD 之後 y 與 z 的分數差(1 − λ) Δ(ℓe) + λ ( Δ(ℓe) − Δ(ℓa) )
      • 第一項：最後一次迴圈原本的差距，乘上 (1 − λ)。如果 y 是 greedy 的選擇，這一項是正的。
      • 第二項：從第 ℓa 次到最後一次，差距是變大還是變小。
      • easy token 的差距越來越大，第二項是正的，第一名不會變。
      • hard token 的差距在早期最大、後來縮小，第二項是負的，而且往往很大。兩項加起來小於 0 時，第一名就換成 z。

      實驗證據

      作者統計了 Huginn-0125 在 GSM8K 上產生的 58,447 個 token，檢查 LoopCD 有沒有把 greedy 的第一名換掉。

      另一個角度：和擴散模型的 guidance 很像

      圖像生成的擴散模型常用 (1 + α) εθ(x) − α εbad(x) 這種組合：εbad 是比較差的預測，例如沒有給條件的預測，或訓練較少的模型。把差的預測減掉，結果會往好的方向推得更遠。LoopCD 的早期迴圈就扮演 εbad 的角色。

      ℓa 要選第幾次

      作者記錄每個 token 的 margin 在哪一次迴圈達到最高。hard token 的高峰集中在第 6 到 12 次，最常見的是第 8 次附近；全部 token 的高峰則分散，而且偏向後面的迴圈。所以選第 8 次當 amateur，剛好抓到 hard token 太早有把握的時刻。

      小結因為 hard token 的差距會「先大後小」，相減後最容易翻轉；easy token 的差距「越來越大」，相減後不受影響。所以 LoopCD 不必偵測 hard token，也能主要修正它們。
      8

      實驗結果

      作者在三類任務上測試：數學推理（GSM8K、MATH-500）、寫程式（HumanEval、MBPP，以及加了更多測試的 HumanEval+、MBPP+）、常識問答（StrategyQA）。比較的方法有：

      Greedy
      LoopLM 的標準做法，直接選最後一次迴圈機率最高的 token。
      MTI
      只在 entropy 高的位置介入，加上負面提示詞再做 guidance。需要調 entropy 門檻，也要多做一次前向計算。
      Self-Eval
      每題產生 4 個答案，讓模型自己評分後挑一個，所以慢很多。
      NoiseCD
      作者設計的對照組：在最後一次的隱藏狀態加雜訊當 amateur。用來檢查效果是不是只來自「隨便扣掉一個比較差的分佈」。
      • 在 Huginn-0125 上，LoopCD 的 9 項成績全部高於 Greedy，最大提升是 HumanEval+ 的 +6.71 分。
      • 在 Ouro-1.4B 上也全部高於 Greedy，提升從 +1.06 到 +4.89 分。
      • LoopCD 不是每一格都最高：Ouro 的 MATH-500 Flex 是 MTI 最高（54.20），Huginn 的 MBPP 是 NoiseCD 略高（42.59），Ouro 的 HumanEval 與 Self-Eval 同為 74.39。
      • 速度是 Greedy 的 0.98 到 0.99 倍；Self-Eval 只有 0.25 到 0.28 倍。
      • NoiseCD 只在少數項目有幫助。它的雜訊同時影響 easy token，而 LoopCD 主要影響 hard token。這支持「用早期迴圈當 amateur」本身就是效果來源。

      可以和提早結束一起用

      提早結束（early exit）是指：當隱藏狀態在連續兩次迴圈之間幾乎不再改變，就不跑剩下的迴圈。這能讓速度大約加倍。LoopCD 可以疊加上去，把提早結束的那一次當作 expert。

      限制與失敗案例

      • amateur 迴圈是靠經驗選的。第 ℓa 次迴圈不一定對每個 token、每個任務、每個模型都是最好的對比對象。作者認為可以訓練一個驗證器來挑選，或在解碼時自動選擇 ℓa。
      • 偶爾會改壞 easy token。例如 greedy 正確寫出 43 × 3 = 129，LoopCD 卻寫成 43 × 3 = 1,293。在那個位置，expert 和 amateur 都偏好正確的 2，但 amateur 更有把握，於是 2 被扣分太多，逗號被選中。這種情況只佔 easy token 的 0.82%。
      • 改了第一個 token，整段推理會換方向。例如 greedy 以 The original piece of wire... 開頭並答對，LoopCD 改以 4 feet is 4 × 12 = 48 inches... 開頭後答錯。約 1.2% 的推理發生這種情況。
      • 有時後面的迴圈才是對的。LoopCD 假設「從早期到最後」的修正方向是好的。如果後面的迴圈把正確答案改錯，LoopCD 會放大這個錯。作者檢查後發現這種位置只佔 2% 到 3%，而且把這些位置換回早期答案，讓答案由對變錯的比例（23.9%）比由錯變對（9.9%）更高，表示後期的修正多半是對的。
      • 整體來說好處較多。在 Huginn-0125 的 GSM8K 上，LoopCD 讓答案「由錯變對」的題數是「由對變錯」的 1.49 倍。
      • 實驗範圍。論文只測試了兩個 LoopLM：Huginn-0125 和 Ouro-1.4B。

      自我檢查與名詞表

      四個問題，選完會立刻顯示答案和說明。

      名詞表

      token
      模型處理文字的單位，可能是字、詞的一部分、數字或符號。
      logit
      模型給每個候選 token 的原始分數，還沒換成機率。
      softmax
      把一組分數換成加總為 1 的機率的函數。
      greedy decoding
      每一步都選機率最高的 token。
      entropy
      衡量機率分佈有多分散；越大表示模型越不確定。
      隱藏狀態
      模型內部每個位置上的一長串數字，表示它目前對上下文的理解。
      LoopLM
      迴圈語言模型。重複執行同一段層（循環區塊）的語言模型。
      迴圈（iteration）
      循環區塊執行一次。Huginn-0125 預設 32 次，Ouro-1.4B 是 4 次。
      logit lens
      把中間的隱藏狀態送進輸出頭，讀出模型在那個階段的預測。
      margin
      某個 token 的 logit 比其他 token 中最高者多出的量。
      hard token
      margin 在早期達到高峰、最後下降至少 1.5 的 token。約佔 10% 到 15%。
      expert／amateur
      對比解碼中較強與較弱的預測來源。LoopCD 中分別是最後一次迴圈與較早一次迴圈。
      對比解碼
      用 expert 的 log 機率減去 λ 倍 amateur 的 log 機率來選 token。
      合理性限制
      只保留 expert 機率至少達到第一名 α 倍（α = 0.1）的 token。
