    RTI：把影像 patch 排成一條線，在內容變化最大處切開

    這篇論文把預訓練像素擴散模型中段的 patch token 換成數量可調的區域 token，一個模型可在 64–512 個 token 的範圍內任選。

    Eduard Zamfir、Christian Reisswig、Zongwei Wu、Yongqin Xian、Radu Timofte（2026）〈Elastic Token Compression for Pixel-Space Diffusion Transformers〉

    01 · 重複的計算

    自然影像的細節集中在少數小方塊（patch）。在已訓練好的像素擴散模型裡，中間幾層對平坦區域的計算大多是重複的。

    02 · 一條線上的切割

    RTI 把所有小方塊排成一條不斷線的路徑，在相鄰內容變化最大的地方切開，每一段合成一個 token。

    03 · 一個模型、多種預算

    同一個模型可在 64–512 個 token 之間任選：B/16 用 512 個時，速度 1.84 倍、GenEval 87.8（原模型 1024 個、87.2）。

    01 · 背景

    擴散 Transformer 對每個 patch 分配相同計算量

    本節符號$N$：patch token 數；$x_t$：取樣過程中的狀態；$\hat x$：網路預測的乾淨影像。

    擴散 Transformer（diffusion transformer，DiT）把影像切成規則的小方格，每一格稱為一個 patch，攤平成一個向量後當作一個 token。網路由一串區塊（block）串接而成，每個區塊包含一層注意力（attention）與一層 MLP。生成一張影像時，模型從純噪聲出發，反覆執行整個網路；執行一次稱為一個取樣步，一個取樣步等於整個網路的一次前向計算，本文的設定要跑 100 步（Sec. 4.1）。

    每個區塊的成本取決於 token 數 $n$：注意力要比較每一對 token，成本約與 $n^2$ 成正比；線性層對每個 token 各算一次，成本與 $n$ 成正比。DiT 對每個 patch、在每個區塊、每個取樣步都分配相同的計算量，不論該 patch 是一片藍天還是一叢樹葉（Sec. 1）。

    本文的基礎模型是 MiniT2I-B/16：一個像素空間（JiT 系列）的文字到影像 DiT，主幹有 17 個區塊，影像 token 與凍結的 FLAN-T5 文字 token 並行。它以 rectified flow 訓練：狀態 $x_t$ 在噪聲與乾淨影像之間內插，網路直接預測乾淨影像 $\hat x$，而不是預測噪聲（Sec. 3.1）。RTI 只縮短影像 token 的序列，文字串流永遠保持全長。

    論文指出浪費在像素空間模型最大：潛空間模型由 VAE 先把影像壓成較小的潛變數，移除了大部分低階空間冗餘；像素空間模型沒有 VAE 先移除低階空間冗餘，每個區塊都要處理這些冗餘（Sec. 1）。以 512² 解析度、patch 大小 16 計算，一張影像是 32×32 的格，共 $N=1024$ 個 patch token（Sec. 3.1），這就是 RTI 要縮短的序列。

    檢查理解

    為什麼論文說浪費在像素空間模型最大？MiniT2I-B/16 在 512² 有幾個 patch token？

    沒有 VAE 先移除低階空間冗餘，每個區塊都要處理；patch 16 → 32×32 = 1024 個（Sec. 1、3.1）。

    02 · 冗餘

    冗餘集中在平坦區域與中段區塊

    本節符號$R$：分組後的組數（預算）；$h_j$：patch $j$ 在某個區塊的特徵；$\bar h_{c(j)}$：$j$ 所屬組的平均；$\bar h$：全部 token 的平均；EV：保留變異。

    要知道 token 有多少重複，作者先做一個不需要訓練的探測：把 $N$ 個 token 分成 $R$ 組，把每個 token 換成它所屬組的平均，再看還剩多少資訊。最簡單的分組是把 32×32 格切成等大的 2×2 方格，共 $R=256$ 組。剩下的資訊用保留變異（explained variance，EV）量（App. C.1）：

    $$\mathrm{EV}=1-\frac{\sum_j\lVert h_j-\bar h_{c(j)}\rVert^2}{\sum_j\lVert h_j-\bar h\rVert^2}$$
    Eq. 5

    EV 的意義是：EV = 1 表示匯集後的 token 完整攜帶原本的表示；EV = 0 表示匯集後不比一個常數好（App. C.1）。EV 量的是某一個區塊激活的線性餘裕，不是輸出影像的品質。論文在 $R=256$ 時發現匯集仍有約 26% 回收不了，這 26% 是 RTI 保留全解析度的末段區塊（coda）與可學習的 WRITE 的理由（App. C.1；兩者在 S4、S9 說明）。

    作者除了等大方格，也用「依內容分組」（S6 才講做法）與「跳過」比較；跳過不是分組，而是只保留 $R$ 個 token、其餘換成平均。探測在凍結的 MiniT2I-B/16 上進行（bf16、30 個 Euler 步、guidance 5.0、十個領域的合成提示，App. C）。

    Fig. 2 從三個方向量冗餘。空間上，依完成影像的梯度能量排序 patch，最細節的 15% patch 占一半細節，前一半占 88%。時間上，把 $N=1024$ 個 token 匯集成 $R=256$ 組時，中段區塊的 EV 隨影像成形上升，依內容分組全程高於等大方格。深度上，EV 由第一塊的 61% 升到中段約 75%，再往最後一塊下降（Fig. 2、Sec. 3.2）；跳過回收的比例比匯集低得多。

    三個方向的冗餘（Fig. 2）

    15% → 50%空間：最細節的 15% patch 占一半細節
    61% → 75%深度：EV 由第一塊升到中段
    26%R = 256 時匯集回收不了的部分

    冗餘有形狀：集中在影像的平坦區域、在取樣後段增加、在中段區塊最高。下一節由這個形狀推出壓縮方法必須保留的性質。

    檢查理解

    Fig. 2 在空間、時間、深度上各量到什麼？

    空間：最細節的 15% patch 占一半細節，前一半占 88%；時間：EV 隨影像成形上升；深度：EV 由第一塊 61% 升到中段約 75% 再往末塊下降（Fig. 2、Sec. 3.2）。

    EV（Eq. 5）的 1 與 0 代表什麼？R = 256 時未回收的 26% 導致什麼設計？

    1：匯集後完整攜帶表示；0：不比常數好；26% 是 RTI 保留全解析度 coda 與可學習 WRITE 的理由（App. C.1）。

    03 · 四個性質

    冗餘的形狀決定壓縮必須保留的四個性質

    本節符號$p_j$：patch $j$ 在格上的座標；$w_{rj}$：patch $j$ 屬於第 $r$ 組的權重（和為 1）；$p_r$：組中心；spread：組內 patch 到中心的平均距離。

    本節比較三個既有的縮減方法，論文把它們都放進同一個介面重新實作（App. A）：

    • Feat Sim（特徵相似度合併，ToMe 式）：取 $R$ 個錨點 token，每個 patch 依特徵的 cosine 相似度指派給最像的錨點。
    • Latent Array（潛變數陣列，Perceiver-IO／RIN 式）：$R$ 個可學習向量以交叉注意力讀取整張圖，再寫回去；不形成分組。
    • Token Skip（Mixture-of-Depths 式）：只讓一部分 token 進入某些區塊，其餘 token 略過該區塊。

    比較用三個量。retained 是 Eq. 5 的 EV 套在各方法自己的分組上，對核心區塊平均，不含任何可學習的寫回步驟，所以是對每種方法同等悲觀的下界（App. C.2）。size–detail 是各組的細緻度（$-\log_2$ 組大小）與它涵蓋的細節之間的相關係數。spread 量一組 patch 散得多開（App. C.2）：

    $$p_r=\sum_j w_{rj}\,p_j,\qquad \mathrm{spread}_r=\sum_j w_{rj}\,\lVert p_j-p_r\rVert_2$$
    Eq. 6

    單一 patch 的 spread 為 0；涵蓋整張 32×32 影像的組為 12.2 格。

    由上一節的冗餘形狀，論文推出四個要求（Sec. 1）。四個要求是連通、大小隨內容、位置、匯總：冗餘的 patch 在平坦區彼此相鄰，所以一組必須連通；細節集中在少數 patch，所以組的大小要隨內容；一組涵蓋影像中一個確定的地方，它的 token 要代表那裡，所以要有位置；Fig. 2c 顯示刪除會失去匯集能保留的東西，所以冗餘內容要匯總而不是刪除。Feat Sim 失去連通與位置；Latent Array 失去分組（因而失去連通）與位置；Token Skip 失去匯總；三者都失去大小隨內容（Sec. 1、4.2）。

    檢查理解

    四個要求是什麼？Feat Sim、Latent Array、Token Skip 各失去什麼？

    連通、大小隨內容、位置、匯總；Feat Sim 失去連通與位置，Latent Array 失去分組（因而連通）與位置，Token Skip 失去匯總；三者都失去大小隨內容（Sec. 1、4.2）。

    04 · 核心區段

    RTI 只壓縮中段核心

    本節符號$s_0$、$s_1$：核心第一與最後一個區塊（含兩端點；B/16 為 3 與 13）。

    RTI 沿用 recurrent-depth Transformer（Geiping et al. 2025）的前段（prelude）／核心（core）／末段（coda）結構：中段一串連續區塊 $[s_0,s_1]$ 是核心。READ 在 $s_0$ 之前把 $N$ 個 patch token 匯集成 $R\ll N$ 個區域 token，核心的每個區塊只處理這段短序列，WRITE 在 $s_1$ 之後把結果散回 $N$ 個 patch；核心以外的區塊維持全解析度（Sec. 3.2）。B/16 的核心是 17 塊中的 $[3,13]$，前後各留三塊。

    兩端不適合壓縮的理由相反。前段還在把原始 patch 轉成特徵，此時匯集會在模型處理之前丟掉像素；末段要把特徵轉回逐像素的輸出，共享的區域更新會使輸出模糊。兩者之間的特徵最冗餘（Sec. 3.2）。主幹以 LoRA（rank 32，加在注意力與 MLP 的投影上）適配較短的序列，其餘權重凍結。

    05 · Hilbert 順序

    Hilbert 曲線把二維分組變成一維切割

    本節符號$q$：格邊長；$\pi$：曲線誘導的順序，$\pi(j)$ 是第 $j$ 個位置的 patch；連續段（run）：順序上一段連續的位置。

    四個要求中的連通與位置，都可由同一個排列 patch 的方式取得。Hilbert 曲線（Hilbert 1891）恰好走過 $2^k\times2^k$ 格的每一格一次。Hilbert 序列的任一連續段都是連通區域，原因是曲線上相鄰位置在格中一定相鄰；所以任何一段連續位置都占據影像中一塊相連的區域，大小任意、不一定是正方形。更強的性質是：每個二元方格（dyadic cell，quadtree 會產生的那種正方形）恰好是 Hilbert 序列上的一段連續位置，所以任何 quadtree 分割都能用切割 Hilbert 序列表達，切割還能表達 quadtree 做不到的分割。其他順序沒有這個性質：raster 在行尾斷開，Morton（Z）順序在二元方格邊界以對角跳躍連接（Sec. 3.1、App. B.4）。

    於是二維的分組問題變成一維的切割問題：只要決定在序列的哪些位置切開。和 quadtree 相比，quadtree 也能隨內容調整大小，但每個區域綁定一個二元正方形，而且每張影像、每個取樣步都要建一棵樹；切 Hilbert 序列保留了隨內容調整大小，去掉了這兩個缺點（Sec. 3.3）。點雲 Transformer（Point Transformer V3）也用這條曲線，但只用來排列注意力的序列；本文用它定義分組本身（Sec. 2）。

    下面的元件比較三種順序。注意：長度為 $2^m$、從對齊位置開始的段，在三種順序下都連通（raster 的對齊段是一整行或一行的一段）〔本頁推導〕；斷裂只出現在不對齊的段。RTI 的切點可以落在任何位置，所以順序的連通性在自適應切割下才重要。

    檢查理解

    為什麼 Hilbert 序列的任一連續段都是連通區域？raster 與 Morton 何處斷開？

    曲線上相鄰位置在格中一定相鄰；每個二元方格恰為一段，可表達任何 quadtree 分割；raster 在行尾斷開，Morton 在二元方格邊界對角跳躍（Sec. 3.1、App. B.4）。

    06 · 切割規則

    在特徵變化最大的地方切割

    本節符號$h_j^{(s_0)}\in\mathbb R^d$：進入核心時 patch $j$ 的特徵；$d_j$：曲線上相鄰兩 patch 的特徵距離；$C$：切點集合。

    論文要的是 $R$ 個連通、在平坦處粗、在細節處細，而且每個取樣步都能便宜重建的區域（Sec. 3.3）。做法是在 Hilbert 序列上，對每一對相鄰 patch 算特徵距離：

    $$d_j=\big\lVert h^{(s_0)}_{\pi(j+1)}-h^{(s_0)}_{\pi(j)}\big\rVert_2,\qquad j=1,\dots,N-1$$
    Eq. 1
    $$C=\{\,j:\ d_j\ \text{屬於最大的}\ R-1\ \text{個}\,\}$$
    Eq. 2

    RTI 決定 $R$ 個區域的方式是：算曲線上相鄰 patch 的特徵距離 $d_j$（Eq. 1），在最大的 $R-1$ 個處切開（Eq. 2），相鄰切點之間的 $R$ 段就是區域。這條規則沒有參數，成本是 $O(N)$：掃一次算距離，再用線性時間的選擇演算法取出切點。它在每個去噪步都從當前狀態 $x_t$ 重算，所以分割會跟著影像的成形改變（Sec. 3.3、App. A）。切點落在特徵跳躍最大處，均勻的段保持合併，細節區一路切到單一 patch。

    為什麼特徵距離能標出內容邊界：因為主幹預測乾淨影像而非噪聲，它的特徵追蹤影像結構，大的距離就標出內容的邊界（Sec. 3.3）。論文的 Fig. 9a 顯示細區域隨物體成形聚集在物體與邊界上。訓練時每一步從 {64, 128, 256, 512} 隨機抽一個 $R$（Sec. 4.1），S10 再說明這帶來的效果。距離相同時，本頁依「距離由大到小、同值取較小的 $j$」排序，使結果確定〔本頁推導：論文未寫平手規則〕。

    07 · READ

    READ 把一個區域匯集成一個 token

    本節符號$c$：一個區域；$|c|$：其 patch 數；$c(j)$：patch $j$ 所屬區域；$\alpha_j$：區域內的匯集權重；$w\in\mathbb R^d$：可學習的評分向量；$z_c$：區域 token；$e_{\text{size}}[\cdot]$：尺寸嵌入。

    每個區域經 READ 變成一個 token（Sec. 3.4）：

    $$\alpha_j=\operatorname{softmax}_{j\in c}\big(w^\top h_j^{(s_0)}\big)$$
    Eq. 3
    $$z_c=\sum_{j\in c}\alpha_j\,h_j^{(s_0)}+e_{\text{size}}\big[\lfloor\log_2|c|\rfloor\big]$$
    Eq. 3

    區域 token 由兩部分組成：區域內 softmax 權重 $\alpha_j=\mathrm{softmax}_{j\in c}(w^\top h_j)$ 的加權平均，加上尺寸嵌入 $e_{\text{size}}[\lfloor\log_2|c|\rfloor]$（Eq. 3）。softmax 只在區域 $c$ 內計算，所以 READ 等於一個限制在區域內的單查詢注意力，不是盲目的平均，可以強調區域中資訊較多的 patch。全模型只有一個評分向量 $w$。區域的大小是任意整數，所以尺寸嵌入用索引 $\lfloor\log_2|c|\rfloor$，讓核心知道這個 token 代表 1 個還是 16 個 patch。

    READ 與 WRITE 都只在區域內作用，成本是 $O(N)$，與 $R$ 無關；它們包含介面全部的可學習參數。全域的查詢（例如 Latent Array 的交叉注意力）每個查詢都要讀整張圖，成本是 $O(NR)$（Sec. 2）。

    檢查理解

    區域 token 由哪些部分組成？

    區域內 softmax 權重 $\alpha_j=\mathrm{softmax}_{j\in c}(w^\top h_j)$ 的加權平均，加上尺寸嵌入 $e_{\text{size}}[\lfloor\log_2|c|\rfloor]$（Eq. 3）。

    08 · 位置

    區域 token 的位置是相量的平均

    本節符號$\omega$：RoPE 的一個頻率；$e^{i\omega p}$：位置 $p$ 在該頻率的單位相量；$|m(\omega)|$：區域內相量平均的長度。

    預訓練主幹用旋轉位置嵌入（rotary position embedding，RoPE）。對一個頻率 $\omega$，位置 $p$ 對應旋轉角 $\omega p$，也就是單位圓上的一個相量 $e^{i\omega p}$；注意力只看兩個 token 的旋轉角之差。模型用許多個頻率，高頻率的角度隨位置轉得快，低頻率轉得慢。

    數值例：取 $\omega=1$，相鄰兩個位置 0 與 1 的旋轉角是 0 與 1 弧度，兩個相量的平均長度是 $|\cos(1/2)|=0.878$；取 $\omega=0.01$，兩個角度幾乎相同，平均長度是 0.99999。平均後，角度轉得快（波長短）的分量變小，角度轉得慢（波長長）的分量幾乎不變；這種「保留長波長、削弱短波長」的效果稱為低通。

    區域 token 的位置取其 patch 旋轉位置嵌入（單位相量）的平均；波長長於區域範圍的分量仍接近長度 1，波長較短的分量縮向 0，所以位置依區域大小變粗（Sec. 3.4）。論文的說法是：單一 patch 的位置精確，大區域的位置粗略，這正適合代表一塊面積而不是一個點的 token。

    〔本頁推導〕一列長 $L$、相鄰間隔 1 的直線區域，頻率 $\omega$ 的平均相量長度是 $\left|\dfrac{\sin(\omega L/2)}{L\sin(\omega/2)}\right|$（等比級數求和）；$L=1$ 時為 1，$\omega L\ll1$ 時接近 1。這個公式只適用於直線段（旁瓣與 $\omega>\pi$ 的混疊除外）；RTI 的區域是二維的 Hilbert 段，下面的元件直接數值求和。

    09 · WRITE

    WRITE 把區域的變化散回每個 patch

    本節符號$z'_c$：區域 token 經過核心後的值；$g$：小型可學習映射；$[\cdot\Vert\cdot]$：向量串接。
    $$h_j^{(s_1+1)}=h_j^{(s_0)}+g\Big(\big[\,h_j^{(s_0)}\,\Vert\,z'_{c(j)}-z_{c(j)}\,\big]\Big)$$
    Eq. 4

    Eq. 4 與「把 $z'_c-z_c$ 原樣加到每個 patch」的天真廣播不同：每個 patch 以 $g([h_j\Vert z'_c-z_c])$ 產生自己的更新，同一區域的 patch 可以各自特化，而不是一起移動。這個形式同時是一條繞過核心的跳接：每個 patch 保留進核心之前的特徵，把核心的工作當修正量接收，所以核心從未看過個別 patch，末段仍能產生逐像素的輸出。消融實驗把整個可學習的 READ/WRITE（READ 與 WRITE 全部）換成平均匯集與廣播寫回，GenEval 下降 7.2（Eq. 4、Sec. 3.4、Fig. 8b）。

    READ 與 WRITE 都初始化為恆等，訓練從凍結模型的行為出發（Sec. 4.1）。論文沒有給出 $g$ 的層數與寬度，本頁因此不為 WRITE 設計互動元件。

    檢查理解

    Eq. 4 與「把 $z'_c-z_c$ 加到每個 patch」有何不同？為何 coda 仍能逐像素輸出？

    每個 patch 以 $g([h_j\Vert z'_c-z_c])$ 產生自己的更新，可特化；形式上是繞過核心的跳接，patch 保留核心前特徵；換成平均＋廣播 GenEval −7.2（Eq. 4、Fig. 8b）。

    11 · 速度上限

    加速的上限來自不縮短的部分

    本節符號$B$：區塊數；$n_{\text{core}}=s_1-s_0+1$：核心區塊數（含兩端點；B/16 的 $[3,13]$ 為 11、$[1,15]$ 為 15）；$\nu=n/N$：區塊內 token 數相對於 $N$ 的比例；$\eta$：注意力在每塊成本中的比重；$\rho$：相對成本；$\tau$：不縮短的開銷比例。

    論文的速度是實測的：在 RTX 4090 上用 fused attention，每批 4 張（classifier-free guidance 使其加倍為 8），量三次交錯執行並取 images/s 的中位數；計時包含分割、READ/WRITE、adapter 與文字串流。速度比是同一主幹兩個吞吐量的比值（Sec. 4.1）。Fig. 10 顯示實測時間比解析 FLOPs 下降得快，因為這些長度下注意力部分受記憶體頻寬限制；分割與 READ/WRITE 只占不到 2%。

    B/16 速度在約 2.5× 飽和，原因是 prelude、coda、文字串流不縮短，所以 B/16 低於 $R\approx192$ 時更少的預算只降低品質、不再加速（L/16 主幹較長，仍會加速：L/16 在 $R=256/128/64$ 時為 2.59×／2.86×／3.01×）。少步數與少 token 的比較都在 L/16 上進行（App. B.3）：L/16 的區域 token 一步便宜 2.6×（L/16 dense 288 ms、L/16 RTI R = 256 112 ms），同樣 1.8 s/張的時間 L/16 dense 只能跑 6 步、L/16 RTI 跑 16 步，GenEval 65.9 對 82.7；高於約 5 s 時增加步數較划算，11.2 s 時 L/16 dense 87.6 對 L/16 RTI 86.3（Sec. 4.2、App. B.3）。作者另指出，六步 Euler 是弱取樣器，少步數蒸餾模型配上區域介面是自然的組合。

    〔本頁推導〕一個只看影像 token 的成本模型：每個區塊的相對成本為 $(1-\eta)\nu+\eta\nu^2$，$\eta=0$ 只算線性層、$\eta=1$ 只算注意力。整個主幹的相對成本為

    $$\rho=\frac{(B-n_{\text{core}})+n_{\text{core}}\big((1-\eta)\nu+\eta\nu^2\big)}{B},\qquad \nu=R/N$$
    本頁推導

    這個模型只用來對照比例，不預測吞吐量。核心長度的比較（App. B.5、Tab. 3）：把核心從 $[3,13]$ 拉長到 $[1,15]$，在 $R=256$ 時 $\eta=0$ 給出 $5888/8960=0.657$（論文 0.66×），$\eta=1$ 給出 0.439（論文「0.44× on attention」）。要讓 $[1,15]$ 回到 $[3,13]$ 在 $R=256$ 的成本，$\eta=0$ 解得 $R=460.8$、$\eta=1$ 解得 $R=572.4$，正是論文的同成本區間 $R\approx461$–572。論文附註：這個區間只計影像 token，全長的文字串流使真正的同吞吐量預算低於 461；$[1,15]$ 沒有計時，只知它的上限高於 2.5×。在同預算下較長的核心較差（GenEval 77.4 對 84.7），但便宜三分之一；在恢復同成本的 $R=512$ 時兩者無法區分（85.4，差 +0.7 落在 ±1.7 內）。作者的結論是：核心長度買的是計算量，不是品質。

    $R\to0$ 時，只看影像 token 的上限是 B/16 $17/6=2.83\times$、L/16 $23/6=3.83\times$。B/16 實測約在 2.5× 飽和，差距來自文字串流與固定開銷；若把它全歸於不縮短的開銷 $\tau$（成本 $\tau+(1-\tau)\rho$），則 $\tau\approx0.073$〔本頁推導〕。

    主結果：B/16 在 $R=256$ 時速度 2.15×、GenEval 84.7（dense 87.2）；在 $R=512$ 時速度 1.84×、GenEval 87.8，同時在品質與速度上超過自己的 dense。同預算下三個基準的代價是：刪除而非匯總 2.4 GenEval（Token Skip；它只有 1.19×，不是同預算的比較，差距因此被低估）、打散分組 4.2（Feat Sim）、移除分組與位置 39.0（Latent Array；論文 Sec. 4.3 指出這同時移除分組與位置，所以 39.0 是「錨定」貢獻的上界，位置單獨的貢獻論文未分離）（Tab. 1、Sec. 4.2–4.3）。

    掃同一個 checkpoint 的預算，從 $R=384$（2.00×）起與 dense 的差距落在噪聲內，但 dense 在每個偏好分數上仍領先。$R=512$ 時 Feat Sim 只與 RTI 的 $R=256$ 列持平。L/16 在 $R=512$ 得 87.5（2.11×），在噪聲內；在 $R=256$、2.59× 時得 86.3（dense 88.1）。論文摘要的「在 2.0× 追平 dense、在 2.6× 仍接近」分別對應 B/16 的 $R=384$ 與 L/16 的 $R=256$〔本頁推導：對應關係〕。作者說 L/16 的結果展示的是轉移到更長的主幹，不是建議選 L/16。

    基準為何失敗

    Token Skip 保留的表示只有 RTI 分組的三分之一；它的稠密那一半核心每次都全量計算，使速度上限低於約 1.3×。Feat Sim 的 patch 離組中心 5.2 格（RTI 0.5），$R=64$ 時差距達 13.8 GenEval，在 $R=256$ 時兩個主幹的每個偏好分數都落後。Latent Array 訓練 40K 步後，一個潛變數的讀取注意力仍覆蓋 11.4 格（最大 12.2）；作者指出 Perceiver-IO 與 RIN 是為從頭訓練設計的（Sec. 4.2）。

    消融

    把切點改成沿同一順序等距放置（順序、預算與介面不變），$R=128$ 時 GenEval 下降 2.7，預算越大下降越少，因為 $R=256$ 時一區只有 4 個 patch，等距切點已接近自適應切點。換成平均與廣播下降 7.2。換成 latent array 則掉到 Latent Array 基準（Fig. 8b）。

    分割跟著影像成形

    以 $\hat x$ 的梯度能量作為細節、1 個 patch 為細區域、16 個以上為粗區域：兩者在最吵的步驟攜帶相同的細節，隨影像成形拉開到約 6 倍；$R=256$、取樣中段時細緻度與細節的相關為 +0.58（Sec. 4.4、App. C.3）。切割只讀進入核心的特徵，從不讀細節量，所以這個對齊是模型自己做到的。區域大小的熵在 $R=512$ 時低、$R=64$ 時高；預算決定大小的範圍，影像決定細區域放在哪裡。

    分布指標與其他任務

    FID（MJHQ-30K，L/16）：RTI 比 Feat Sim 好 8.6（$R=512$）與 13.3（$R=256$），RTI 的 $R=256$ 還低於 Feat Sim 的 $R=512$。FID 是 RTI 在一半 token 時唯一沒追上 dense 的指標：$R=512$ 時高 2.4；作者的結論是壓縮先損失分布保真度，後損失組合準確率（App. B.1）。類別條件 ImageNet-256（JiT）：$R=130$ 時 B/16 的 FID 為 6.23，Feat Sim 為 15.99；$R=64$ 用 62% 的 token 計算量得 16.69，Token Skip 用 71% 得 19.11；L/16 在 $R=193$（88% 計算量）得 2.42，公開的 dense 為 2.36（App. B.2）。

    順序消融（App. B.4）：$R=256$ 時三種順序的差異在噪聲內；預算越小越依局部性排序。$R=64$ 時 raster 比 Hilbert 低 0.268 PickScore 與 0.154 ImageReward，Morton 介於其間（0.153、0.083）。GenEval 上 raster 在 $R=128$ 與 64 低 3.2 與 4.6（遠超 ±1.6 的波動），Morton 維持參考值；作者的解讀是行尾斷裂傷害構圖，對角跳躍只損失知覺品質。

    檢查理解

    B/16 在 R = 256、R = 512 的速度與 GenEval？同預算下三個基準的代價？

    $R=256$：2.15×、84.7（dense 87.2）；$R=512$：1.84×、87.8；刪除而非匯總 2.4（Token Skip 只有 1.19×，不是同預算比較，差距被低估）、打散分組 4.2、移除分組與位置 39.0（上界）GenEval（Tab. 1、Sec. 4.2–4.3）。

    延伸閱讀：RTI 的實驗結果、消融與限制、免訓練的擴散 token 合併、學得路由與動態 DiT

    14 · 實作

    實作設定與注意事項

    有實驗支持的常見錯誤

    1. 用 raster 順序切割：$R\le128$ 時行尾斷裂明顯降低 GenEval（3.2、4.6；App. B.4）；Morton 只損失知覺分數。
    2. 以平均與廣播取代 READ/WRITE：GenEval 下降 7.2（Fig. 8b）。
    3. 換成不帶位置的 latent array：同時移除分組與位置，品質掉到 Latent Array 的 45.7；位置單獨的貢獻論文未分離（Sec. 4.3）。
    4. 以 FLOPs 估計速度：Fig. 10 的實測時間低於 FLOP 曲線；B/16 約在 2.5× 飽和，$R\lt192$ 不再加速（L/16 仍會加速）。

    論文的做法（未做對照實驗的設計選擇）

    1. 只壓縮中段：依 Fig. 2c 兩端對每個 patch 敏感的推理，B/16 的核心為 17 塊中的 $[3,13]$；App. B.5 只比較了 $[1,15]$（同成本下無差異）。
    2. 每個去噪步都從當前狀態重建分割（App. A）。
    3. 每步從 {64, 128, 256, 512} 抽 $R$；未訓練的 96、192、384 落在同一曲線（Sec. 4.3）；只用單一預算訓練的效果未測試。
    4. READ/WRITE 初始化為恆等（Sec. 4.1）。論文未給出 $g$ 的層數與寬度，也未給出 $e_{\text{size}}$ 的維度。
